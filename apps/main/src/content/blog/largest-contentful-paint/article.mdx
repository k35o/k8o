# LargestContentfulPaintでLCPを測り要素を調べる

<BrowserSupportStatus featureId="largest-contentful-paint"></BrowserSupportStatus>

## はじめに

`LargestContentfulPaint`（Largest Contentful Paint API）は、ページを開いてから、画面に見えている中で一番大きな画像やテキストのブロックが描かれた時刻と、その要素を返すAPIです。Core Web VitalsのLCP（Largest Contentful Paint）は、この時刻を読み込みの速さの指標にしたものです。Safari 26.2が対応して、Baseline 2025に入りました。

手元で一度測るだけなら、Chrome DevToolsのPerformanceパネルやLighthouseで足ります。実際のユーザーの環境でLCPを集めたいときや、どの要素がLCPになったかをページのコードから調べたいときに、このAPIを使います。

## 基本的な使い方

`PerformanceObserver`でLCPのエントリを受け取ります。

```js
const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  // 最後のエントリが最終的なLCP
  const lastEntry = entries[entries.length - 1];

  console.log(`LCP: ${lastEntry.startTime}ms`);
  console.log(`要素: ${lastEntry.element?.tagName}`);
  console.log(`サイズ: ${lastEntry.size}px²`);

  if (lastEntry.url) {
    console.log(`リソースURL: ${lastEntry.url}`);
  }
});

observer.observe({ type: 'largest-contentful-paint', buffered: true });
```

開いているページのDevToolsのコンソールにこのコードを貼ると、そのページを読み込んだときのLCPの時刻と要素、面積が出ます。`buffered: true`を付けているので、読み込みが終わった後に貼っても、それまでに記録されたエントリが届きます。TypeScriptでは`getEntries()`が`PerformanceEntry`の配列を返すので、`list.getEntries() as LargestContentfulPaint[]`と型を絞ってから`element`や`size`を読みます。

### 複数のEntry

`PerformanceObserver`には複数の`entry`が届きます。ページの読み込みが進むにつれて、一番大きな要素が変わるからです。最初は小さなテキストが一番大きくても、後から大きな画像が読み込まれると、その画像の要素が新しい`entry`として届きます。

つまり、LCPは届いた`entry`の最後のものです。ただし、いつ最後になったかはページの側からは分かりません。

```js
let lcpValue = 0;

const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  lcpValue = lastEntry.startTime;
});

observer.observe({ type: 'largest-contentful-paint', buffered: true });

// ユーザーの最初の操作でLCPを確定
const controller = new AbortController();
for (const type of ['keydown', 'pointerdown']) {
  window.addEventListener(type, () => {
    console.log(`最終LCP: ${lcpValue}ms`);
    observer.disconnect();
    controller.abort();
  }, { signal: controller.signal });
}
```

ここでは、ユーザーの最初のクリックやキー入力でLCPを確定しています。ブラウザも、最初の操作の後は新しい`entry`を報告しません。どのブラウザでも、ボタンをクリックした後にもっと大きな要素を足しても、`entry`は届きません。

そのため、SPAでリンクをクリックし、文書を読み込まずにページを移ったときも、移った先のページのLCPは届きません。`buffered: true`でobserveし直すと、届くのは文書を読み込んだページの`entry`です。

## Largest Contentful Paint API

Largest Contentful Paint APIは、ビューポート内で一番大きなコンテンツ要素が描画されるまでの時間を、`LargestContentfulPaint`インターフェースで返します。

LCPの計測のためのAPIなので、`img`要素・`svg`内の`image`要素・`video`要素・`background-image`でスタイリングされた要素と、`p`要素などのテキスト要素が対象となります。

### PerformanceEntryから継承したプロパティ

`LargestContentfulPaint`は`PerformanceEntry`を継承しており、`startTime`、`entryType`などのプロパティを持ちます。

#### startTime

後に紹介する`LargestContentfulPaint`独自のプロパティである`renderTime`または`loadTime`のいずれかの時刻を返します。`renderTime`が0でなければ`renderTime`を、0なら`loadTime`を返します。

#### entryType

`LargestContentfulPaint`の場合は`"largest-contentful-paint"`を返します。

### LargestContentfulPaint独自のプロパティ

また、独自のプロパティとして`renderTime`・`loadTime`・`size`・`element`・`url`・`id`を持ちます。

#### renderTime

要素が実際にレンダリングされた時間です。

クロスオリジンの画像で`Timing-Allow-Origin`ヘッダーが無い場合、以前は`0`でしたが、今は少し粗くした時刻を返してよいことになっています。`Timing-Allow-Origin`を付けずに別のオリジンの画像を読むと、どのブラウザでも`0`ではなく描画の時刻が入ります。正確な時刻が要るときは、画像を返すサーバーで`Timing-Allow-Origin`を付けます。

#### loadTime

リソースの読み込みが完了した時間です。

テキスト要素の場合は0になります。

#### size

要素のサイズをピクセル単位の面積で返します。

この値は要素の可視領域のサイズであり、クリップされた部分やビューポート外の部分は含まれません。

#### element

LCPの候補になった要素を返します。

要素がDOMから削除された場合や、Shadow DOM内にある場合は`null`を返します。どのブラウザでも、`entry`を受け取った後にその要素をDOMから消すと、`element`は`null`になります。Shadow DOMの中の画像は、ChromeとFirefoxでは`element`が`null`の`entry`として届き、Safariでは`entry`になりません。

#### url

リソースを持つ場合、そのリソースのURLを返します。

#### id

要素のid属性の値を返します。id属性がない場合は空文字列を返します。

## おわりに

`LargestContentfulPaint`を使うと、ページを読み込んだときに一番大きな要素が描かれた時刻と、その要素をページのコードから受け取れます。候補が変わるたびに`entry`が届き、ユーザーの最初の操作で報告が止まるので、その時点で最後の`entry`をLCPとして扱います。
