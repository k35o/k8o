# LargestContentfulPaintでLCPを測り要素を調べる

<BrowserSupportStatus featureId="largest-contentful-paint"></BrowserSupportStatus>

## はじめに

`LargestContentfulPaint`（Largest Contentful Paint API）は、ページを開いてから、画面に見えている中で一番大きな画像やテキストのブロックが描かれた時刻と、その要素を返すAPIです。Core Web VitalsのLCP（Largest Contentful Paint）は、この時刻を読み込みの速さの指標にしたものです。Safari 26.2が対応して、Baseline 2025に入りました。

手元で一度測るときは、Chrome DevToolsのPerformanceパネルやLighthouseを使います。実際のユーザーの環境でLCPを集めたいときや、どの要素がLCPになったかをページのコードから調べたいときに、このAPIを使います。

## 基本的な使い方

`PerformanceObserver`でLCPのエントリを受け取ります。

```js
const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  // 最後のエントリが最終的なLCP
  const lastEntry = entries[entries.length - 1];

  console.log(`LCP: ${lastEntry.startTime}ms`);
  console.log(`要素: ${lastEntry.element?.tagName}`);
  console.log(`サイズ: ${lastEntry.size}px²`);

  if (lastEntry.url) {
    console.log(`リソースURL: ${lastEntry.url}`);
  }
});

observer.observe({ type: 'largest-contentful-paint', buffered: true });
```

開いているページのDevToolsのコンソールにこのコードを貼ると、そのページを読み込んだときのLCPの時刻と要素、面積が出ます。`buffered: true`を付けているので、読み込みが終わった後に貼っても、それまでに記録されたエントリが届きます。TypeScriptでは`getEntries()`が`PerformanceEntry`の配列を返すので、`list.getEntries() as LargestContentfulPaint[]`と型を絞ってから`element`や`size`を読みます。

下の例は、結果の欄の文書を読み込んだときのLCPの候補を、届いた順に表示します。最初のテキストが1つ目の候補になり、1秒後に描く大きなテキストが2つ目の候補として届きます。やり直すと、文書を読み込み直して測り直します。Safari 27.2は、結果の欄のようなiframeの中の文書にはエントリを届けないので、候補は出ません。

```html demo="candidates"
<p class="first">最初に描かれるテキスト</p>
<p>届いたLCPの候補</p>
<ol id="entries"></ol>
```

```js demo="candidates"
const entries = document.querySelector('#entries');

const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    const item = document.createElement('li');
    item.textContent = `${Math.round(entry.startTime)}ms ${entry.element?.tagName} ${entry.size}px²`;
    entries.append(item);
  }
});

if (PerformanceObserver.supportedEntryTypes.includes('largest-contentful-paint')) {
  observer.observe({ type: 'largest-contentful-paint', buffered: true });
} else {
  entries.textContent = 'このブラウザはLCPのエントリに対応していません';
}

// 1秒後に大きな要素を描くと、新しい候補が届く
setTimeout(() => {
  const later = document.createElement('p');
  later.className = 'later';
  later.textContent = '後から描かれる大きなテキスト';
  entries.before(later);
}, 1000);
```

```css demo="candidates"
.first {
  font-size: 1.25rem;
}

.later {
  font-size: 2rem;
  font-weight: bold;
}
```

### LCPが確定するとき

`PerformanceObserver`には複数の`entry`が届きます。ページの読み込みが進むにつれて、一番大きな要素が変わるからです。最初は小さなテキストが一番大きくても、後から大きな画像が読み込まれると、その画像の要素が新しい`entry`として届きます。

つまり、LCPは届いた`entry`の最後のものです。ただし、いつ最後になったかはページの側からは分かりません。

```js
let lcpValue = 0;

const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  lcpValue = lastEntry.startTime;
});

observer.observe({ type: 'largest-contentful-paint', buffered: true });

// ユーザーの最初の操作でLCPを確定
const controller = new AbortController();
for (const type of ['keydown', 'pointerdown']) {
  window.addEventListener(type, () => {
    console.log(`最終LCP: ${lcpValue}ms`);
    observer.disconnect();
    controller.abort();
  }, { signal: controller.signal });
}
```

ここでは、ユーザーの最初のクリックやキー入力でLCPを確定しています。ブラウザも、最初の操作の後は新しい`entry`を報告しません。どのブラウザでも、ボタンをクリックした後にもっと大きな要素を足しても、`entry`は届きません。

そのため、SPAでリンクをクリックし、文書を読み込まずにページを移ったときも、移った先のページのLCPは届きません。`buffered: true`でobserveし直すと、届くのは文書を読み込んだページの`entry`です。

## 対象の要素とプロパティ

LCPの候補になるのは、次の要素です。

- `img`要素
- `svg`の中の`image`要素
- `video`要素
- `background-image`で画像を付けた要素
- `p`要素などのテキストを含む要素

`entry`から読む値は、次のとおりです。

- `startTime`：LCPの時刻。`renderTime`が0でなければ`renderTime`、0なら`loadTime`
- `renderTime`：要素が描かれた時刻
- `loadTime`：リソースの読み込みが終わった時刻。テキストの要素では0
- `size`：要素の見えている部分の面積（平方ピクセル）
- `element`：LCPの候補になった要素
- `url`：画像などのリソースのURL
- `id`：要素の`id`属性の値。無ければ空文字列

`Timing-Allow-Origin`ヘッダーの無い別のオリジンの画像でも、`renderTime`には少し粗くした時刻が入ります。どのブラウザでも`0`にはなりません。正確な時刻が要るときは、画像を返すサーバーで`Timing-Allow-Origin`を付けます。

どのブラウザでも、`entry`を受け取った後にその要素をDOMから消すと、`element`は`null`になります。Shadow DOMの中の画像は、ChromeとFirefoxでは`element`が`null`の`entry`として届き、Safariでは`entry`になりません。

## おわりに

`LargestContentfulPaint`を使うと、一番大きな要素が描かれた時刻とその要素を、ページのコードから受け取れます。候補が変わるたびに`entry`が届き、最初の操作で報告が止まるので、その時点で最後の`entry`をLCPとして扱います。
