# rcap・rch・rex・ric単位でremのように文字数で幅を決める

## はじめに

`rcap`・`rch`・`rex`・`ric`は、ルート要素（`<html>`）のフォントを基準にしたCSSの長さの単位です。`rem`が`em`のルート版であるように、それぞれ`cap`・`ch`・`ex`・`ic`のルート版で、どの要素の中で使っても同じ長さになります。

要素自身の文字に合わせたいなら、`ch`や`ic`で足ります。入力欄の幅を中の数字10桁に合わせるなら`10ch`です。一方で、見出しや入力欄のように文字サイズの違う要素でも、本文の数字や全角文字を基準にした同じ長さにそろえたい場面では、`ch`や`ic`は要素ごとに値が変わってしまいます。そこで使うのが`r`の付いた単位です。

```html
<p style="font-size: 32px">
  <span style="display: inline-block; width: 10ch; background: gold">10ch</span>
</p>
<p style="font-size: 32px">
  <span style="display: inline-block; width: 10rch; background: skyblue">10rch</span>
</p>
```

開くと、文字サイズが32pxの段落の中で`10ch`の帯は32pxの数字10桁分に伸びます。`10rch`の帯はルートの文字サイズ（ブラウザの既定なら16px）の数字10桁分のままで、`10ch`の半分の長さです。

4つの単位は、Firefox 147のリリースでBaseline 2026に追加されました。

## cap, ch, ex, ic単位の復習

まず、Baseline 2026に追加された単位から`r`を取り除いたものを確認しましょう。

- `cap`: 現在のフォントの大文字の高さ
- `ch`: 現在のフォントの`0`の幅
- `ex`: 現在のフォントの小文字xの高さ
- `ic`: 現在のフォントの`水`の幅

これらはその要素に付与されたフォントサイズか、親要素から継承されたフォントサイズに基づいて計算されます。
そのため、ネストした要素では値が変わる可能性があります。

## rcap, rch, rex, ric単位の紹介

`rem`が`em`のルート要素を元としたものであるように、`rcap`・`rch`・`rex`・`ric`はそれぞれ`cap`・`ch`・`ex`・`ic`の基準をルート要素にした単位です。

これらの単位は、常にルート要素のフォント設定に基づいて計算されます。どこで使用しても同じ値になるため、ページ全体で一貫したサイズ指定が可能です。

<PlaygroundEmbed demo="通常版とルート版の違い" headingLevel="h4" sectionId="root-font-units" />

font-sizeの値を変えると、`ch`のバーは文字サイズに合わせて伸び縮みし、`rch`のバーは長さが変わりません。

ルートに`font: 16px sans-serif`を指定したページで、`font-size: 32px`の要素の中の値を測りました。Chrome 156、Safari 27.2、Firefox 159のいずれでも、`ch`・`ic`・`cap`・`ex`はルートで測った値の倍になり、`rch`・`ric`・`rcap`・`rex`はルートの値のままでした。Chrome 156なら、`1ch`は21.02px、`1rch`は10.51pxです。

基準になるのは、ルート要素に当たっているフォントです。`font-family`を`body`にだけ指定していると、本文の文字ではなく、`<html>`に当たるブラウザ既定のフォントで測られます。`lang="en"`のページの`body`に`sans-serif`を指定すると、3つのブラウザとも`body`の中の`1ch`は8.9px、`1rch`は既定のTimesの`0`の幅の8pxでした。本文の文字を基準にするなら、`font-family`は`html`に指定します。

### rcap

<BrowserSupportStatus featureId="rcap" />

ルート要素のキャップハイトに基づく単位です。

```css
.heading {
  /* 大文字の高さを基準にしたマージン */
  margin-bottom: 1rcap;
}
```

### rch

<BrowserSupportStatus featureId="rch" />

ルート要素の`0`の幅に基づく単位です。

```css
/* [!og] */
.input-number {
  /* 入力欄の文字サイズに関係なく、ルートの文字で数字10桁分の幅にそろえる */
  width: 10rch;
}
```

`10rch`は、入力欄の中の数字10桁が収まる幅ではありません。入力欄は既定で親のフォントを継承せず、Chrome 156では13.33pxのArialで描かれます。`font-size: 24px`の入力欄に`width: 10rch`を指定すると、Chrome 156、Safari 27.2、Firefox 159のいずれでも10桁の数字が収まりませんでした（Chrome 156では幅109pxに対して中身が137px）。中の数字に合わせるなら`10ch`を使います。

### rex

<BrowserSupportStatus featureId="rex" />

ルート要素の小文字`x`の高さに基づく単位です。

```css
.inline-icon {
  /* どの文字サイズの中でも、ルートのxの高さにそろえる */
  height: 1rex;
  width: 1rex;
}
```

### ric

<BrowserSupportStatus featureId="ric" />

ルート要素の`水`の幅に基づく単位です。CJKのテキストで特に有用です。

```css
.japanese-text {
  /* 全角文字20文字分の幅 */
  max-width: 20ric;
}
```

## おわりに

`rcap`、`rch`、`rex`、`ric`の4つの単位を紹介しました。

これらは`rem`と同様にルート要素を基準とするため、コンポーネントがどこに配置されても一貫したサイズを維持できます。
特定の文字サイズに基づいた精密で相対的なサイズの指定が可能になり、デザインの一貫性を保ちやすくなります。

なお、行の高さに基づく`lh`単位のルート版である`rlh`はBaseline 2023から利用可能です。これで、フォント関連の相対単位のルート版が全て揃いました。
