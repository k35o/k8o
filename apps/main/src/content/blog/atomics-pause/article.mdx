# AtomicsでWorker間の共有メモリを安全に読み書きする

## Atomics

<BrowserSupportStatus featureId="shared-memory"></BrowserSupportStatus>

`Atomics`は、Workerなどの複数のスレッドが`SharedArrayBuffer`で同じメモリを共有するときに、値を割り込まれずに読み書きしたり、スレッド間で待ち合わせたりするための静的メソッドを集めたオブジェクトです。

Workerとのやり取りが、`postMessage`で値をコピーして送り合うだけなら`Atomics`は要りません。複数のスレッドが同じ`SharedArrayBuffer`を書き換えるときは、`int32[0]++`のような普通の書き換えでは更新が失われるので、`Atomics`を使います。2つのWorkerが100万回ずつ足すと、次のようになります。

```js title="race.mjs"
import { Worker, isMainThread, workerData } from 'node:worker_threads';

if (isMainThread) {
  const int32 = new Int32Array(new SharedArrayBuffer(8));
  const workers = [0, 1].map(() => new Worker(new URL(import.meta.url), { workerData: int32 }));
  await Promise.all(workers.map((worker) => new Promise((resolve) => worker.on('exit', resolve))));
  console.log(int32[0], int32[1]);
} else {
  for (let i = 0; i < 1_000_000; i++) {
    workerData[0]++; // 読んでから書くまでに、ほかのスレッドが割り込める
    Atomics.add(workerData, 1, 1);
  }
}
```

Node.js 26.13.0で動かすと、`Atomics.add`で足した`int32[1]`は必ず2000000になり、`++`で足した`int32[0]`は1544495や1816934のように毎回足りなくなりました。同じことをブラウザのWorkerで試しても、Chrome 156、Safari 27.2、Firefox 159のどれでも`++`の方はどの回も2000000に届きませんでした。

ブラウザで`SharedArrayBuffer`を使うには、ページを`Cross-Origin-Opener-Policy: same-origin`と`Cross-Origin-Embedder-Policy: require-corp`のヘッダーで返し、`crossOriginIsolated`を`true`にします。ヘッダーの無いページでは、3つのブラウザのどれでも`SharedArrayBuffer`自体が定義されていませんでした。

```js
// 4バイトのSharedArrayBufferを作成
// SharedArrayBufferはcrossOriginIsolatedで安全なコンテキストでのみ実行可能
const sab = new SharedArrayBuffer(4);
// 4バイトのInt32Arrayを作成
const int32 = new Int32Array(sab);
```

`Atomics`は静的なメソッドのみを持つオブジェクトで、共有メモリ上のデータを他の処理に割り込まれずに一度に完了する操作（不可分操作、Atomics操作）を行う関数や複数の実行単位でイベントを待機したり通知したりするための関数を提供します。

### 不可分操作、Atomics操作

`Atomics`が提供する基本的な不可分操作は以下の通りです。一連の処理で`int32`は共通した変数です。

`Atomics.load`は指定したインデックスの値を読み込みます。

```js
// 0番目の値を読み込む
const value = Atomics.load(int32, 0);
console.log(value); // 0
```

`Atomics.store`は指定したインデックスに値を書き込みます。

```js
// 0番目の値に1を書き込む
Atomics.store(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.add`は指定したインデックスの値に指定した値を加算します。

```js
// 0番目の値に1を加算する
Atomics.add(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 2
```

`Atomics.sub`は指定したインデックスの値から指定した値を減算します。

```js
// 0番目の値から1を減算する
Atomics.sub(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.and`は指定したインデックスの値と指定した値の論理積を計算します。

```js
// 0番目の値と1の論理積を計算する
Atomics.and(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.or`は指定したインデックスの値と指定した値の論理和を計算します。

```js
// 0番目の値と1の論理和を計算する
Atomics.or(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.xor`は指定したインデックスの値と指定した値の排他的論理和を計算します。

```js
// 0番目の値と1の排他的論理和を計算する
Atomics.xor(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 0
```

`Atomics.exchange`は指定したインデックスの値を指定した値で置き換えます。返り値は置き換え前の値です。

```js
// 0番目の値を1で置き換える
const oldValue = Atomics.exchange(int32, 0, 1);
console.log(oldValue); // 0
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.compareExchange`は指定したインデックスの値が指定した値と等しい場合にのみ、指定した値で置き換えます。返り値は置き換え前の値です。

```js
// 0番目の値が1の場合に2で置き換える
const previous = Atomics.compareExchange(int32, 0, 1, 2);
console.log(previous); // 1
console.log(Atomics.load(int32, 0)); // 2
```

### イベントの待機と通知

`Atomics`は`wait`と`notify`によってスレッド間でイベントを待機したり通知したりします。
`wait`は`SharedArrayBuffer`を元にした`Int32Array`または`BigInt64Array`でのみ利用でき、共有していない配列を渡すと`TypeError`になります。`notify`は共有していない配列にも呼べますが、待機しているスレッドが無いので常に0を返します。

`wait`は指定したインデックスの値が指定した値と一致する場合`notify`からの通知があるまで待機します。
待機中、スレッドはブロックされます。そのため、メインスレッドから呼び出すことは許可されていません。ブラウザのメインスレッドで呼ぶと、Chrome 156、Safari 27.2、Firefox 159のどれでも`TypeError`になりました。Node.jsのメインスレッドでは呼べます（Node.js 26.13.0で確認）。

```js
// notifyから通知が来るまで待機する
// 第4引数はタイムアウト時間(ミリ秒)で、デフォルトはInfinityで無限
// 返り値は"ok"、"not-equal"、"timed-out"のいずれか
// "ok": notifyから通知が来て待機が解除された場合
// "not-equal": 指定したインデックスの値が指定した値と異なっていた場合
// "timed-out": タイムアウト時間が経過した場合
Atomics.wait(int32, 0, 0);
// 待機完了後に呼ばれる
console.log('waited');
// 下の例と合わせて実行されたとき
console.log(Atomics.load(int32, 0)); // 1
```

タイムアウトを渡さなければ、`wait`で待機したスレッドは`notify`で通知されるまで再開しません。
`notify`は指定したインデックスの値で待機しているスレッドに対して通知を送信します。

```js
// [!og]
// 0番目の値を1にする
Atomics.store(int32, 0, 1);
// 0番目の値で待機中のwaitに通知する
// 第3引数には通知する対象の個数、デフォルトはInfinity
const agent = Atomics.notify(int32, 0);
// 通知されたAgentの数を返す
console.log(agent); // 1
```

上記の2つの例では、待機中のスレッドは、`int32`の0番目の値に対して通知が送られるのを待っています。
値を`1`に更新したあと`notify`によって通知が行われ、スレッドは待機状態を抜けます。

## Atomics.pause

<BrowserSupportStatus featureId="atomics-pause"></BrowserSupportStatus>

`Atomics.pause`はBaseline 2025で追加された、マイクロウェイト（非常に短い待機）を実現するための新しい静的メソッドです。
このメソッドはスピンロックやビジーウェイトのループ内で使用され、CPUに対してスピン中であるというヒントを与えて、リソースの消費を最適化します。

ロックが空くまでループを回して待つのがスピンロックです。次の`lock`は、`compareExchange`で0を1に替えられたらロックを取れたことにし、取れなかった回は`Atomics.pause`を呼んでから試し直します。

```js
// int32[0] が 0 なら空き、1 ならロック中
function lock(int32) {
  for (let i = 0; Atomics.compareExchange(int32, 0, 0, 1) !== 0; i++) {
    Atomics.pause(i);
  }
}

function unlock(int32) {
  Atomics.store(int32, 0, 0);
}
```

`Atomics.pause`を呼ばずにループを回し続けると、ロックが解放されるまでCPUをフル稼働させるので、他のプロセスやスレッドに悪影響を及ぼす可能性があります。`Atomics.pause`は、CPUに対して今スピン中であるというヒントを与え、ループの1回ごとに短く待ちます。

4つのWorkerがこのロックを100万回ずつ取り合い、ロックの中で`int32[1]++`をすると、どのブラウザでも結果は4000000になりました。Chrome 156では`Atomics.pause`を入れると約160ms、外すと約200msで終わり、Node.js 26.13.0でも約120〜150msと約180〜220msでした（Apple M4のMac）。Safari 27.2とFirefox 159は回ごとのばらつきが大きく、どちらが速いとは言えませんでした。

`Atomics.pause`には任意引数があり、待機時間についてのヒントを整数で渡します（ヒントが利用されることは保証されていません）。利用された場合は、与えられた値より小さい値を渡された時の待機時間以上は待つように働きます。
[Intelの最適化マニュアル](https://www.intel.com/content/www/us/en/content-details/671488/intel-64-and-ia-32-architectures-optimization-reference-manual-volume-1.html)ではループにおいてこれを使ったBackoff戦略を利用することが推奨されています。

上の`lock`では、試した回数を渡しています。手元で100万回呼んだ時間は引数が0でも1000でも変わらず、Chrome 156で約17ms、Safari 27.2で約10ms、Firefox 159で約11msでした。3つのブラウザとも、引数による違いは見えませんでした。`1.5`や文字列の`'1'`を渡すと、どれも`TypeError`になります。

## おわりに

共有メモリの安全な操作方法として、`Atomics`の静的メソッドの基本的な使い方から、Baseline 2025で使えるようになった`Atomics.pause`の活用までを解説しました。

`Atomics`を適切に利用することで、マルチスレッド環境におけるデータの整合性を保ちつつ、効率的な同期処理が可能になります。`Atomics.pause`は、スピンロックのループで呼ぶだけでCPUにスピン中であることを伝えられ、手元のChrome 156ではロックの取り合いが速く終わりました。
