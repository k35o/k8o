# AtomicsでWorker間の共有メモリを安全に読み書きする

## Atomics

<BrowserSupportStatus featureId="shared-memory"></BrowserSupportStatus>

`Atomics`は、Workerなどの複数のスレッドが`SharedArrayBuffer`で同じメモリを共有するときに、値を割り込まれずに読み書きしたり、スレッド間で待ち合わせたりするための静的メソッドを集めたオブジェクトです。

Workerとのやり取りが、`postMessage`で値をコピーして送り合うだけなら`Atomics`は要りません。複数のスレッドが同じ`SharedArrayBuffer`を書き換えるときは、`int32[0]++`のような普通の書き換えでは更新が失われるので、`Atomics`を使います。2つのWorkerが100万回ずつ足すと、次のようになります。

```js title="race.mjs"
import { Worker, isMainThread, workerData } from 'node:worker_threads';

if (isMainThread) {
  const int32 = new Int32Array(new SharedArrayBuffer(8));
  const workers = [0, 1].map(() => new Worker(new URL(import.meta.url), { workerData: int32 }));
  await Promise.all(workers.map((worker) => new Promise((resolve) => worker.on('exit', resolve))));
  console.log(int32[0], int32[1]);
} else {
  for (let i = 0; i < 1_000_000; i++) {
    workerData[0]++; // 読んでから書くまでに、ほかのスレッドが割り込める
    Atomics.add(workerData, 1, 1);
  }
}
```

Node.jsで動かすと、`Atomics.add`で足した`int32[1]`は必ず2000000になり、`++`で足した`int32[0]`は1544495や1816934のように毎回足りなくなりました。同じことをブラウザのWorkerで試しても、どのブラウザでも`++`の方は2000000に届きません。

ブラウザで`SharedArrayBuffer`を使うには、ページを`Cross-Origin-Opener-Policy: same-origin`と`Cross-Origin-Embedder-Policy: require-corp`のヘッダーで返し、`crossOriginIsolated`を`true`にします。ヘッダーの無いページでは、どのブラウザでも`SharedArrayBuffer`自体が定義されていません。

```js
// 4バイトのSharedArrayBufferを作成
// SharedArrayBufferはcrossOriginIsolatedで安全なコンテキストでのみ実行可能
const sab = new SharedArrayBuffer(4);
// 4バイトのInt32Arrayを作成
const int32 = new Int32Array(sab);
```

`Atomics`のメソッドは、割り込まれずに一度で終わる読み書き（不可分操作）と、スレッド間の待ち合わせの2つに分かれます。

### 不可分操作

基本的な不可分操作は次のとおりです。どの例も、上の`int32`を続けて使います。

`Atomics.load`は指定したインデックスの値を読み込みます。

```js
// 0番目の値を読み込む
const value = Atomics.load(int32, 0);
console.log(value); // 0
```

`Atomics.store`は指定したインデックスに値を書き込みます。

```js
// 0番目の値に1を書き込む
Atomics.store(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.add`は指定したインデックスの値に指定した値を加算します。

```js
// 0番目の値に1を加算する
Atomics.add(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 2
```

`Atomics.sub`は指定したインデックスの値から指定した値を減算します。

```js
// 0番目の値から1を減算する
Atomics.sub(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.and`は指定したインデックスの値と指定した値の論理積を計算します。

```js
// 0番目の値と1の論理積を計算する
Atomics.and(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.or`は指定したインデックスの値と指定した値の論理和を計算します。

```js
// 0番目の値と1の論理和を計算する
Atomics.or(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.xor`は指定したインデックスの値と指定した値の排他的論理和を計算します。

```js
// 0番目の値と1の排他的論理和を計算する
Atomics.xor(int32, 0, 1);
console.log(Atomics.load(int32, 0)); // 0
```

`Atomics.exchange`は指定したインデックスの値を指定した値で置き換えます。返り値は置き換え前の値です。

```js
// 0番目の値を1で置き換える
const oldValue = Atomics.exchange(int32, 0, 1);
console.log(oldValue); // 0
console.log(Atomics.load(int32, 0)); // 1
```

`Atomics.compareExchange`は指定したインデックスの値が指定した値と等しい場合にのみ、指定した値で置き換えます。返り値は置き換え前の値です。

```js
// 0番目の値が1の場合に2で置き換える
const previous = Atomics.compareExchange(int32, 0, 1, 2);
console.log(previous); // 1
console.log(Atomics.load(int32, 0)); // 2
```

### イベントの待機と通知

`Atomics`の`wait`と`notify`で、スレッド間で待ち合わせます。`wait`は`SharedArrayBuffer`を元にした`Int32Array`または`BigInt64Array`でのみ利用でき、共有していない配列を渡すと`TypeError`になります。`notify`は共有していない配列にも呼べますが、待機しているスレッドが無いので常に0を返します。

`wait`は、指定したインデックスの値が指定した値と同じなら、`notify`で通知されるまで待ちます。待っているあいだはスレッドが止まるので、ブラウザのメインスレッドでは呼べず、どのブラウザでも`TypeError`になります。Node.jsのメインスレッドでは呼べます。

```js
// notifyから通知が来るまで待機する
// 第4引数はタイムアウト時間(ミリ秒)で、デフォルトはInfinityで無限
// 返り値は"ok"、"not-equal"、"timed-out"のいずれか
// "ok": notifyから通知が来て待機が解除された場合
// "not-equal": 指定したインデックスの値が指定した値と異なっていた場合
// "timed-out": タイムアウト時間が経過した場合
Atomics.wait(int32, 0, 0);
// 待機完了後に呼ばれる
console.log('waited');
// 下の例と合わせて実行されたとき
console.log(Atomics.load(int32, 0)); // 1
```

タイムアウトを渡さなければ、`wait`で待機したスレッドは`notify`で通知されるまで再開しません。`notify`は、指定したインデックスで待っているスレッドに通知を送ります。

```js
// [!og]
// 0番目の値を1にする
Atomics.store(int32, 0, 1);
// 0番目の値で待機中のwaitに通知する
// 第3引数には通知する対象の個数、デフォルトはInfinity
const agent = Atomics.notify(int32, 0);
// 通知されたAgentの数を返す
console.log(agent); // 1
```

上の2つの例では、待っているスレッドは`int32`の0番目への通知を待っています。値を`1`にしてから`notify`で通知すると、スレッドは待機を抜けます。

## Atomics.pause

<BrowserSupportStatus featureId="atomics-pause"></BrowserSupportStatus>

`Atomics.pause`は、ごく短い時間だけ待つ静的メソッドです。Firefox 137が対応して、Baseline 2025に入りました。スピンロックのようにループで待つ処理の中で呼び、今スピン中であることをCPUに伝えます。

ロックが空くまでループを回して待つのがスピンロックです。次の`lock`は、`compareExchange`で0を1に替えられたらロックを取れたことにし、取れなかった回は`Atomics.pause`を呼んでから試し直します。

```js
// int32[0] が 0 なら空き、1 ならロック中
function lock(int32) {
  for (let i = 0; Atomics.compareExchange(int32, 0, 0, 1) !== 0; i++) {
    Atomics.pause(i);
  }
}

function unlock(int32) {
  Atomics.store(int32, 0, 0);
}
```

`Atomics.pause`を呼ばずにループを回すと、ロックが空くまでCPUを使い続けるので、ほかのスレッドの邪魔になることがあります。`Atomics.pause`を呼ぶと、ループの1回ごとに短く待ちます。

4つのWorkerがこのロックを100万回ずつ取り合い、ロックの中で`int32[1]++`をすると、どのブラウザでも結果は4000000になりました。Chromeでは`Atomics.pause`を入れると約160ms、外すと約200msで終わり、Node.jsでも約120〜150msと約180〜220msでした（Apple M4のMac）。SafariとFirefoxは回ごとのばらつきが大きく、どちらが速いとは言えませんでした。

`Atomics.pause`には、待つ時間のヒントを整数で渡せます。ヒントが使われるとは限りませんが、使われる場合は、大きい値では小さい値のとき以上に待ちます。[Intelの最適化マニュアル](https://www.intel.com/content/www/us/en/content-details/671488/intel-64-and-ia-32-architectures-optimization-reference-manual-volume-1.html)では、ループで待つ時間を少しずつ延ばすバックオフが勧められています。

上の`lock`では、試した回数を渡しています。手元で100万回呼んだ時間は引数が0でも1000でも変わらず、Chromeで約17ms、Safariで約10ms、Firefoxで約11msでした。どのブラウザでも、引数による違いは見えませんでした。`1.5`や文字列の`'1'`を渡すと、どれも`TypeError`になります。

## おわりに

`Atomics`のメソッドを使うと、Worker間で共有したメモリを割り込まれずに読み書きし、`wait`と`notify`で待ち合わせられます。スピンロックでは、ループの中で`Atomics.pause`を呼んで、CPUにスピン中であることを伝えます。
