# コントラスト比の計算式と相対輝度の求め方

## はじめに

背景色とテキスト色のコントラスト比はWCAG 2.1において[AA基準](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)と[AAA基準](https://www.w3.org/WAI/WCAG21/Understanding/contrast-enhanced)の2つの達成基準によって定められています。
AA基準では、通常のテキストに4.5:1以上、大きなテキストに3:1以上のコントラスト比を求めます。AAA基準では、通常のテキストに7:1以上、大きなテキストに4.5:1以上を求めます。
大きなテキストは、18pt（24px）以上か、太字なら14pt（約18.66px）以上の文字を指します。それより小さい文字は通常のテキストとして扱います。
これらの基準はコントラストに対する支援技術を用いない中程度の弱視の人がテキストを読めることを目的として設けられています。

この基準は[WebAIMのチェッカー](https://webaim.org/resources/contrastchecker/)や、[Storybookのa11yアドオン](https://storybook.js.org/addons/@storybook/addon-a11y)のようなツールで確認できます。
ツールを使えば簡単に求められるので、計算方法を知らなくても確認はできます。それでも、計算方法を知っておくと、色を選ぶときの判断に役立ちます。私も以前はツールに頼りきりでしたが、計算方法を知ってその重要性を理解しました。この記事では、色のコントラスト比の計算方法を紹介します。

## 計算式

コントラスト比は、2つの色の相対輝度から求めます。輝度は、広がりを持つ光源からある方向へ出る光の、面積あたりの明るさを表す物理量です[^1]。相対輝度を$L$で表すと、コントラスト比$C$は次の式で計算します。

```math
C = \frac{(L_1 + 0.05)}{(L_2 + 0.05)}
```

$L_1$は$L_2$よりも相対的に明るい色となるようにします。輝度の定義より明るい色は暗い色よりも輝度が大きいので、与式は$1$以上になります。
さらに、分母と分子には周囲光の影響として$0.05$を加えています。これで、分子と分母が$0$になることを防いでいます。
これから計算方法を紹介しますが、相対輝度$L$は$0 \sim 1$の値をとります。さらに、計算結果は1以上の値になることを踏まえるとコントラスト比は$1\sim 21$の値をとります。

相対輝度は色空間内の任意の点の相対的な明るさです。最小値が`#000000`で$0$、最大値が`#ffffff`で$1$となるように正規化されます。
色の表現法は様々ありますが、計算では$(R,G,B)$で赤・緑・青のそれぞれ$0\sim1$の数値で表したものを使います。`#4080c0`であれば、各成分の16進数を10進数に直すと$(64,128,192)$で、これを$255$で割った$(0.251,0.502,0.753)$を使います。
そしてそれぞれの成分を以下のルールに基づいて変形します。

```math
    F(x) =
        \begin{cases}
            \frac{x}{12.92} \quad x \leqq 0.04045 \\
            (\frac{x + 0.055}{1.055})^{2.4} \quad x > 0.04045 \\
        \end{cases}
```

`F(x)`は単調増加関数で、$x$の最小値は0、最大値は1です。そのため、$F(x)$の最小値は$F(0) = 0$、最大値は$F(1) = 1$となり、$0\sim1$の値を取ります。

この変形は、sRGBの値を光の量に比例する値に戻すためのものです。sRGBの値は、人間の視覚が明るさを非線形に捉える特性に合わせて割り振られていて、光の量には比例しません。

暗い色は、明るい色と同じだけ輝度が変わっても、その変化を大きく感じることが見て取れます。sRGBの値はこの感じ方に合わせて割り振られているので、値から輝度に戻す式は$2.4$乗になります(下図は$y = x^{2.4}$をプロットしたものです。上の図とは軸が逆なことに注意してください)。

また、$0.04045$以下の暗い色では、べき乗の曲線がほぼ平らになり、値の違いが輝度にほとんど表れなくなります。そのため、この範囲は$12.92$で割るだけの直線の式になっています。

計算した結果を赤・緑・青それぞれの見え方に合わせて重みをつけて足し合わせると相対輝度が求められます。

```math
 L = 0.2126 \times R + 0.7152 \times G + 0.0722 \times B
```

重みの合計は1です。$L$も同じく$0\sim1$の値を取るようになっています。
重みの付け方も人間の視覚で捉えやすい色を基準に設けています。人間は緑色に対する感受性が最も高く、次に赤色、最後に青色の順で感じるので緑が最も相対輝度に寄与して、青が最も寄与しないような重みづけになっています。

## コード

計算式が分かったので、コードに落とし込んでいきましょう。
まずは補正を行う関数を作っていきます。

```ts
const applyCorrection = (color: number): number => {
  if (color <= 0.04045) {
    return color / 12.92;
  }

  return Math.pow((color + 0.055) / 1.055, 2.4);
};
```

`color`には$0\sim1$の範囲外の数値を渡せますが、この記事ではそのような数値を考えないものとして記述します。

次に相対輝度を求める関数です。

```ts
type RGB = [number, number, number];

const computeRelativeLuminance = (rgb: RGB): number => {
  const [r, g, b] = rgb;
  return (
    0.2126 * applyCorrection(r) +
    0.7152 * applyCorrection(g) +
    0.0722 * applyCorrection(b)
  );
};
```

`number`型の3つの要素を持つタプル型を`RGB`という名前で作りました。

最後にコントラスト比を求める関数です。

```ts
const computeContrastRatio = (rgb1: RGB, rgb2: RGB): number => {
  const l1 = computeRelativeLuminance(rgb1);
  const l2 = computeRelativeLuminance(rgb2);
  return (Math.max(l1, l2) + 0.05) / (Math.min(l1, l2) + 0.05);
};
```

相対輝度の計算が終わるまでどちらが明るいか分からないので、計算後に大きい方が分子に、小さい方が分母になるように調整しています。

## さいごに

コントラスト比の計算方法を紹介しました。計算式からは、人間の視覚が感じやすい色や、緑の成分を強めると青の成分を強めるより約10倍も相対輝度が上がることなど、ツールで調整するだけでは分からなかったことが読み取れます。
今後もツールを使って結果を鵜呑みにするだけではなく、結果がどのように導かれるかを理解していきたいです。
