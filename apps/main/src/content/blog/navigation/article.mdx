# Navigation APIでSPAのルーティングを実装する

<BrowserSupportStatus featureId="navigation" />

## はじめに

Navigation APIは、リンクのクリックやフォーム送信、ブラウザの戻るボタンと進むボタンといったページの遷移を、`navigation`オブジェクトの`navigate`イベント1つで受け取れるAPIです。イベントの`intercept()`を呼ぶと、ページを読み込み直す代わりに、JavaScriptで画面を書き換えるSPAの遷移になります。Firefox 147が対応して、Baseline 2026に入りました。

遷移のたびにページを読み込み直すサイトなら、History APIもNavigation APIも要りません。SPAでも、ルーターのライブラリが用意する`<Link>`のような部品でリンクを書くなら、ライブラリの内側のHistory APIで足ります。素の`<a>`やフォーム、戻るボタンと進むボタンまでを1か所で受け取り、遷移の途中でデータを取りに行く処理を挟めるのは、Navigation APIだけです。

```html
<a href="/about">About</a>
<p id="view"></p>
<script>
  navigation.addEventListener('navigate', (event) => {
    if (!event.canIntercept) return;
    event.intercept({
      handler() {
        document.getElementById('view').textContent = location.pathname;
      },
    });
  });
</script>
```

リンクを押すと、ページを読み込み直さずにURLが`/about`に変わり、段落に`/about`と出ます。ブラウザの戻るボタンを押すと、URLと段落が`/`に戻ります。

## History APIでのルーティングの課題

これまでSPAのルーティングには、History API（`pushState()`と`popstate`）を使ってきました。しかしHistory APIはSPAが広まる前に設計されたもので、ルーティングのライブラリは多くの課題を避けながら作られてきました。簡略化すると、次のようなコードになります。

```js
// リンクのクリックは個別にハンドリング
document.querySelectorAll('a').forEach((link) => {
  link.addEventListener('click', (e) => {
    e.preventDefault();
    history.pushState(null, '', link.href);
    renderPage(link.href);
  });
});

// ブラウザの戻る/進むは別のイベントで検知
window.addEventListener('popstate', () => {
  renderPage(location.href);
});
```

リンクのクリックは`click`イベント、戻るボタンと進むボタンは`popstate`イベントと、遷移の種類ごとに別のリスナーが要ります。`pushState()`を呼んでも`popstate`は発火しないので、JavaScriptからの遷移を知るには、さらに別の仕組みが要ります。フォーム送信まで含めると、遷移の処理はアプリケーションのあちこちに散らばります。

また、`popstate`は遷移が終わってから発火するので、遷移を途中で止めたり、遷移の前にデータを取りに行ったりする処理を挟むのが難しくなります。

ルーティングのライブラリは、`<a>`の代わりに`<Link>`コンポーネントを用意して、この複雑さを隠しています。たとえばTanStack Routerでは、[`<Link>`コンポーネントのクリックハンドラ](https://github.com/TanStack/router/blob/1acc8eaf3a07cbe1c19ffcf2d4dcecdef34ffc1f/packages/react-router/src/link.tsx#L605-L642)で修飾キーやボタンの種類を見て`preventDefault()`を呼び、[Historyモジュール](https://github.com/TanStack/router/blob/1acc8eaf3a07cbe1c19ffcf2d4dcecdef34ffc1f/packages/history/src/index.ts)では`popstate`のリスナーを登録したうえで、`pushState`と`replaceState`をネイティブの関数ごと上書きして呼び出しを検知しています。

## Navigation APIの基本

Navigation APIは`window.navigation`オブジェクトから使います。History APIの`pushState()`や`history.back()`に代わるメソッドとして、次のものがあります。

- `navigation.navigate(url)`：指定したURLへ遷移する（`history.pushState()`と違い、`intercept()`を呼ばなければページを読み込む）
- `navigation.back()`、`navigation.forward()`：履歴を戻る、進む（`history.back()`、`history.forward()`に当たる）
- `navigation.traverseTo(key)`：特定の履歴エントリへ移る（`history.go()`に当たるが、相対の位置ではなくキーで指定する）
- `navigation.reload()`：現在のページを読み込み直す
- `navigation.updateCurrentEntry({ state })`：遷移せずに、現在のエントリの状態だけを書き換える

`updateCurrentEntry()`を除くこれらのメソッドは、`committed`と`finished`の2つのPromiseを持つオブジェクトを返します。

```js
const { committed, finished } = navigation.navigate('/next');

await committed; // URLが変更された
await finished;  // ナビゲーションに伴う非同期処理が完了した
```

- `committed`：遷移がコミットされた（URLバーが書き換わった）ときに解決する
- `finished`：遷移に伴う非同期の処理がすべて終わったときに解決する

## navigateイベント

`navigate`イベントは、リンクのクリックやフォーム送信、`navigation.navigate()`の呼び出しや戻るボタンと進むボタンのどれでも発火するので、すべての種類の遷移を1か所で受け取れます。

```js
navigation.addEventListener('navigate', (event) => {
  console.log(event.navigationType); // "push", "replace", "reload", "traverse"
  console.log(event.destination.url);
});
```

History APIの`history.pushState()`を呼んだときも、`navigationType`が`"push"`の`navigate`イベントが発火します。History APIで遷移するライブラリと同じページにあっても、`pushState()`を上書きせずに遷移を知れます。

`NavigateEvent`は、遷移を見分けるための次のプロパティを持ちます。

- `navigationType`：遷移の種類（`"push"`、`"replace"`、`"reload"`、`"traverse"`）
- `destination`：遷移先の情報を持つオブジェクト。`destination.url`で遷移先のURLを取れる
- `canIntercept`：インターセプトできるか（クロスオリジンでは`false`）
- `hashChange`：フラグメントだけの変更か
- `downloadRequest`：`download`属性の付いたリンクなら、その属性の値（値の無い`download`属性では空文字、ダウンロードでなければ`null`）
- `formData`：POSTのフォーム送信なら`FormData`（それ以外では`null`）
- `signal`：別の遷移が始まったときや、ユーザーが停止ボタンを押したときに中断される`AbortSignal`
- `info`：`navigate()`を呼んだときに渡した一時的なデータ
- `userInitiated`：ユーザーの操作による遷移か（`navigation.navigate()`や`navigation.back()`などJavaScriptからの遷移では`false`）
- `sourceElement`：遷移を起こした要素（クリックされた`<a>`や送信された`<form>`など。`navigation.navigate()`や`history.pushState()`による遷移では`null`）
- `hasUAVisualTransition`：ブラウザがこのイベントの前に、スワイプで戻るときのような遷移のアニメーションを見せたか

これらのプロパティで、SPAとしてインターセプトする遷移を見分けます。

```js
// [!og]
navigation.addEventListener('navigate', (event) => {
  // インターセプト不要なナビゲーションをスキップ
  if (!event.canIntercept) return;
  if (event.hashChange) return;
  if (event.downloadRequest !== null) return;

  // URLに対してルート定義をマッチング
  const url = new URL(event.destination.url);
  const matched = matchRoutes(routes, url.pathname);
  if (matched === null) return;

  // マッチしたルートのハンドラを実行
  event.intercept({
    async handler() {
      await loadRouteData(matched, event.signal);
    },
  });
});
```

`download`属性の付いたリンクでも`canIntercept`は`true`になるので、`downloadRequest`で除きます。値の無い`download`属性では`downloadRequest`が空文字になるため、真偽ではなく`null`と比べます。

### intercept()

`NavigateEvent`の`intercept()`メソッドは、ブラウザの通常の遷移（ページの読み込み直し）を止め、代わりにSPAの遷移にします。

```js
event.intercept({
  async handler() {
    // URLは既に更新済み（コミット後に実行される）
    const data = await fetch(event.destination.url, {
      signal: event.signal,
    });
    renderPage(await data.json());
  },
});
```

`handler`は、遷移がコミットされて（URLバーが書き換わって）から呼ばれるので、`handler`の中で読む`location.pathname`はすでに遷移先のパスです。`handler`のPromiseが解決するまで、ブラウザはタブに読み込み中の表示を出し、ユーザーが停止ボタンを押すと`event.signal`が中断されます。

`intercept()`は、フォーカスのリセットとスクロールの復元も自動で行います。次のオプションを`"manual"`にすると、自分で行えます。

- `focusReset`：`"after-transition"`（既定。自動でフォーカスをリセットする）か`"manual"`
- `scroll`：`"after-transition"`（既定。自動でスクロールを復元する）か`"manual"`

遷移が終わったか失敗したかは、`navigatesuccess`と`navigateerror`のイベントで知れます。

```js
navigation.addEventListener('navigatesuccess', () => {
  loadingIndicator.hidden = true;
});

navigation.addEventListener('navigateerror', (event) => {
  showErrorMessage(event.error.message);
});
```

`handler`が投げたエラーは`event.error`に入るので、エラーの内容はそこから読みます。`event.message`はブラウザで形が違い、`TypeError('boom')`を投げると、ChromeとSafariでは`Uncaught TypeError: boom`、Firefoxでは`TypeError: boom`になります。

### \<Link\>コンポーネントが必須ではなくなる

`navigate`イベントは通常の`<a>`のクリックでも発火するので、`<a>`に`click`のハンドラーを付けなくても、`<a>`を書くだけでSPAの遷移になります。

```tsx
// History APIのルーターでは、<Link>がクリックを受け取る
import { Link } from 'react-router';
<Link to="/about">About</Link>

// Navigation APIのルーターでは、<a>のままでよい
<a href="/about">About</a>
```

## 履歴エントリの管理

History APIでは`history.length`で履歴の長さは取れましたが、個々のエントリのURLや状態を読む手段はありませんでした。Navigation APIでは、`navigation.currentEntry`で現在のエントリを、`navigation.entries()`で同じオリジンの履歴エントリを`NavigationHistoryEntry`の配列として取れます。

```js
const entries = navigation.entries();
for (const entry of entries) {
  console.log(entry.url, entry.key, entry.id, entry.index);
}
```

`entries()`に入るのは、現在のエントリから別のオリジンをはさまずに続くエントリだけです。たとえば同じオリジンのページを3つ進んでから、別のオリジンのページを経て`/c`へ進むと、`entries()`は`/c`の1件だけを返し、`navigation.canGoBack`も`false`になります。`history.length`には、はさんだページより前のエントリも数えられます。

各`NavigationHistoryEntry`には`id`と`key`の2つの識別子があります。

- `id`：エントリそのものを見分ける。`history: "replace"`で置き換えると新しい`id`になる
- `key`：履歴の中の位置を見分ける。`history: "replace"`で置き換えても同じ`key`のまま

`key`は、上で触れた`navigation.traverseTo()`に渡します。

```js
// アプリのトップページのkeyを記録しておく
const homeKey = navigation.currentEntry.key;

// どこからでもトップページに戻れる
backToHomeButton.onclick = () => {
  navigation.traverseTo(homeKey);
};
```

### 状態の管理

`navigate()`には`state`と`info`の2種類のデータを渡せます。

```js
navigation.navigate('/product', {
  state: { scrollPosition: 100 }, // 履歴に永続化される
  info: { animation: 'slide' },  // 今回のナビゲーションでのみ利用可能
});
```

`state`は履歴エントリごとに保存され、`navigation.entries()`のどのエントリからも`entry.getState()`で取り出せます。History APIの`history.state`とは別に保存されるので、`navigate()`に`state`を渡しても`history.state`は`null`のままです。

`info`は今回の遷移でだけ使える一時的なデータで、`navigate`イベントの`event.info`で受け取れます。`back()`、`forward()`、`traverseTo()`には、`info`だけを渡せます。

`updateCurrentEntry()`は、遷移せずに現在のエントリの状態だけを書き換えるので、アコーディオンの開閉やタブの切り替えのような画面の状態を履歴に残せます。`navigate`イベントは発火せず、代わりに`currententrychange`イベントが発火します。

```js
navigation.updateCurrentEntry({
  state: {
    ...navigation.currentEntry.getState(),
    detailsOpen: true,
  },
});
```

## おわりに

Navigation APIでは、素の`<a>`やフォーム、戻るボタンと進むボタンまでの遷移を`navigate`イベント1つで受け取り、`intercept()`でSPAの遷移にできます。`entries()`で履歴を読み、`state`と`info`で状態を渡せるので、SPAのルーティングに要るものがブラウザの機能でそろいます。

Navigation APIを使ったルーターの実装を読むなら、React向けに作られた[FunStack Router](https://github.com/uhyo/funstack-router)のコードがおすすめです。今はルーティングに要る最小限の機能に絞って作られているので、Navigation APIの各機能がルーターとしてどう組み立てられているかを読み取りやすいです。
