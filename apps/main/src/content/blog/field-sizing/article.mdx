# field-sizingでtextareaの高さを内容に合わせる

<BrowserSupportStatus featureId="field-sizing" />

## はじめに

`field-sizing`は、`input`や`textarea`、`select`の大きさを、入力された内容に合わせて伸び縮みさせるかを決めるCSSプロパティです。`field-sizing: content`を指定すると、改行するたびに`textarea`の高さが伸び、文字を打つたびに`input`の幅が広がります。Firefox 152が対応して、Baseline 2026に入りました。

大きさが決まっていてよい入力欄なら、今までどおり`width`や`rows`で決めれば足ります。入力に合わせて伸ばしたいときは、これまで`input`イベントで`scrollHeight`を読んで`height`を書き換えるJavaScriptが要りました。`field-sizing: content`なら、その処理をCSSだけで書けます。

## デモ

<PlaygroundEmbed demo="field-sizing: contentの挙動" headingLevel="h4" sectionId="field-sizing" />

`content`のまま、テキストエリアで改行すると高さが伸び、セレクトボックスで選択肢を選ぶと幅がその選択肢に合います。`fixed`に切り替えると、どのコントロールも入力に関わらず大きさが変わらなくなります。

## field-sizingの値

`field-sizing`が取る値は`fixed`と`content`の2つです。

```css
input {
  /* [!callout: 既定値。最初に決まったサイズで固定される] */
  field-sizing: fixed;
}

input {
  /* [!callout: 入力内容に合わせてサイズが変わる] */
  field-sizing: content;
}
```

`fixed`が既定値で、これは従来どおりの挙動です。`content`を指定すると、コントロールが内容を包み込むように縮み、テキストが増えると広がります。

## 対象となる要素

`field-sizing`が効くのは、内容に関わらず既定の推奨サイズを持つ要素です。HTMLでは次のフォームコントロールが対象です。

- `text`・`email`・`search`・`tel`・`url`・`password`・`number`といった、テキストを直接入力する`input`
- `file`の`input`
- `textarea`
- `select`

`textarea`は単一行のテキスト入力に近い挙動になり、幅の制約に達すると今度は高さ方向に行が増え、高さの制約にも達するとスクロールバーが出ます。`select`はドロップダウンなら選択中の選択肢の幅にフィットし、`multiple`属性付きのリストボックスならスクロールせずに全選択肢が見える高さになります。選択肢が7つの`multiple`の`select`を比べると、`fixed`では4つ分ほどの高さで、`content`では7つすべてが見える高さになります。

`file`の`input`は、ブラウザによって結果が分かれます。Chromeでは`content`にすると選んだファイル名に合わせて幅が変わり、Safariでは`content`にしても幅が変わりません。Firefoxでは`fixed`のままでもファイル名に合わせて幅が変わります。今のところ、`file`の`input`の幅は`field-sizing`ではブラウザ間で揃いません。

## min/maxと組み合わせる

`field-sizing: content`だけを指定すると、`input`は最小でテキストカーソルの幅まで縮みます。実用上は`min-width`や`max-width`を添えて、伸び縮みの範囲を決めておくのが扱いやすいです。

```css
/* [!og] */
input {
  field-sizing: content;
  min-width: 8rem;
  max-width: 20rem;
}
```

`placeholder`を指定した`input`は、値が空のあいだはプレースホルダー全体が見える幅で描画されます。フォーカスしても幅は変わらず、1文字入れた時点で内容の幅まで縮みます。上の例なら`min-width`の8remが下限になるので、短い値で細くなりすぎることはありません。

`width`や`height`を固定値で指定すると、その軸は内容に追従しなくなります。止まるのは固定した軸だけで、幅を固定した`textarea`では高さが内容に追従します。

固定値の`width`のほかに、レイアウト側でコントロールが幅いっぱいに引き伸ばされる場合も、内容に合わせて縮みません。たとえば`flex-direction: column`のFlexアイテムやGridアイテムは、既定でコンテナの幅まで広がります。引き伸ばしを止めれば`field-sizing: content`が効きます。コントロール側で指定するなら、`align-self`（Flex）や`justify-self`（Grid）を`start`にするといった方法があります。

### textareaの高さを内容に合わせる

`textarea`の高さを入力に合わせたいときは、幅を決めて、高さだけを内容に追従させます。高さの範囲は`min-height`と`max-height`で決めます。`lh`単位を使うと、行数で書けます。

```css
textarea {
  field-sizing: content;
  width: 100%;
  min-height: 3lh;
  max-height: 10lh;
}
```

空のときは3行分の高さで表示され、改行するたびに1行ずつ伸び、10行分に達するとそれ以上は伸びずにスクロールバーが出ます。`content`では`rows`属性が効かないので、初期の高さは`min-height`で決めます。

幅を決めていない`textarea`は、改行するまで横に伸び続けます。幅を指定せず`height`だけを固定した`textarea`に文字サイズ16pxで全角25文字を入れると、折り返さずに幅が約400pxまで広がります。高さを内容に合わせる用途では、幅を先に決めておきます。

## 属性との関係

`field-sizing: content`を指定すると、サイズに関わる一部の属性は意味を持たなくなります。`input`の`size`、`textarea`の`rows`・`cols`はいずれも既定の推奨サイズを決める属性なので、サイズが内容に追従する`content`では効きません。`rows="8"`の`textarea`は空のとき1行分の高さになり、`size="40"`の`input`も空のときは数pxの幅まで縮みます。

伸びる上限を内容側から決めたいときは`maxlength`が使えます。文字数の上限に達するとコントロールはそれ以上大きくなりません。

```html
<input type="tel" maxlength="15" />
```

## おわりに

`field-sizing: content`は、フォームコントロールのサイズを入力内容に追従させるためのCSSプロパティです。Baseline 2026で主要ブラウザに揃いました。テキストエリアの高さをJavaScriptで調整していた処理は、幅を決め、`field-sizing: content`と`min-height`・`max-height`を組み合わせれば、CSSだけに置き換えられます。`input`の幅を内容に合わせるときは、`min-width`・`max-width`で伸び縮みの範囲を決めます。
