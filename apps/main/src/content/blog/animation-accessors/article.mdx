# event.animationでCSSアニメーションを止める・速める

<BrowserSupportStatus featureId="animations-css-animation-accessors" />

## はじめに

`event.animation`は、`animationstart`や`transitionend`などのイベントを発火させた、CSSアニメーションやトランジションの`Animation`を指すプロパティです。イベントで受け取ったアニメーションを、そのまま止めたり速めたりできます。Safari 27が対応して、Baseline 2026に入りました。

どのアニメーションの節目かを知るだけなら、`animationName`や`propertyName`と`elapsedTime`で足ります。途中で止めたり速度を変えたりするには`Animation`オブジェクトが要り、これまでは`getAnimations()`で要素のアニメーションを一覧にして、名前の一致するものを探していました。

```js
element.addEventListener('animationstart', (event) => {
  const animation = element
    .getAnimations()
    .find((a) => a.animationName === event.animationName);
});
```

`AnimationEvent`と`TransitionEvent`に`animation`プロパティが加わり、この探し方をしなくても済むようになりました。この2つのプロパティは、BaselineではAnimation accessorsとまとめて呼ばれています。

## 書き方

使い方は`event.animation`を読むだけです。`animationstart`などで受け取る[`AnimationEvent`の`animation`](https://drafts.csswg.org/css-animations-2/#dom-animationevent-animation)には`CSSAnimation`が、`transitionrun`などで受け取る[`TransitionEvent`の`animation`](https://drafts.csswg.org/css-transitions-2/#Events-TransitionEvent-animation)には`CSSTransition`が入っています。どちらも`Animation`のサブクラスなので、`playbackRate`や`pause()`、`finished`をそのまま使えます。

```js
// [!og]
panel.addEventListener('transitionrun', (event) => {
  const transition = event.animation;
  if (transition.transitionProperty !== 'opacity') return;
  // 閉じるときのフェードだけ3倍速で終わらせる
  if (panel.classList.contains('is-closing')) {
    transition.playbackRate = 3;
  }
});
```

`transitionrun`で受け取った`CSSTransition`は、同じトランジションの`transitionstart`や`transitionend`で受け取るものと同じオブジェクトです。1本のアニメーションの`animationstart`と`animationiteration`、`animationend`でも同様です。どのブラウザでも、トランジションの3つのイベントの`event.animation`を`===`で比べると、どれも同じです。`animationiteration`で周回を数え、決めた回数で`pause()`を呼ぶといった使い方ができます。`event.animation.finished`を`await`すれば、終わるまで待つこともできます。

```css demo="blink"
#badge {
  animation: blink 0.5s infinite;
}
@keyframes blink {
  50% {
    opacity: 0;
  }
}
```

```html demo="blink"
<div id="badge">●</div>
```

```js demo="blink"
const badge = document.querySelector('#badge');
let iterations = 0;
badge.addEventListener('animationiteration', (event) => {
  iterations += 1;
  // 2周したところで止める
  if (iterations === 2) event.animation.pause();
});
```

結果の欄では、●が2回点滅したあと、表示されたまま止まります。

## getAnimations()で探す方法との違い

`getAnimations()`から名前で探す方法には、うまくいかない場面が2つありました。

1つ目は、同じ名前のアニメーションを2本指定したときです。`animation: fade 0.1s, fade 0.2s`のように書くと`animationstart`は2回発火しますが、`event.animationName`は2回とも`fade`なので、どちらのアニメーションのイベントかを名前では区別できません。この問題は、[CSSWGでこのプロパティを決めたときの動機](https://github.com/w3c/csswg-drafts/issues/9010)の1つでもあります。`event.animation`には別々の`CSSAnimation`が入り、`event.animation.effect.getTiming().duration`を読むと100と200が返ります。どのブラウザでも、はじめにのコードのように名前で探した`find()`は、2回ともdurationが100の1本目を返します。

2つ目は、`animationend`で受け取るときです。`animation-fill-mode`が`none`だと、`animationend`の中で`getAnimations()`を呼んでも、いま終わったアニメーションは見つかりません。`getAnimations()`が返すのは仕様で[relevant](https://drafts.csswg.org/web-animations-1/#relevant-animations-section)と定義されたアニメーション、つまり効果がこれから始まるか進行中か、まだ残っているものだけです。`none`の場合、終わった時点でこの条件から外れます。`event.animation`なら、終わった後でも`playState`が`finished`の`CSSAnimation`として読めます。どのブラウザでも、`animation-fill-mode`を`forwards`にすると、`animationend`の中の`getAnimations()`にも終わったアニメーションが残ります。

```css demo="beat"
@keyframes beat {
  50% {
    opacity: 0.2;
  }
}

#box {
  width: 2rem;
  height: 2rem;
  background-color: steelblue;
  animation:
    beat 0.5s,
    beat 0.8s;
}
```

```html demo="beat"
<div id="box"></div>
<ol id="log"></ol>
```

```js demo="beat"
const box = document.querySelector('#box');
const log = document.querySelector('#log');

const record = (event) => {
  const { animation } = event;
  const duration = animation.effect.getTiming().duration;
  const item = document.createElement('li');
  item.textContent = `${event.type} ${event.animationName} ${duration}ms`;
  if (event.type === 'animationend') {
    item.textContent += ` 一覧に残る: ${box.getAnimations().includes(animation)}`;
  }
  log.append(item);
};

box.addEventListener('animationstart', record);
box.addEventListener('animationend', record);
```

結果の欄のログでは`animationName`はすべて`beat`ですが、`event.animation`から読んだdurationで2本を区別できます。`animationend`の行では、`getAnimations()`に残っているかが`false`になり、終わったアニメーションが一覧から外れたと分かります。

## 疑似要素のアニメーション

`::before`などの疑似要素に指定したアニメーションのイベントは、元の要素で発火します。`event.target`は元の要素を指し、`event.pseudoElement`が`::before`になります。

`element.getAnimations()`で疑似要素のアニメーションまで探すには、[`getAnimations({ subtree: true })`](https://drafts.csswg.org/web-animations-1/#dom-getanimationsoptions-subtree)のようにオプションが要ります。既定では要素自身のアニメーションしか返さないためです。`event.animation`なら探す必要はなく、`event.animation.effect`の[`pseudoElement`](https://drafts.csswg.org/web-animations-1/#dom-keyframeeffect-pseudoelement)が`::before`、`target`が元の要素になっています。どのブラウザでも、`animationstart`の中では`getAnimations()`は空の配列を返し、`getAnimations({ subtree: true })`には`event.animation`と同じものが入っています。

## 使うときの注意

使うときに気をつけたい点が3つあります。

1つ目は、`event.animation`が`null`のことがある点です。`new AnimationEvent('animationend')`のように自前で作ったイベントは、初期化辞書で`animation`を渡さない限り`null`です。どのブラウザでも、渡さずに作った`AnimationEvent`と`TransitionEvent`の`animation`は`null`です。`dispatchEvent()`で流したイベントも同じリスナーで受けるなら、`null`の場合に備えておきます。

```js
// 初期化辞書で渡さなければ event.animation は null
const event = new AnimationEvent('animationend', { animationName: 'fade' });
```

2つ目は、`event.animation`からアニメーションを操作すると、CSS側の指定が効かなくなる点です。たとえば`animation-play-state`は、CSSアニメーションを`running`で再生し、`paused`で止めるプロパティです。`:hover`のときだけ`paused`にして、ホバー中は止めるといった使い方をします。ところが`event.animation`で`pause()`や`play()`を一度呼ぶと、そのアニメーションは以後`animation-play-state`の変更に従わなくなります。[CSS Animations Level 2](https://drafts.csswg.org/css-animations-2/#animations)が、APIでの操作をCSSより優先すると定めているためです。`effect.updateTiming()`で指定した項目も同じで、対応する`animation-*`プロパティの変更は反映されません。どのブラウザでも、`pause()`と`play()`を続けて呼んだあとに`animation-play-state`を`paused`にしても、`playState`は`running`のままです。`updateTiming()`で`duration`を2000にしたあとに`animation-duration`を0.5sにしても、2000のままです。CSS側で制御し続けたいアニメーションでは、`event.animation`は読むだけにとどめます。

3つ目は、TypeScriptの型です。TypeScriptのDOMの型には、`AnimationEvent`と`TransitionEvent`の`animation`がまだありません。`event.animation`と書くとTS2339のエラーになるので、TypeScriptでは`'animation' in event`で確かめてから、`instanceof CSSAnimation`で絞り込みます。

## おわりに

`event.animation`を使うと、アニメーションのイベントから発火元の`Animation`をそのまま受け取れます。`getAnimations()`から名前で探す必要も、同じ名前の2本を区別する工夫も要りません。
