# event.animationでCSSアニメーションを止める・速める

<BrowserSupportStatus featureId="animations-css-animation-accessors" />

## はじめに

`event.animation`は、`animationstart`や`transitionend`などのイベントを発火させた、CSSアニメーションやトランジションの`Animation`を指すプロパティです。イベントで受け取ったアニメーションを、そのまま止めたり速めたりできます。Safari 27が対応して、Baseline 2026に入りました。

どのアニメーションの節目かは、`animationName`や`propertyName`と`elapsedTime`で分かります。途中で止めたり速度を変えたりするには`Animation`オブジェクトが要り、これまでは`getAnimations()`で要素のアニメーションを一覧にして、名前の一致するものを探していました。

```js
element.addEventListener('animationstart', (event) => {
  const animation = element
    .getAnimations()
    .find((a) => a.animationName === event.animationName);
});
```

`AnimationEvent`と`TransitionEvent`に加わった`animation`プロパティは、イベントを発火させた`Animation`を直接指します。この2つのプロパティは、BaselineではAnimation accessorsとまとめて呼ばれています。

## 書き方

`animationstart`などの`AnimationEvent`には`CSSAnimation`が、`transitionrun`などの`TransitionEvent`には`CSSTransition`が入ります。どちらも`Animation`のサブクラスなので、`playbackRate`や`pause()`、`finished`をそのまま使えます。

```js
// [!og]
panel.addEventListener('transitionrun', (event) => {
  const transition = event.animation;
  if (transition.transitionProperty !== 'opacity') return;
  // 閉じるときのフェードだけ3倍速で終わらせる
  if (panel.classList.contains('is-closing')) {
    transition.playbackRate = 3;
  }
});
```

1本のトランジションやアニメーションのイベントには、どのブラウザでも同じオブジェクトが入ります。そのため、`animationiteration`で周回を数え、決めた回数で`pause()`を呼べます。

```css demo="blink"
#badge {
  animation: blink 0.5s infinite;
}
@keyframes blink {
  50% {
    opacity: 0;
  }
}
```

```html demo="blink"
<div id="badge">●</div>
```

```js demo="blink"
const badge = document.querySelector('#badge');
let iterations = 0;
badge.addEventListener('animationiteration', (event) => {
  iterations += 1;
  // 2周したところで止める
  if (iterations === 2) event.animation.pause();
});
```

結果の欄では、●が2回点滅したあと、表示されたまま止まります。

## getAnimations()で探す方法との違い

`getAnimations()`から探す方法には、うまくいかない場面が3つあります。

1つ目は、同じ名前のアニメーションを2本指定したときです。`animation: fade 0.1s, fade 0.2s`では`event.animationName`が2回とも`fade`なので、はじめにのコードのように名前で探すと、どのブラウザでも2回とも1本目が返ります。`event.animation`なら、2本を別々の`CSSAnimation`として受け取れます。

2つ目は、`animationend`で受け取るときです。`animation-fill-mode`が`none`だと、終わったアニメーションは`getAnimations()`から外れるので、`animationend`の中では見つかりません。`event.animation`なら、終わったあとでも読めます。

```css demo="beat"
@keyframes beat {
  50% {
    opacity: 0.2;
  }
}

#box {
  width: 2rem;
  height: 2rem;
  background-color: steelblue;
  animation:
    beat 0.5s,
    beat 0.8s;
}
```

```html demo="beat"
<div id="box"></div>
<ol id="log"></ol>
```

```js demo="beat"
const box = document.querySelector('#box');
const log = document.querySelector('#log');

const record = (event) => {
  const { animation } = event;
  const duration = animation.effect.getTiming().duration;
  const item = document.createElement('li');
  item.textContent = `${event.type} ${event.animationName} ${duration}ms`;
  if (event.type === 'animationend') {
    item.textContent += ` 一覧に残る: ${box.getAnimations().includes(animation)}`;
  }
  log.append(item);
};

box.addEventListener('animationstart', record);
box.addEventListener('animationend', record);
```

結果の欄のログでは`animationName`はすべて`beat`ですが、`event.animation`から読んだdurationで2本を区別できます。`animationend`の行では、`getAnimations()`に残っているかが`false`になり、終わったアニメーションが一覧から外れたと分かります。

3つ目は、`::before`などの疑似要素のアニメーションです。イベントは元の要素で発火しますが、`getAnimations()`は既定で要素自身のアニメーションしか返さないので、`{ subtree: true }`を渡さないと見つかりません。`event.animation`なら、そのまま受け取れます。

## 使うときの注意

`new AnimationEvent('animationend')`のように自前で作ったイベントは、初期化辞書で`animation`を渡さない限り`event.animation`が`null`です。`dispatchEvent()`で流したイベントも同じリスナーで受けるなら、`null`に備えておきます。

`event.animation`で`pause()`や`play()`、`effect.updateTiming()`を呼ぶと、そのアニメーションは以後、`animation-play-state`などのCSSの変更に従わなくなります。CSS側で制御し続けたいアニメーションでは、`event.animation`は読むだけにとどめます。

TypeScriptのDOMの型には、`AnimationEvent`と`TransitionEvent`の`animation`がまだありません。`'animation' in event`で確かめてから、`instanceof CSSAnimation`で絞り込みます。

## おわりに

`event.animation`を使うと、アニメーションのイベントから発火元の`Animation`をそのまま受け取れます。`getAnimations()`から名前で探す必要も、同じ名前の2本を区別する工夫も要りません。
