# CSP違反をReport-Onlyとreport-toで検知する

<BrowserSupportStatus featureId="reporting-csp-violations" />

## はじめに

CSP violation reportsは、Content Security Policy（CSP）に違反したリソースの読み込みやスクリプトの実行を、ブラウザがレポートとして知らせる仕組みです。`report-to`ディレクティブでサーバーに送らせるか、`securitypolicyviolation`イベントでページ内から受け取ります。Firefox 149が対応して、Baseline 2026に入りました。

自分のブラウザで違反を確かめるだけなら、DevToolsのコンソールに出るエラーで足ります。しかし、ユーザーのブラウザで起きた違反を集めるには、この仕組みが要ります。いきなり厳しいポリシーを本番に入れると、サードパーティのスクリプトや古いコードが思わぬ場所で止まることがあります。違反を集めれば、ポリシーの過不足を本番の違反から確かめながら締めていけます。

Reporting API全体については[Reporting APIでCSP違反などのレポートをサーバーに集める](/blog/reporting)を参照してください。

## report-toディレクティブによるサーバー送信

CSP違反をサーバーに送信するには、`Content-Security-Policy`ヘッダーに`report-to`ディレクティブを追加し、対応する`Reporting-Endpoints`ヘッダーで送信先を定義します。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy: default-src 'self'; report-to csp-endpoint
```

`Reporting-Endpoints`ヘッダーで定義したエンドポイント名を`report-to`の引数として渡すことで、CSP違反のレポートがそのエンドポイントに送信されます。エンドポイントのURLはHTTPSにします。手元で試すときは、`http://localhost`のURLにも届きます。

次のコードのページは、別のオリジンの画像を読もうとし、`img-src 'self'`に違反します。

```js title="server.mjs"
import { createServer } from 'node:http';

createServer((req, res) => {
  if (req.method === 'POST') {
    let body = '';
    req.on('data', (chunk) => (body += chunk));
    req.on('end', () => {
      console.log(req.headers['content-type'], body);
      res.writeHead(204).end();
    });
    return;
  }
  res.writeHead(200, {
    'Content-Type': 'text/html; charset=utf-8',
    'Reporting-Endpoints': 'csp-endpoint="http://localhost:3000/csp-reports"',
    'Content-Security-Policy': "img-src 'self'; report-to csp-endpoint",
  });
  res.end('<img src="https://example.com/a.png">');
}).listen(3000);
```

`http://localhost:3000`を開くと画像は表示されず、ターミナルに`effectiveDirective`が`img-src`のレポートが出ます。FirefoxとSafariでは、届くものの形が違います。

- Firefox：`Content-Type`は`application/reports+json`で、レポートの配列が届く。レポートは`age`と`type`、`url`、`user_agent`、`body`を持つ
- Safari：`Content-Type`は`application/csp-report`で、レポートが1件ずつ届く。レポートは`type`と`url`、`body`だけを持ち、`blockedURL`は`https://example.com:443/a.png`のようにポート番号が付く

どちらも`type`は`csp-violation`で、`body`には違反したリソースのURLやディレクティブ、ポリシー文字列などが入ります。受け取るサーバーは、配列と1件のオブジェクトの両方を扱えるようにしておきます。

いつ送るかはブラウザに委ねられていて、届くことも保証されません。Firefoxは数秒のうちに複数のレポートを1つの配列にまとめて送り、Safariは違反のたびに1件ずつすぐ送ります。

## securitypolicyviolationイベント

JavaScriptからCSP違反を検知するには、`securitypolicyviolation`イベントを使います。サーバーにエンドポイントを持たないときや、違反が起きたその場でページの中で何かしたいときに使います。

```js
document.addEventListener('securitypolicyviolation', (event) => {
  console.log(event.effectiveDirective); // "script-src-elem"
  console.log(event.blockedURI); // "https://evil.com/script.js"
  console.log(event.originalPolicy); // "default-src 'self'; ..."
});
```

イベントは`Document`と`Element`、`WorkerGlobalScope`で発火するので、Web Workerの中でも受け取れます。

### イベントオブジェクトのプロパティ

`SecurityPolicyViolationEvent`は、HTTPのレポートの`body`とほぼ同じ情報をプロパティに持ちます。

- `blockedURI`：ブロックされたリソースのURI（レポートでは`blockedURL`）
- `violatedDirective`：違反したディレクティブ（`effectiveDirective`の古い別名）
- `effectiveDirective`：違反を検出したディレクティブ
- `originalPolicy`：違反したCSPのポリシーの文字列
- `documentURI`：違反が起きたドキュメントのURI（レポートでは`documentURL`）
- `sourceFile`と`lineNumber`、`columnNumber`：違反を起こしたスクリプトの位置
- `sample`：違反した内容の先頭40文字。インラインのスクリプトや`eval()`の違反では`'report-sample'`を指定したときだけ入り、Trusted Typesの違反では指定しなくても入る
- `disposition`：`"enforce"`か`"report"`
- `statusCode`：ドキュメントのHTTPステータスコード
- `referrer`：違反が起きたドキュメントのリファラー

HTTPのレポートとは、`blockedURI`と`blockedURL`、`documentURI`と`documentURL`のように、名前が少し違うプロパティがあります。

## Report-Onlyモードによる段階的な導入

`Content-Security-Policy-Report-Only`ヘッダーを使うと、ポリシーを強制せずに、違反のレポートだけを集められます。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy-Report-Only: default-src 'self'; report-to csp-endpoint
```

Report-Onlyで違反した`eval()`はそのまま実行され、レポートと`securitypolicyviolation`イベントの`disposition`は`"report"`になります。`disposition`を見れば、強制しているポリシーの違反と、試しているポリシーの違反を分けられます。

本番では、次の流れでポリシーを締めていきます。

1. Report-Onlyで違反を集め、ポリシーの許可する範囲を調整する
2. 違反がほとんど無くなったら、`Content-Security-Policy`で強制する
3. 強制した後も`report-to`は残し、新しく起きる違反を見続ける

## おわりに

CSP violation reportsを使うと、ポリシーを書いただけでは見えない、ユーザーのブラウザで起きた違反を集められます。`report-to`でサーバーに集め、`securitypolicyviolation`でページの中で受け取りながら、Report-Onlyで強制せずにポリシーを締めていけます。
