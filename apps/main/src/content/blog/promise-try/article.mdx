# Promise.tryで同期関数の例外もcatchで受け取る

<BrowserSupportStatus featureId="promise-try"></BrowserSupportStatus>

## はじめに

`Promise.try`は、渡した関数をその場で呼び、結果を`Promise`に包んで返すメソッドです。関数が同期的に例外を投げても、返した`Promise`が拒否されても、`catch`で受け取れます。Firefox 134が対応して、Baseline 2025に入りました。

`async`関数の中なら、`await fn()`を`try...catch`で囲めば、同期の例外も拒否も受け取れます。`Promise.try`が要るのは、`then`と`catch`をつなぐ書き方で、同期的に例外を投げるかもしれない関数を扱うときです。`Promise.resolve(fn())`では同期の例外が`catch`に届かず、`Promise.resolve().then(fn)`では`fn`の呼び出しが後回しになります。

```js
const parse = (text) => JSON.parse(text);

Promise.try(parse, '{').catch((error) => console.log('catchで受け取った', error.name));
Promise.resolve(parse('{')).catch((error) => console.log('catchで受け取った', error.name));
```

`Promise.try`の行は`catchで受け取った SyntaxError`を出し、`Promise.resolve`の行は`catch`に届かずに`Uncaught SyntaxError`になります。

## Promise.tryとは

`Promise.try`は`Promise`を返すので、`then`や`catch`、`finally`をつなげて使います。

```js
Promise.try(callback)
  .then(() => console.log('fulfilled'))
  .catch(() => console.log('rejected'))
  .finally(() => console.log('settled'));
```

同期の`syncFn`の結果も、非同期の`asyncFn`と同じように`then`で取り出せます。

```js
const syncFn = () => {
  return 'sync';
};

const asyncFn = async () => {
  return 'async';
};

console.log(Promise.try(syncFn)); // Promise {<fulfilled>: 'sync'}
console.log(Promise.try(asyncFn)); // Promise {<pending>}

Promise.try(syncFn).then(console.log); // sync
Promise.try(asyncFn).then(console.log); // async
```

例外も、`try...catch`ではなく`catch`で受け取ります。

```js
const syncFn = () => {
  throw 'sync';
};

const asyncFn = async () => {
  throw 'async';
};

console.log(Promise.try(syncFn)); // Promise {<rejected>: 'sync'}
console.log(Promise.try(asyncFn)); // Promise {<pending>}

Promise.try(syncFn).catch(console.log); // sync
Promise.try(asyncFn).catch(console.log); // async
```

### Promise.tryで引数付きの関数を呼び出す

関数に引数を渡すには、`Promise.try`の第2引数以降に渡すか、引数を渡して呼ぶ関数で包みます。

```js
// [!og]
const fn = (arg1, arg2) => {
  return arg1 + arg2;
};

Promise.try(fn, 1, 2).then(console.log); // 3
Promise.try(() => fn(1, 2)).then(console.log); // 3
```

TypeScriptでは`Promise.try`の型が次のように定義されていて、どちらの書き方でも引数の型が確かめられます。

```ts
try<T, U extends unknown[]>(callbackFn: (...args: U) => T | PromiseLike<T>, ...args: U): Promise<Awaited<T>>;
```

この型は、`lib`に`es2025`か`esnext`を指定すると使えます。`es2024`のままでは、`Property 'try' does not exist on type 'PromiseConstructor'`のエラーになります。

## Promise.tryが使えない場合

`Promise.try`が無かったころは、`new Promise`で同じことを書いていました。

```js
const promiseTry = (callback, ...args) => {
  return new Promise((resolve) => resolve(callback(...args)));
};
```

関数名を`promiseTry`にしたのは、`try`が予約語で使えないためです。`new Promise`に渡した関数の中で投げられた例外は拒否として扱われるので、`callback`が同期的に投げても`catch`で受け取れます。`callback`が`Promise`を返したときは、`resolve`がその結果を引き継ぎます。

この書き方は、知らない人には何をしているかが読み取りにくく、`Promise.try`ならこの実装が要りません。

## Promise.tryが有効な場面

`Promise.try`は、同期で値を返すときと非同期で返すときがある関数を扱うときに役立ちます。

```js
import { readFile } from 'node:fs/promises';

const cache = new Map();

const readFileWithCache = (path) => {
  if (cache.has(path)) {
    return cache.get(path);
  }

  return readFile(path, 'utf8').then((data) => {
    cache.set(path, data);
    return data;
  });
};
```

`readFileWithCache`は、初回は`readFile`で非同期にファイルを読み、2回目以降は`cache`に保存した値をそのまま返します。そのため戻り値は、初回は`Promise<string>`、2回目以降は`string`になり、呼び出す側は2つの場合を扱わなければなりません。

```js
console.log(readFileWithCache('path/to/file')); // 初回はPromise {<pending>}、2回目以降はファイルの中身の文字列
```

`Promise.try`で包むと、何回目の呼び出しでも`Promise<string>`が返ります。

```js
console.log(Promise.try(() => readFileWithCache('path/to/file'))); // 何回目でもPromise
```

この例は関数の中を直しても使いやすくできますが、`Promise.try`で包めば、関数の中に手を入れずに同期と非同期を同じように扱えます。

## おわりに

`Promise.try`を使うと、関数が同期で返すか非同期で返すかを気にせずに結果を扱え、同期で投げられた例外も`catch`で受け取れます。同期と非同期が混ざる関数を扱うときに使ってみてください。
