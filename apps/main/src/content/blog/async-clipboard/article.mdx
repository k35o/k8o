# Clipboard APIでテキストや画像をコピー・ペーストする

<BrowserSupportStatus featureId="async-clipboard"></BrowserSupportStatus>

## はじめに

Clipboard APIは、`navigator.clipboard`からクリップボードを読み書きするJavaScriptのAPIです。テキストは`writeText()`と`readText()`で、PNG画像は`ClipboardItem`に包んで`write()`と`read()`でコピー・ペーストします。

ユーザーがキーボードやメニューでコピー・貼り付けしたときの中身を差し替えるだけなら、`copy`・`paste`イベントの`clipboardData`で足ります。ボタンを押したときにコピーする、ボタンからクリップボードを読むといった、ユーザーのコピー操作を待たない読み書きはClipboard APIで書きます。ボタンからのコピーには以前`document.execCommand('copy')`を使っていましたが、非推奨です。読み取りの`document.execCommand('paste')`は、Chrome 156、Safari 27.2、Firefox 159のどれでも`false`を返し、何も貼り付けませんでした。

この記事では、Clipboard APIの使い方を最初に確認してから、Baseline 2025に追加された`ClipboardItem.supports()`について紹介します。

## Clipboard API

Clipboard APIは`Clipboard`インターフェースにより実装されており、`navigator.clipboard`を通じてアクセスできます。

`Clipboard`インターフェースは、以下の非同期なメソッドを提供しています。

- `readText()`: クリップボードからテキストデータを読みとる
- `writeText()`: クリップボードにテキストデータを書き込む
- `read()`: クリップボードからデータを読みとる
- `write()`: クリップボードにデータを書き込む

```js
// readText
navigator.clipboard.readText().then(console.log);

// writeText
navigator.clipboard
  .writeText('Hello, world!')
  .then(() => console.log('Text copied to clipboard!'));
```

`readText`と`writeText`は、テキストデータを扱うための簡単なメソッドです。`read`と`write`もベースは同じですが、テキスト以外のコンテンツも扱うため少し複雑です。こちらについては後ほど詳しく紹介します。

### 権限

Clipboard APIはセキュリティ上の都合で実行に対する制限がかけられています。

制限はブラウザによって異なります。例えばChromeでは読み込みと書き込みをPermissions APIを使って、`clipboard-read`と`clipboard-write`で確認できます。

```js
const readPermission = await navigator.permissions.query({
  name: 'clipboard-read',
});

readPermission.state === 'granted'; // クリップボードの読み取りが許可されている
readPermission.state === 'prompt'; // ユーザーに許可を求める
readPermission.state === 'denied'; // クリップボードの読み取りが拒否されている

const writePermission = await navigator.permissions.query({
  name: 'clipboard-write',
});

writePermission.state === 'granted'; // クリップボードの書き込みが許可されている
writePermission.state === 'prompt'; // ユーザーに許可を求める
writePermission.state === 'denied'; // クリップボードの書き込みが拒否されている
```

これに対し、FirefoxやSafariでは、これらの権限はサポートされていません。Safari 27.2とFirefox 159では、`navigator.permissions.query()`に`clipboard-read`や`clipboard-write`を渡すと`TypeError`で失敗します。

ユーザーの操作を挟まずに`readText()`を呼ぶと、Safari 27.2とFirefox 159はどちらも`NotAllowedError`で拒否しました。

> Safariで発生するエラー: The request is not allowed by the user agent or the platform in the current context, possibly because the user denied permission.

Firefoxのエラーは`Clipboard read request was blocked due to lack of user activation.`で、ユーザーの操作が無いことを理由に挙げています。

## ClipboardItem

`ClipboardItem`は、クリップボードに書き込むデータを表すオブジェクトです。先ほど挙げた`Clipboard`インターフェースで利用できる`read`と`write`で使われます。
`read`はクリップボードから読み取ったデータを`ClipboardItem`の配列で解決し、`write`は引数に渡した`ClipboardItem`の配列をクリップボードに書き込みます。

```ts
// read
const clipboardItems = await navigator.clipboard.read();
for (const clipboardItem of clipboardItems) {
  for (const type of clipboardItem.types) {
    const blob = await clipboardItem.getType(type);
    console.log(blob);
  }
}

// write
const item = new ClipboardItem({
  'image/png': new Blob(['...'], { type: 'image/png' }),
});
navigator.clipboard
  .write([item])
  .then(() => console.log('Image copied to clipboard!'));
```

`ClipboardItem`は2つの引数によって組み立てられます。

1つ目の引数はオブジェクトをデータで渡します。`MIME`タイプをキーに、Blobや文字列、これらをPromiseでラップしたものを値に持つオブジェクトを渡します。

```js
{
  'image/png': new Blob(['...'], { type: 'image/png' }),
  'text/plain': 'Hello, world!',
}
```

2つ目の引数はオブジェクトでオプションを渡します。現在は`presentationStyle`をサポートしています。値には`unspecified`、`inline`、`attachment`を渡せます。デフォルト値は `unspecified`です。
コンテンツを貼り付ける際に、貼り付け位置に適切な表現をインラインで表示する`inline`と添付ファイルとして扱う`attachment`があります。

```ts
new ClipboardItem(
  { 'text/plain': 'Hello, world!', },
  { presentationStyle: 'unspecified' },
);
new ClipboardItem(
  { 'text/plain': 'Hello, world!', },
  { presentationStyle: 'inline' },
);
new ClipboardItem(
  { 'text/plain': 'Hello, world!', },
  { presentationStyle: 'attachment' },
);
```

Chrome 156の`ClipboardItem`には`presentationStyle`のプロパティが無く、渡した値を読むと`undefined`でした。Safari 27.2とFirefox 159では、渡した値がそのまま返ります。

作成された`ClipboardItem`インスタンスは、`types`プロパティ、`getType()`メソッドを持ちます（Baselineで対応しているものだけを紹介しています）。
`types`は利用可能なMIMEタイプを配列で返し、`getType()`は第一引数に渡したMIMEタイプをもとにPromiseで解決したBlobを返します。

```js
const item = new ClipboardItem(
  {
    'image/png': new Blob(['...'], { type: 'image/png' }),
    'text/plain': 'Hello, world!',
  },
  { presentationStyle: 'inline' },
);
console.log(item.types); // ['image/png', 'text/plain']
for (const type of item.types) {
  item.getType(type).then((blob) => {
    // Blob {size: 3, type: 'image/png'}
    // Blob {size: 13, type: 'text/plain'}
    console.log(blob);
  });
}
item.getType('text/html').catch((err) => {
  // NotFoundError: Failed to execute 'getType' on 'ClipboardItem': The type was not found
  console.error(err);
});
```

### ClipboardItem supports

<BrowserSupportStatus featureId="clipboard-supports"></BrowserSupportStatus>

`ClipboardItem.supports`はClipboard APIとして、特定のMIMEタイプがサポートされていることを確認するためのものです。

`text/plain`、`text/html`、`image/png`は常にサポートされていますが、`text/uri-list`、`image/svg+xml`と`web `で始めるカスタムMIMEタイプは、ブラウザやOSによって結果が異なります。

<LinkCard href="https://w3c.github.io/clipboard-apis/#dom-clipboarditem-supports" />

サポートされていれば`true`、サポートされていなければ`false`を返します。

```js
// [!og]
ClipboardItem.supports('text/plain'); // true
ClipboardItem.supports('text/html'); // true
ClipboardItem.supports('image/png'); // true

ClipboardItem.supports('text/uri-list'); // true or false
ClipboardItem.supports('image/svg+xml'); // true or false
ClipboardItem.supports('web image/png'); // true or false

ClipboardItem.supports('application/json'); // false
```

手元で試すと、ブラウザによって結果が分かれるMIMEタイプは次のようになりました。

- Chrome 156: `image/svg+xml`と`web `で始まるタイプが`true`、`text/uri-list`が`false`
- Safari 27.2: `text/uri-list`が`true`、`image/svg+xml`と`web `で始まるタイプが`false`
- Firefox 159: 3つとも`false`

`image/jpeg`は、どのブラウザでも`false`でした。JPEGの画像は、次の節のようにcanvasでPNGにしてから書き込みます。

### PNG画像のコピーと貼り付け

ClipboardItemを利用してPNG画像のコピーと貼り付けを行う例を作成しました。

<PlaygroundEmbed demo="画像のコピー・ペースト" headingLevel="h5" sectionId="async-clipboard" />

画像を選んでコピーのボタンを押すと、その画像がPNGとしてクリップボードに入ります。表示のボタンを押すと、クリップボードにあるPNG画像がペーストされた画像の欄に出ます。

コピーを行う関数と貼り付けを行う関数は以下のようになっています。`copyImage`は画像をcanvasに描き、`toBlob()`でPNGのBlobにしてから書き込みます。

```ts
const copyImage = async () => {
  const img = document.getElementById('source') as HTMLImageElement | null;
  if (!img) return;
  const canvas = document.createElement('canvas');
  canvas.width = img.naturalWidth;
  canvas.height = img.naturalHeight;
  const ctx = canvas.getContext('2d');
  if (!ctx) return;
  ctx.drawImage(img, 0, 0);
  const blob = await new Promise<Blob>((resolve, reject) => {
    canvas.toBlob((blob) => {
      if (!blob) {
        reject(new Error('Blobが取得できませんでした'));
        return;
      }
      resolve(blob);
    });
  });
  const file = new File([blob], 'image.png', { type: 'image/png' });
  const data = [new ClipboardItem({ 'image/png': file })];
  await navigator.clipboard.write(data);
};

const pasteImage = async () => {
  const img = document.getElementById('pasted') as HTMLImageElement | null;
  if (!img) return;
  const items = await navigator.clipboard.read();
  for (const item of items) {
    for (const type of item.types) {
      if (type === 'image/png') {
        const blob = await item.getType(type);
        const url = URL.createObjectURL(blob);
        img.src = url;
      }
    }
  }
};
```

`canvas.toBlob()`のコールバックの中で`throw`しても、Promiseは拒否されません。幅と高さが0のcanvasでは、コールバックに`null`が渡ります。これで試すと、Chrome 156、Safari 27.2、Firefox 159のどれでもPromiseは待ち続け、エラーは`window`の`error`イベントに出ました。コールバックの中では`reject`を呼びます。

## おわりに

Clipboard APIは、クリップボードにアクセスするためのAPIです。
これを使うことで、ユーザーが選択したテキストや画像などをクリップボードへコピーしたり、クリップボードからデータを貼り付けられます。

過去には`execCommand()`を利用していましたが、Clipboard APIを利用することで、より簡単に安全にクリップボードにアクセスできるようになりました。
`execCommand()`は非推奨なので、今後はClipboard APIを利用するようにしましょう。
