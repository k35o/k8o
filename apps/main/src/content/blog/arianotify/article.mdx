# ariaNotify()でスクリーンリーダーに文字列を読み上げさせる

<BrowserSupportStatus featureId="arianotify" />

## はじめに

`ariaNotify()`は、引数に渡した文字列をスクリーンリーダーに読み上げさせる、`document`と要素のメソッドです。DOMを書き換えずに、画面の変化を音声で伝えられます。Safari 27が対応して、Baseline 2026に入りました。

画面に出ている文字の変化を読ませるだけなら、`aria-live`のライブリージョンで足ります。エディタのショートカットで太字を切り替えたときや、バックグラウンドの保存が終わったときの変化は、画面を見ていれば伝わりますが、スクリーンリーダーの利用者には伝わりません。これまでは読み上げ専用の隠し要素に`aria-live`を付け、伝えたい文字列をそこへ書き込んで読ませていました。`ariaNotify()`なら、読ませるためだけにDOMを書き換える必要がありません。

## 書き方

`ariaNotify()`は`document`と各要素にあり、第1引数に読み上げさせる文字列を渡します。

```js
// [!og]
const editor = document.querySelector('#editor');

editor.addEventListener('keydown', (event) => {
  if (!(event.ctrlKey || event.metaKey) || event.key !== 'b') return;
  event.preventDefault();
  const isBold = toggleBold(editor);
  // 見た目は太字になるが、それだけでは切り替わったことが伝わらない
  editor.ariaNotify(isBold ? '太字 オン' : '太字 オフ');
});
```

第2引数の`priority`には`'normal'`か`'high'`を指定でき、既定は`'normal'`です。`'normal'`は読み上げ中の内容が終わってから、`'high'`は読み上げ中の内容を中断して読まれます。`aria-live`の`polite`と`assertive`にあたります。どのブラウザでも、`priority`に`'low'`のような別の値を渡すと`TypeError`になります。

```js
// 読み上げ中の内容を中断して読ませる
editor.ariaNotify('保存に失敗しました', { priority: 'high' });

// 特定の要素に紐づかない通知はdocumentで呼ぶ
document.ariaNotify('下書きを保存しました');
```

ボタンを押すと、入力した文字列をボタンの`ariaNotify()`に渡し、呼び出し履歴に渡した引数と親の`lang`属性が並びます。スクリーンリーダーを起動した状態で押すと、その文字列が読み上げられます。

## ライブリージョンとの違い

ライブリージョンが読むのは、`aria-live`を付けた要素の中身の変化です。読ませる文字列はその要素の中身に限られ、要素もあらかじめDOMに置いておく必要があります。挿入した直後に中身を入れると、読まれないことがあるためです。

`ariaNotify()`は引数の文字列をそのまま読みます。画面には件数だけを出し、読み上げでは`24件に絞り込みました`と伝える、といった使い分けができます。事前に要素を用意する必要もありません。

## どの要素で呼ぶか

特定のUIに関わる通知はその要素で、ページ全体に関わる通知は`document`で呼ぶのが素直です。どちらで呼んでも読まれますが、次の2点が変わります。

1つ目は読み上げの言語です。要素で呼ぶと、その要素に最も近い`lang`属性の言語で読まれます。`document`で呼ぶと`<html>`要素の`lang`属性の言語です。日本語のページに埋め込んだ英語のUIなら、そのUIの要素で呼べば英語の音声で読まれます。

2つ目は非表示の要素の扱いです。`display: none`や`hidden`属性、`aria-hidden="true"`などでアクセシビリティツリーから外れた要素で呼ぶと、何も起きません。どのブラウザでも、こうした要素やDOMに追加していない要素で呼んでも、例外は出ずに`undefined`が返ります。読まれないときは、呼んだ要素が非表示になっていないかを確かめます。

## 使うときの注意

呼ぶ回数には気を配る必要があります。続けて呼ぶと、最後の1件しか読まれないことがあります。伝えたい内容は1回の呼び出しにまとめます。ユーザー操作が無くても呼べるので、タイマーや通信の完了を起点にもできます。どのブラウザでも、ページを開いてクリックする前に呼んで例外は出ません。ただし、乱発すると利用者の操作を妨げます。

MDNの互換性データには、読み上げられない環境が載っています。macOSでは、フォーカス中の入力欄の値が変わるなど、別のアクセシビリティイベントが同時に起きると通知が読まれないことがあります。VoiceOverがそちらを読むためです。ChromeOSでは、メソッドはあっても読み上げは行われません。

TypeScriptのDOMの型には、まだ`ariaNotify()`がありません。そのまま呼ぶとTS2339のエラーになるので、型の宣言を足します。

```ts title="aria-notify.d.ts"
type AriaNotificationOptions = {
  priority?: 'normal' | 'high';
};

interface Element {
  ariaNotify(announcement: string, options?: AriaNotificationOptions): void;
}

interface Document {
  ariaNotify(announcement: string, options?: AriaNotificationOptions): void;
}
```

## おわりに

`ariaNotify()`があれば、読み上げのためだけに隠しライブリージョンを置いて書き換える必要はありません。
