# Screen Wake Lock APIで画面のスリープを防ぐ

<BrowserSupportStatus featureId="screen-wake-lock"></BrowserSupportStatus>

## はじめに

Screen Wake Lock APIは、ページを表示しているあいだ、端末の画面が暗くなったりスリープしたりするのを止めるAPIです。`navigator.wakeLock.request('screen')`でロックを取ると、タブを離れるか`release()`を呼ぶまで画面が点いたままになります。iOSのSafari 18.4が対応して、Baseline 2025に入りました。

レシピを見ながら料理するときのように、画面を見ているのに触らない場面では、OSの設定した時間で画面が暗くなります。Screen Wake Lock APIを使うと、ページの側から画面を点けたままにできます。

## Screen Wake Lock APIによるスリープを体験する

Screen Wake Lock APIを使用してスリープのロックを要求するボタンを用意しました。

```html demo="lock" allow="screen-wake-lock"
<button id="lock" type="button">スリープ機能をロックする</button>
```

```js demo="lock"
const button = document.querySelector('#lock');
let wakeLock = null;

button.disabled = !('wakeLock' in navigator);
button.addEventListener('click', async () => {
  if (wakeLock !== null) {
    await wakeLock.release();
    return;
  }
  wakeLock = await navigator.wakeLock.request('screen');
  button.textContent = 'スリープ機能のロックを解除する';
  // release() を呼んだときも、タブを離れてブラウザが解除したときも届く
  wakeLock.addEventListener('release', () => {
    wakeLock = null;
    button.textContent = 'スリープ機能をロックする';
  });
});
```

ボタンを押してロックを取ると、ボタンの文言がロックを解除する文言に切り替わります。

Macでは、標準のアクティビティモニタで確かめられます。`エネルギー`のタブを開くと、ロックしているあいだは、お使いのブラウザの行の`非スリープ`の列が`はい`になります。

ブラウザのタブを切り替えたり、スクリーンを畳んだりすると`非スリープ`が`いいえ`に変わります。

ボタンを押してから別のタブに切り替えて戻ってくると、ボタンの文言がロックする前の文言に戻っていることがわかります。

これは表示中のタブが有効な範囲でのみScreen Wake Lock APIが有効になり、有効範囲からはみ出るとロックが解除されるためです。

Macのターミナルからは`pmset -g assertions`で確かめられます。ChromeとFirefoxでロックを取ると、ブラウザのプロセスに`NoDisplaySleepAssertion`の行が加わり、その名前はChromeでは`Blink Wake Lock`、Firefoxでは`screen`です。Firefoxでは、別のタブに切り替えるとこの行が消えます。

## Screen Wake Lock APIの使い方

Screen Wake Lock APIは、`navigator.wakeLock`から使用します。

`navigator.wakeLock.request()`メソッドを使用すると、画面のスリープを防ぐことを要求し、`WakeLockSentinel`インスタンスを返します。
このインスタンスは、ロックを解除するための`release()`メソッドを持っています。

```js
// [!og]
let wakeLock = null;

// 画面をロックする
wakeLock = await navigator.wakeLock.request('screen');

// 画面のロックを解除する
await wakeLock.release();
```

### navigator.wakeLock.request

`navigator.wakeLock.request`は画面のスリープを防ぐことを要求するメソッドです。

`navigator.wakeLock.request`は第1引数にロックの種類を任意で渡せます。
指定できるのは`screen`だけで、省略しても`screen`になります。`'system'`のような別の値を渡すと`TypeError`になります。

戻り値は`WakeLockSentinel`インスタンスで解決するPromiseです。ロックを取れないときは`NotAllowedError`で拒否されます。たとえば次のときです。

- タブが隠れているとき
- `allow="screen-wake-lock 'none'"`を付けた`iframe`の中
- ボタンを押すといったユーザーの操作を経ずに呼んだとき（Safariだけ）

Safariでは、ページを開いた直後に呼んでも、`button.click()`でスクリプトからクリックして呼んでも断られ、`navigator.permissions.query({ name: 'screen-wake-lock' })`は`prompt`を返します。ChromeとFirefoxは`granted`を返し、ページを開いた直後でもロックを取れます。Safariに対応するなら、デモのようにボタンを押したときに`request()`を呼ぶ形にします。

### WakeLockSentinel

`WakeLockSentinel`インスタンスは`released`プロパティと`type`プロパティ、`release()`メソッドを持ちます。

`released`プロパティは`navigator.wakeLock.request`によるロックが解除されているかどうかを示すプロパティで、`type`プロパティはロックの種類を示します。

```js
wakeLock.released; // false
wakeLock.type; // 'screen'
```

`release()`メソッドは`navigator.wakeLock.request`によるロックを解除するためのメソッドです。

```js
// 画面のロックを解除する
await wakeLock.release();
```

`WakeLockSentinel`インスタンスは、`addEventListener`で`release`を指定して、`navigator.wakeLock.request`によるロックが解除されたときに発火するイベントを登録できます。

```js
const wakeLock = await navigator.wakeLock.request('screen');
// タブを切り替えるなど、何かしらの操作によるロックの解除を検知する
wakeLock.addEventListener('release', () => {
  console.log('Wake Lock was released');
});
```

`release`イベントは、そのインスタンスのロックが外れたことを知らせるだけで、画面のロックが外れたとは限りません。`request()`を2回呼び、片方だけ`release()`すると、`release`は呼んだほうにだけ発火します。もう片方の`released`は`false`のままです。ChromeとFirefoxでは、`pmset -g assertions`の行も残ります。同じインスタンスの`release()`を2回呼んでもエラーにはならず、イベントも1回しか発火しません。

### タブに戻ったときに取り直す

タブを離れるとロックは外れ、戻ってきても取り直されません。レシピのページのように見ているあいだずっと画面を点けておきたいときは、`visibilitychange`でタブに戻ったことを知り、もう一度`request()`を呼びます。

```js
let wakeLock = null;

const requestWakeLock = async () => {
  wakeLock = await navigator.wakeLock.request('screen');
};

button.addEventListener('click', requestWakeLock);

document.addEventListener('visibilitychange', async () => {
  if (wakeLock !== null && document.visibilityState === 'visible') {
    await requestWakeLock();
  }
});
```

Firefoxでは、別のタブに切り替えたときに`visibilitychange`、`release`の順に発火し、隠れているあいだの`request()`は`NotAllowedError`で断られます。元のタブに戻ると`visibilitychange`の中で新しいロックが取れ、`pmset -g assertions`の行も戻ります。Safariでは、ボタンを押さずに開いたページだと、タブに戻ったときの`visibilitychange`の中で呼んだ`request()`も`NotAllowedError`で断られます。

## おわりに

Screen Wake Lock APIを使うと、見ているのに触らないページで画面を点けたままにできます。ロックはタブを離れると外れ、Safariではユーザーの操作を経ずに呼ぶと断られるので、最初のロックはボタンを押したときに取り、タブに戻ったときに取り直します。
