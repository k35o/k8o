# Screen Wake Lock APIで画面のスリープを防ぐ

<BrowserSupportStatus featureId="screen-wake-lock"></BrowserSupportStatus>

## はじめに

Screen Wake Lock APIは、ページを表示しているあいだ、端末の画面が暗くなったりスリープしたりするのを止めるAPIです。`navigator.wakeLock.request('screen')`でロックを取ると、タブを離れるか`release()`を呼ぶまで画面が点いたままになります。

ユーザーが画面を触っているあいだは、OSが画面を点けたままにするので、このAPIは要りません。レシピを見ながら料理するときのように、画面を見ているのに触らない場面では、OSの設定した時間で画面が暗くなります。この場面でページの側から画面を点けたままにできるのが、Screen Wake Lock APIです。2025年のBaselineに追加されました。

## Screen Wake Lock APIによるスリープを体験する

Screen Wake Lock APIを使用してスリープのロックを要求するボタンを用意しました。

<PlaygroundEmbed demo="スクリーンスリープ防止" headingLevel="h4" sectionId="screen-wake-lock" />

ボタンを押してロックを取ると、ボタンの文言がロックを解除する文言に切り替わります。

Macでは、標準のアクティビティモニタで確かめられます。`エネルギー`のタブを開くと、ロックしているあいだは、お使いのブラウザの行の`非スリープ`の列が`はい`になります。

ブラウザのタブを切り替えたり、スクリーンを畳んだりすると`非スリープ`が`いいえ`に変わります。

ボタンを押してから別のタブに切り替えて戻ってくると、ボタンの文言がロックする前の文言に戻っていることがわかります。

これは表示中のタブが有効な範囲でのみScreen Wake Lock APIが有効になり、有効範囲からはみ出るとロックが解除されるためです。
この仕様はセキュリティとプライバシーの問題を解決してくれています。

ターミナルからは`pmset -g assertions`で確かめられます。Chrome 156とFirefox 159でロックを取ると、ブラウザのプロセスに`NoDisplaySleepAssertion`の行が加わり、その名前はChromeでは`Blink Wake Lock`、Firefoxでは`screen`でした。Firefox 159では、別のタブに切り替えるとこの行が消えました。

## Screen Wake Lock APIの使い方

Screen Wake Lock APIは、`navigator.wakeLock`から使用します。

`navigator.wakeLock.request()`メソッドを使用すると、画面のスリープを防ぐことを要求し、`WakeLockSentinel`インスタンスを返します。
このインスタンスは、ロックを解除するための`release()`メソッドを持っています。

```js
// [!og]
let wakeLock = null;

// 画面をロックする
wakeLock = await navigator.wakeLock.request('screen');

// 画面のロックを解除する
await wakeLock.release();
```

### navigator.wakeLock.request

`navigator.wakeLock.request`は画面のスリープを防ぐことを要求するメソッドです。

`navigator.wakeLock.request`は第1引数にロックの種類を任意で渡せます。
指定できるのは`screen`だけで、省略しても`screen`になります。Chrome 156、Safari 27.2、Firefox 159のいずれでも、`'system'`のような別の値を渡すと`TypeError`になりました。

戻り値は`WakeLockSentinel`インスタンスで解決するPromiseです。ロックを取れないときは`NotAllowedError`で拒否されます。試したなかでは、次のときに`NotAllowedError`になりました。

- タブが隠れているとき（Firefox 159）
- `allow="screen-wake-lock 'none'"`を付けた`iframe`の中（Chrome 156、Safari 27.2、Firefox 159）
- ボタンを押すといったユーザーの操作を経ずに呼んだとき（Safari 27.2）

Safari 27.2では、ページを開いた直後に呼んでも、`button.click()`でスクリプトからクリックして呼んでも断られ、`navigator.permissions.query({ name: 'screen-wake-lock' })`は`prompt`を返しました。Chrome 156とFirefox 159は`granted`を返し、ページを開いた直後でもロックを取れました。Safariに対応するなら、デモのようにボタンを押したときに`request()`を呼ぶ形にします。

### WakeLockSentinel

`WakeLockSentinel`インスタンスは`released`プロパティと`type`プロパティ、`release()`メソッドを持ちます。

`released`プロパティは`navigator.wakeLock.request`によるロックが解除されているかどうかを示すプロパティで、`type`プロパティはロックの種類を示します。

```js
wakeLock.released; // false
wakeLock.type; // 'screen'
```

`release()`メソッドは`navigator.wakeLock.request`によるロックを解除するためのメソッドです。

```js
// 画面のロックを解除する
await wakeLock.release();
```

`WakeLockSentinel`インスタンスは、`addEventListener`で`release`を指定して、`navigator.wakeLock.request`によるロックが解除されたときに発火するイベントを登録できます。

```js
const wakeLock = await navigator.wakeLock.request('screen');
// タブを切り替えるなど、何かしらの操作によるロックの解除を検知する
wakeLock.addEventListener('release', () => {
  console.log('Wake Lock was released');
});
```

`release`イベントは、そのインスタンスのロックが外れたことを知らせるだけで、画面のロックが外れたとは限りません。Chrome 156とFirefox 159で`request()`を2回呼び、片方だけ`release()`すると、`release`は呼んだほうにだけ発火しました。もう片方の`released`は`false`のままで、`pmset -g assertions`の行も残りました。同じインスタンスの`release()`を2回呼んでもエラーにはならず、イベントも1回しか発火しません。

### タブに戻ったときに取り直す

タブを離れるとロックは外れ、戻ってきても取り直されません。レシピのページのように見ているあいだずっと画面を点けておきたいときは、`visibilitychange`でタブに戻ったことを知り、もう一度`request()`を呼びます。

```js
let wakeLock = null;

const requestWakeLock = async () => {
  wakeLock = await navigator.wakeLock.request('screen');
};

button.addEventListener('click', requestWakeLock);

document.addEventListener('visibilitychange', async () => {
  if (wakeLock !== null && document.visibilityState === 'visible') {
    await requestWakeLock();
  }
});
```

Firefox 159で試すと、別のタブに切り替えたときに`visibilitychange`、`release`の順に発火し、隠れているあいだの`request()`は`NotAllowedError`で断られました。元のタブに戻ると`visibilitychange`の中で新しいロックが取れ、`pmset -g assertions`の行も戻りました。Safari 27.2では、ボタンを押さずに開いたページで試すと、タブに戻ったときの`visibilitychange`の中で呼んだ`request()`も`NotAllowedError`で断られました。

## おわりに

Baseline 2025に追加された、Screen Wake Lock APIの紹介を行いました。
ページを開いたままデバイスの外側で作業を行うときに悩まされるスリープの問題を解決してくれるAPIです。

ロックはタブを離れると外れるので、レシピのページのように見続けてもらうページでは、タブに戻ったときに取り直します。Safariではユーザーの操作を経ずに呼ぶと断られるので、最初のロックはボタンを押したときに取る形にしておきます。
