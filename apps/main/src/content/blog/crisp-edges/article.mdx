# image-renderingでドット絵をぼかさずに拡大する

<BrowserSupportStatus featureId="crisp-edges" />

## はじめに

`image-rendering`は、画像を拡大や縮小して表示するときのアルゴリズムを切り替えるCSSプロパティです。`crisp-edges`を指定すると、色を混ぜずにピクセルの境界をはっきり保ったまま拡大でき、ドット絵やQRコードがぼやけません。Chrome 148が`crisp-edges`に対応して、Baseline 2026に入りました。

ブラウザは画像を本来のサイズより大きく表示するとき、既定では色を補間して滑らかに見せます。写真ならこれで自然に拡大されるので、指定は要りません。ドット絵やQRコードのように、ピクセル単位で意味を持つ画像はぼやけて絵柄が崩れるので、`crisp-edges`か`pixelated`を指定します。

## image-renderingの値

`image-rendering`は、`<img>`や`<canvas>`、`background-image`のように、ラスタ画像を拡大や縮小して描くすべての要素に指定できます。主な値は次の3つです。

- `auto`（既定値）：ブラウザに任せる。多くのブラウザは双線形補間のような滑らかな拡大を選ぶ
- `crisp-edges`：色の補間やぼかしを避け、境界とコントラストを保つ。最近傍法（nearest neighbor）か同じような手法が使われる
- `pixelated`：整数倍までは最近傍法で拡大し、端数の分だけ補間する

`crisp-edges`と`pixelated`はどちらも、拡大してもピクセルの境界をはっきり残す値ですが、[仕様](https://drafts.csswg.org/css-images-3/#valdef-image-rendering-crisp-edges)が求めるアルゴリズムが少し違います。`crisp-edges`は色を混ぜず境界をぼかさないことだけが決まっていて、具体的な手法はブラウザに任されています。`pixelated`は、まず最近傍法で次に大きい整数倍まで拡大し、そのあと補間で目的の大きさに仕上げます。

仕様の上では、整数倍でない大きさに拡大したとき、`pixelated`だけが境界を少し補間します。ただ、ブラウザはどちらの値でも色を混ぜずに描くので、見た目はほとんど変わりません。次の3つは、4×4の白黒の市松模様を102pxに拡大したものです。

`auto`は境界がぼやけて灰色が混ざり、`crisp-edges`と`pixelated`は白と黒の2色だけで描かれます。

## 使い方

ドット絵風の小さな画像を`<img>`で拡大して表示する例です。

```css
/* [!og] */
img.pixel-art {
  image-rendering: crisp-edges;
  width: 256px; /* 元画像が16x16でも、最近傍法で滲まずに拡大される */
}
```

`background-image`で背景に貼り付ける場合も、同じプロパティが効きます。

```css
.tile {
  background-image: url('/sprites.png');
  image-rendering: crisp-edges;
}
```

接頭辞の付いた値は、今は要りません。`-moz-crisp-edges`を受け付けるのはFirefoxだけで（計算値は`crisp-edges`）、ChromeとSafariは受け付けません。接頭辞なしの`crisp-edges`は、どのブラウザも受け付けます。

## おわりに

`image-rendering: crisp-edges`を指定すると、ドット絵やQRコードを拡大しても色が混ざらず、ピクセルの境界がはっきり残ります。接頭辞の付いた`-moz-crisp-edges`は要らず、接頭辞なしの`crisp-edges`だけを書けば足ります。
