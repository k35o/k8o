# contenteditableでプレーンテキストだけを編集させる

<BrowserSupportStatus featureId="contenteditable-plaintextonly"></BrowserSupportStatus>

## はじめに

`contenteditable`は、付けた要素の中身をページの上でそのまま編集できるようにするHTMLのグローバル属性です。値を`plaintext-only`にすると、貼り付けた太字や背景色などの書式を受け付けず、テキストだけを編集させられます。Firefox 136が対応して、Baseline 2025に入りました。

フォームに文字を入力させるだけなら、`textarea`や`input`で足ります。`contenteditable`が要るのは、見出しや段落のようなページの中の要素を、その見た目のまま編集させたいときです。`contenteditable="true"`では貼り付けた書式も入るため、テキストだけに限るには`paste`イベントで書式を落とす処理を書いていました。`plaintext-only`なら、属性だけでテキストに限れます。

## contenteditable

値を`true`にすると、要素の中身を書式ごと自由に編集できます。

```html
<div contenteditable="true">
  ここを編集できます
</div>
```

<Playground

    ここを編集できます

例の文字は、選んで書き換えられます。例の上の題をコピーして貼り付けると、文字と一緒に背景色と太字も入ります。

要素が編集できる状態かは、`HTMLElement.isContentEditable`で分かります。子要素を持てない`img`や`input`に付けても`true`を返すので、要素が編集に向くかどうかの判定には使えません。

## plaintext-only

値を`plaintext-only`にすると、要素の中のテキストだけを編集できます。

```html
<!-- [!og] -->
<div contenteditable="plaintext-only">
  ここを編集できます
</div>
```

<Playground
  headingLevel="h4"
  title={
    'div要素にcontenteditable="plaintext-only"を付与したサンプル'
  }
>
  <div
    contentEditable="plaintext-only"
    suppressContentEditableWarning
  >
    ここを編集できます
  </div>
</Playground>

上と同じように題をコピーして貼り付けると、文字だけが入り、背景色と太字は入りません。テキストしか入らないので、`true`のときより、実装で考えるケースが減ります。

書式を付けるコマンドも効きません。選んだ文字に`document.execCommand('bold')`を実行すると、`true`では`<b>`で囲まれますが、`plaintext-only`では`false`が返って何も変わりません。`insertHTML`のコマンドで`<b>太字</b>`を入れても、`plaintext-only`ではタグが落ちて文字だけが入ります。

編集した値は、`textContent`ではなく`innerText`で読みます。`plaintext-only`の要素でも、改行のコマンドによっては`<br>`や`<div>`の要素が入るからです。改行を入れる`insertLineBreak`のコマンドを実行すると、Chromeでは`\n`の文字が、SafariとFirefoxでは`<br>`が入ります。`<br>`が入ると`textContent`からは改行が消えますが、`innerText`ならどのブラウザでも改行を`\n`で取れます。

```html
<h1 contenteditable="plaintext-only" id="title">記事のタイトル</h1>
```

```js
document.querySelector('#title').addEventListener('input', (event) => {
  console.log(event.currentTarget.innerText);
});
```

入力のたびに、改行を`\n`にした値がコンソールに出ます。

## おわりに

`contenteditable="true"`では、貼り付けた書式まで入ることを考えて実装する必要がありました。`plaintext-only`ならテキストだけを受け付けるので、リッチテキストを扱わない場面では、属性を1つ書くだけで書式の心配が要らなくなります。
