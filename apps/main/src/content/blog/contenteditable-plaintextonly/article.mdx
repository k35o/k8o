# contenteditableでプレーンテキストだけを編集させる

<BrowserSupportStatus featureId="contenteditable-plaintextonly"></BrowserSupportStatus>

## はじめに

`contenteditable`は、付けた要素の中身をページの上でそのまま編集できるようにするHTMLのグローバル属性です。値を`plaintext-only`にすると、貼り付けた太字や背景色などの書式を受け付けず、テキストだけを編集させられます。Firefox 136が対応して、Baseline 2025に入りました。

フォームの文字の入力には、`textarea`や`input`を使います。`contenteditable`が要るのは、見出しや段落のようなページの中の要素を、その見た目のまま編集させたいときです。`contenteditable="true"`では貼り付けた書式も入るため、テキストだけに限るには`paste`イベントで書式を落とす処理を書いていました。`plaintext-only`なら、属性だけでテキストに限れます。

## contenteditable

値を`true`にすると、要素の中身を書式ごと自由に編集できます。

```html demo="editable"
<p><b style="background-color: gold; color: black">コピーする文字</b></p>
<div contenteditable="true">
  ここを編集できます
</div>
```

結果の欄の文字は、選んで書き換えられます。その上の背景色と太字の付いた文字をコピーして貼り付けると、文字と一緒に背景色と太字も入ります。

下の画像のように、Baselineの表示をそのまま貼り付けることもでき、画像も入ります。

要素が編集できる状態かは、`HTMLElement.isContentEditable`で分かります。子要素を持てない`img`や`input`に付けても`true`を返すので、要素が編集に向くかどうかの判定には使えません。

## plaintext-only

値を`plaintext-only`にすると、要素の中のテキストだけを編集できます。

```html demo="plaintext-only"
<!-- [!og] -->
<div contenteditable="plaintext-only">
  ここを編集できます
</div>
```

上の例と同じ文字をコピーして貼り付けると、文字だけが入り、背景色と太字は入りません。テキストしか入らないので、`true`のときより、実装で考えるケースが減ります。

`document.execCommand('bold')`のような書式のコマンドも、`plaintext-only`では効かずに`false`を返し、`insertHTML`で入れたタグも落ちて文字だけが入ります。

編集した値は、`textContent`ではなく`innerText`で読みます。`plaintext-only`でも、SafariとFirefoxでは改行が`<br>`などの要素で入り、`textContent`ではその改行が消えるからです。

```html
<h1 contenteditable="plaintext-only" id="title">記事のタイトル</h1>
```

```js
document.querySelector('#title').addEventListener('input', (event) => {
  console.log(event.currentTarget.innerText);
});
```

入力のたびに、改行を`\n`にした値がコンソールに出ます。

## おわりに

`contenteditable="plaintext-only"`を使うと、ページの中の要素をその見た目のまま、テキストだけを受け付ける編集欄にできます。リッチテキストを扱わない場面では、貼り付けた書式も属性だけで落とせます。
