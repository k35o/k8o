# WebTransportでQUIC（HTTP/3）の双方向通信をする

<BrowserSupportStatus featureId="webtransport" />

## はじめに

WebTransportは、QUIC（HTTP/3）の上で、ブラウザとサーバーがデータを双方向にやり取りするAPIです。1本の接続に独立したストリームをいくつも開け、届かなくても再送しないデータグラムも送れます。Safari 26.4が対応して、Baseline 2026に入りました。

チャットや通知のように少量のテキストをやり取りするだけなら、サーバーのライブラリやホスティングがそろったWebSocketで足ります。しかし、WebSocketはTCPの上で1本のメッセージ列しか持てないので、一部のデータが遅れると後のデータまで待たされます。遅れたデータを待たずにほかの流れを進めたい通信や、ゲームの座標のように古い値を捨ててよい通信は、WebTransportで書けます。

## 使い方

WebTransportは、HTTPSで配ったページのようなSecure Contextでだけ使え、Web Workerからも使えます。渡すURLは`https`で始めます。`http`のURLや`#`の付いたURLを渡すと、コンストラクタが`SyntaxError`を投げます。ポート番号を省くと、`https`の既定の443番につなぎます。

### コネクションを開く

`WebTransport`コンストラクタにURLを渡し、`ready`プロミスを待つことで接続が確立します。

```ts
const transport = new WebTransport('https://example.com:4433/chat');

await transport.ready;
console.log('接続完了');

// 切断時の処理
transport.closed
  .then(() => console.log('正常に切断されました'))
  .catch((err) => console.error('切断時にエラー', err));
```

切断したいときは`transport.close()`を呼びます。

手元のサーバーに開発用の自己署名の証明書でつなぐときは、`serverCertificateHashes`に証明書のSHA-256のハッシュを渡します。

```ts
const transport = new WebTransport('https://localhost:4433/chat', {
  serverCertificateHashes: [{ algorithm: 'sha-256', value: certHash }],
});
```

`certHash`は、`openssl x509 -in cert.pem -outform der | openssl dgst -sha256 -binary`で出る32バイトを`Uint8Array`にしたものです。仕様では、ハッシュで許す証明書はECDSAの鍵で、有効期間が2週間以内のものに限られます。

`serverCertificateHashes`を渡さないと、`ready`が`WebTransportError`で拒否されます。

### データグラムの送受信

データグラムは順序保証も再送もない、もっとも軽量な送受信方法です。
最悪届かなくても最新の値で上書きすればよい、チャットの入力状態やキャラクターの座標のようなデータの送受信に向いています。

データグラムは`transport.datagrams`の`readable`で受け取り、`createWritable()`で作った書き込み用のストリームで送ります。Chromeは`createWritable()`を持たず、`writable`だけを持ちます。Safariは逆に`writable`を持たないので、`transport.datagrams.writable.getWriter()`と書くと`TypeError`になります（Firefoxは両方を持つ）。どちらも標準のStreams APIなので、`getReader()`や`getWriter()`でそのまま扱えます。

```js
// 送信
const writable =
  transport.datagrams.createWritable?.() ?? transport.datagrams.writable;
const writer = writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));
writer.releaseLock();

// 受信
const reader = transport.datagrams.readable.getReader();
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  console.log('受信:', value);
}
```

1つのデータグラムで送れる大きさは`transport.datagrams.maxDatagramSize`で分かります。値はブラウザによって大きく違い、Chromeは1211、Firefoxは1024、Safariは65535を返します。

### 単方向ストリーム

ストリームはデータグラムと違い、順序が保証され、欠損した場合は再送されます。
クライアントから一方向にデータを送るだけでよい場合は単方向ストリームが便利です（Unidirectionalは単方向という意味）。

```ts
const stream = await transport.createUnidirectionalStream();
const writer = stream.getWriter();
await writer.write(new Uint8Array([10, 20, 30]));
await writer.close();
```

サーバー側から送られてくる単方向ストリームは`transport.incomingUnidirectionalStreams`から受け取れます。

```ts
const reader = transport.incomingUnidirectionalStreams.getReader();
while (true) {
  const { value: stream, done } = await reader.read();
  if (done) break;
  // stream は ReadableStream
  const streamReader = stream.getReader();
  // ...読み込み処理
}
```

### 双方向ストリーム

リクエスト・レスポンスのように、両方向にデータをやり取りしたいときは双方向ストリームを使います（Bidirectionalは双方向という意味）。
1つの`WebTransportBidirectionalStream`が`readable`と`writable`の両方を持っています。

送信と受信は独立しているので、次のように並行して動かせます。送信の完了を待たずに受信ループを回せるので、サーバーから届くデータをリアルタイムに処理できます。

```ts
// [!og]
const stream = await transport.createBidirectionalStream();

// 受信ループを先に起動しておく
const receiveTask = (async () => {
  const reader = stream.readable.getReader();
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log('受信:', value);
  }
})();

// 受信ループの裏で送信する
const writer = stream.writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));
await writer.close();

await receiveTask;
```

複数のストリームを並行して開けるので、たとえばファイル転送と制御メッセージを別々のストリームで流す、といった設計が自然に書けます。

## おわりに

WebTransportを簡単に紹介しました。

HTTP/3の特徴をそのままWebに持ち込んだAPIで、複数ストリームの並行処理やデータグラムによる軽量な送信、ネットワーク切り替え時にも維持しやすい接続といった、WebSocketでは難しかった通信が実現できます。
とはいえWebSocketの手軽さや成熟したエコシステムには今も大きな魅力があるので、用途に応じて使い分けるのが現実的です。

Baseline 2026で主要ブラウザすべてで使えるようになったので、ピッタリな状況があればぜひ使ってみてください。
