# WebTransportでQUIC（HTTP/3）の双方向通信をする

<BrowserSupportStatus featureId="webtransport" />

## はじめに

WebTransportは、QUIC（HTTP/3）の上で、ブラウザとサーバーがデータを双方向にやり取りするAPIです。1本の接続に独立したストリームをいくつも開け、届かなくても再送しないデータグラムも送れます。Safari 26.4が対応して、Baseline 2026に入りました。

チャットや通知のような少量のテキストのやり取りには、サーバーのライブラリやホスティングがそろったWebSocketを使います。WebSocketはTCPの上で1本のメッセージ列しか持てないので、一部のデータが遅れると後のデータまで待たされます。遅れたデータを待たずにほかの流れを進めたい通信や、ゲームの座標のように古い値を捨ててよい通信は、WebTransportで書けます。

## 使い方

WebTransportは、HTTPSで配ったページのようなSecure Contextでだけ使え、Web Workerからも使えます。渡すURLは`https`で始めます。`http`のURLや、`#chat`のようなフラグメントの付いたURLを渡すと、コンストラクタが`SyntaxError`を投げます。ポート番号を省くと、`https`の既定の443番につなぎます。

### コネクションを開く

`WebTransport`のコンストラクタにURLを渡し、`ready`の`Promise`が解決すると、接続ができます。

```ts
const transport = new WebTransport('https://example.com:4433/chat');

await transport.ready;
console.log('接続完了');

// 切断時の処理
transport.closed
  .then(() => console.log('正常に切断されました'))
  .catch((err) => console.error('切断時にエラー', err));
```

切断したいときは`transport.close()`を呼びます。

手元のサーバーに開発用の自己署名の証明書でつなぐときは、`serverCertificateHashes`に証明書のSHA-256のハッシュを渡します。渡さないと、`ready`が`WebTransportError`で拒否されます。

```ts
const transport = new WebTransport('https://localhost:4433/chat', {
  serverCertificateHashes: [{ algorithm: 'sha-256', value: certHash }],
});
```

`certHash`は、`openssl x509 -in cert.pem -outform der | openssl dgst -sha256 -binary`で出る32バイトを`Uint8Array`にしたものです。仕様では、ハッシュで許す証明書はECDSAの鍵で、有効期間が2週間以内のものに限られます。

### データグラムの送受信

データグラムは、順序も再送も無い、もっとも軽い送受信の方法です。届かなくても次の値で上書きすればよい、入力中の表示やキャラクターの座標のようなデータで使います。

データグラムは`transport.datagrams`の`readable`で受け取り、`createWritable()`で作った書き込み用のストリームで送ります。どちらも標準のStreams APIなので、`getReader()`や`getWriter()`でそのまま扱えます。

ただし、Chromeは`createWritable()`を持たず、`writable`だけを持ちます。Safariは逆に`writable`を持たないので、`transport.datagrams.writable.getWriter()`と書くと`TypeError`になります。Firefoxは両方を持ちます。そこで、`createWritable()`が無いときだけ`writable`を使います。

```js
// 送信
const writable =
  transport.datagrams.createWritable?.() ?? transport.datagrams.writable;
const writer = writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));
writer.releaseLock();

// 受信
const reader = transport.datagrams.readable.getReader();
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  console.log('受信:', value);
}
```

1つのデータグラムで送れる大きさは、`transport.datagrams.maxDatagramSize`で分かります。値はブラウザによって大きく違い、Chromeは1211、Firefoxは1024、Safariは65535を返します。

### 単方向ストリーム

ストリームはデータグラムと違い、順序が保たれ、欠けたデータは再送されます。一方向に送るだけでよいときは、単方向（Unidirectional）のストリームを使います。

```ts
const stream = await transport.createUnidirectionalStream();
const writer = stream.getWriter();
await writer.write(new Uint8Array([10, 20, 30]));
await writer.close();
```

サーバーから開かれた単方向のストリームは、`transport.incomingUnidirectionalStreams`から受け取ります。

```ts
const reader = transport.incomingUnidirectionalStreams.getReader();
while (true) {
  const { value: stream, done } = await reader.read();
  if (done) break;
  // stream は ReadableStream
  const streamReader = stream.getReader();
  // ...読み込み処理
}
```

### 双方向ストリーム

リクエストとレスポンスのように両方向にやり取りするときは、双方向（Bidirectional）のストリームを使います。1つの`WebTransportBidirectionalStream`が、`readable`と`writable`の両方を持ちます。

送信と受信は独立しているので、送信の完了を待たずに受信のループを回せます。

```ts
// [!og]
const stream = await transport.createBidirectionalStream();

// 受信ループを先に起動しておく
const receiveTask = (async () => {
  const reader = stream.readable.getReader();
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log('受信:', value);
  }
})();

// 受信ループの裏で送信する
const writer = stream.writable.getWriter();
await writer.write(new Uint8Array([1, 2, 3]));
await writer.close();

await receiveTask;
```

ストリームはいくつも並行して開けるので、ファイルの転送と制御のメッセージを別々のストリームで流すような設計も書けます。

## おわりに

WebTransportを使うと、1本の接続に独立したストリームをいくつも開き、再送しないデータグラムも送れます。少量のテキストのやり取りにはWebSocketを使い、遅れを待たせたくない通信や、古い値を捨ててよい通信のときにWebTransportを選びます。
