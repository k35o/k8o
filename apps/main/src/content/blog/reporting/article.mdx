# Reporting APIでCSP違反などのレポートをサーバーに集める

<BrowserSupportStatus featureId="reporting" />

## はじめに

Reporting APIは、CSP違反のようにブラウザが検知した問題を、レポートとしてサーバーに送らせたり、JavaScriptで受け取ったりする仕組みです。レポートの種類は仕様ごとに決まっていて、Baselineに入っているのはCSPの違反（`csp-violation`）のレポートです。

JavaScriptの例外なら、`window.onerror`で拾って`fetch`で送れば足ります。CSPの違反は、ブラウザが検知してもページの例外にならないので、Reporting APIで受け取ります。ユーザーのブラウザで起きた、開発環境では気づきにくい問題を集められます。

レポートの収集には2つのアプローチがあります。

- `Reporting-Endpoints`ヘッダー: レポートをサーバーのエンドポイントに自動送信する
- `ReportingObserver`: JavaScriptでレポートをクライアントサイドで検知する

次のコードは、両方を使う例です。ページは別のオリジンの画像を読もうとし、CSPの`img-src 'self'`に違反します。

```js title="server.mjs"
import { createServer } from 'node:http';

const page = `<script>
  new ReportingObserver((reports) => {
    for (const report of reports) console.log(report.type, report.body.blockedURL);
  }).observe();
</script>
<img src="https://example.com/a.png">`;

createServer((req, res) => {
  if (req.method === 'POST') {
    let body = '';
    req.on('data', (chunk) => (body += chunk));
    req.on('end', () => {
      console.log(req.headers['content-type'], body);
      res.writeHead(204).end();
    });
    return;
  }
  res.writeHead(200, {
    'Content-Type': 'text/html; charset=utf-8',
    'Reporting-Endpoints': 'default="http://localhost:3000/reports"',
    'Content-Security-Policy': "img-src 'self'; report-to default",
  });
  res.end(page);
}).listen(3000);
```

`http://localhost:3000`を開くと、DevToolsのコンソールに`ReportingObserver`が受け取った`csp-violation https://example.com/a.png`が出ます。Chrome 156、Safari 27.2、Firefox 159のどれでも出ました（Safari 27.2のURLは`https://example.com:443/a.png`）。Firefox 159とSafari 27.2では、数秒のうちにターミナルにも同じ違反のレポートが出ました。

## Reporting-Endpointsヘッダー

`Reporting-Endpoints`はレスポンスヘッダーで、レポートの送り先のエンドポイントに名前を付けて定義します。カンマで区切れば、複数の名前を定義できます。

```http
Reporting-Endpoints: default="https://example.com/reports"
```

エンドポイントのURLはHTTPSにします。HTTPのエンドポイントは無視されますが、手元で試すときの`http://localhost`には届きます。

### エンドポイントの指定方法

CSPの`report-to`ディレクティブに、`Reporting-Endpoints`で付けた名前を書きます。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy: default-src 'self'; report-to csp-endpoint
```

この設定では、CSPの違反のレポートが`csp-endpoint`のURLに届きます。

### レポートの送信形式

ブラウザはレポートをJSON形式でエンドポイントにPOSTします。`Content-Type`は`application/reports+json`で、bodyはレポートの配列です。

```json
[
  {
    "type": "csp-violation",
    "age": 53531,
    "url": "https://example.com/page",
    "user_agent": "Mozilla/5.0 ...",
    "body": {
      "blockedURL": "https://evil.com/script.js",
      "columnNumber": 39,
      "disposition": "enforce",
      "documentURL": "https://example.com/page",
      "effectiveDirective": "script-src-elem",
      "lineNumber": 121,
      "originalPolicy": "default-src 'self'; report-to csp-endpoint",
      "referrer": "https://www.google.com/",
      "sample": "",
      "sourceFile": "https://example.com/app.js",
      "statusCode": 200
    }
  }
]
```

`age`フィールドはレポート生成からの経過ミリ秒数です。絶対時刻を含めるとブラウザの内部時計のズレからユーザーを特定するフィンガープリントに悪用される恐れがあるため、相対時間が使われています。

上の`server.mjs`で試すと、Firefox 159はこの形の配列を送りました。Safari 27.2は`Content-Type`が`application/csp-report`で、`type`・`url`・`body`だけを持つオブジェクトを1件ずつ送り、`age`と`user_agent`はありませんでした。受け取るサーバーは両方の形を扱えるようにしておきます。

いつ送るかはブラウザに委ねられていて、配信は保証されません。Firefox 159は数秒のうちに複数のレポートを1つの配列にまとめて送り、Safari 27.2は違反のたびにすぐ送りました。

### Report-Onlyモード

セキュリティヘッダーには、ポリシーを強制せずにレポートのみ収集するReport-Onlyモードがあります。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy-Report-Only: default-src 'self'; report-to csp-endpoint
```

Report-Onlyモードで送信されるレポートの`disposition`フィールドは`"report"`になります（通常のモードは`"enforce"`になります）。

新しいポリシーを導入する際は、まずReport-Onlyモードで違反箇所を可視化してから強制モードに切り替えると安全です。

## ReportingObserver

`ReportingObserver`はJavaScript上でレポートを検知するAPIです。サーバーへの送信が不要な場合や、クライアントサイドでレポートに基づいた処理を行いたい場合に便利です。

```js
// [!og]
const observer = new ReportingObserver((reports) => {
  for (const report of reports) {
    console.log(report.type); // "csp-violation"
    console.log(report.url); // "https://example.com/page"
    console.log(report.body); // レポートの詳細
  }
});

observer.observe();
```

`ReportingObserver`がCSPの違反を受け取るかは、ブラウザで違いました。`report-to`を書いたCSPの違反は、Chrome 156、Safari 27.2、Firefox 159のどれでも届きました。`report-to`の無いCSP（`<meta>`で書いたものを含む）の違反は、Chrome 156にだけ届きました。ページ内で受け取るだけのときも、ヘッダーのCSPに`report-to`を書いておきます。

### コンストラクタ

`ReportingObserver`のコンストラクタは第1引数にコールバック関数、第2引数にオプションを受け取ります。

```js
new ReportingObserver(callback, options);
```

コールバック関数にはレポートの配列と`ReportingObserver`インスタンス自身が渡されます。

オプションには`types`と`buffered`を指定できます。

```js
const observer = new ReportingObserver(
  (reports, observer) => {
    // レポートの処理
  },
  {
    // 収集するレポートの種類を絞り込む
    types: ['csp-violation'],
    // observe()呼び出し前に生成されたレポートも含める
    buffered: true,
  },
);
```

`types`を指定しない場合は、すべての種類のレポートが収集されます。`buffered`を`true`にすると、`observe()`の呼び出し前にバッファされたレポートも取得でき、ページ読み込み時に発生したレポートを後から確認できます。

### メソッド

`ReportingObserver`には3つのメソッドがあります。

`observe()`でレポートの収集を開始します。

```js
observer.observe();
```

`takeRecords()`で収集済みのレポートを配列として取得し、キューを空にします。

```js
const records = observer.takeRecords();
```

`disconnect()`でレポートの収集を停止します。

```js
observer.disconnect();
```

### Reportオブジェクト

コールバックに渡されるレポートは以下のプロパティを持ちます。

- `type`: レポートの種類（`"csp-violation"`など）
- `url`: レポートが生成されたドキュメントのURL
- `body`: レポートの種類に応じた詳細情報（`ReportBody | null`）

`body`の内容はレポートの種類によって異なります。

CSP違反レポート（`type: "csp-violation"`）の場合は以下のプロパティを持ちます。

```js
report.body.blockedURL; // ブロックされたリソースのURL
report.body.disposition; // "enforce" または "report"
report.body.documentURL; // ドキュメントのURL
report.body.effectiveDirective; // 違反を検出したディレクティブ
report.body.originalPolicy; // 元のCSPポリシー文字列
report.body.referrer; // リファラー（不明な場合はnull）
report.body.sample; // 違反コードの先頭40文字
report.body.sourceFile; // スクリプトファイルのURL（不明な場合はnull）
report.body.lineNumber; // 行番号
report.body.columnNumber; // 列番号
report.body.statusCode; // HTTPステータスコード
```

## おわりに

Reporting APIは、ブラウザが検知する問題を体系的に収集する仕組みを提供します。`Reporting-Endpoints`ヘッダーによるサーバーへの自動送信と`ReportingObserver`によるクライアントサイドでの検知を組み合わせることで、CSP違反のような問題を可視化できます。

まずはReport-Onlyモードで既存のセキュリティポリシーの違反状況を把握するところから始めてみましょう。
