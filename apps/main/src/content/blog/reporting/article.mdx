# Reporting APIでCSP違反などのレポートをサーバーに集める

<BrowserSupportStatus featureId="reporting" />

## はじめに

Reporting APIは、CSP違反のようにブラウザが検知した問題を、レポートとしてサーバーに送らせたり、JavaScriptで受け取ったりする仕組みです。Firefox 149が対応して、Baseline 2026に入りました。レポートの種類は仕様ごとに決まっていて、Baselineに入っているのはCSPの違反（`csp-violation`）のレポートです。

JavaScriptの例外は、`window.onerror`で拾って`fetch`で送れます。CSPの違反は、ブラウザが検知してもページの例外にならないので、Reporting APIで受け取ります。ユーザーのブラウザで起きた、開発環境では気づきにくい問題を集められます。

レポートを受け取る方法は2つあります。

- `Reporting-Endpoints`ヘッダー：サーバーのエンドポイントに、ブラウザが自動で送る
- `ReportingObserver`：ページのJavaScriptで受け取る

次のコードは、両方を使う例です。ページは別のオリジンの画像を読もうとし、CSPの`img-src 'self'`に違反します。

```js title="server.mjs"
import { createServer } from 'node:http';

const page = `<script>
  new ReportingObserver((reports) => {
    for (const report of reports) console.log(report.type, report.body.blockedURL);
  }).observe();
</script>
<img src="https://example.com/a.png">`;

createServer((req, res) => {
  if (req.method === 'POST') {
    let body = '';
    req.on('data', (chunk) => (body += chunk));
    req.on('end', () => {
      console.log(req.headers['content-type'], body);
      res.writeHead(204).end();
    });
    return;
  }
  res.writeHead(200, {
    'Content-Type': 'text/html; charset=utf-8',
    'Reporting-Endpoints': 'default="http://localhost:3000/reports"',
    'Content-Security-Policy': "img-src 'self'; report-to default",
  });
  res.end(page);
}).listen(3000);
```

`http://localhost:3000`を開くと、DevToolsのコンソールに`ReportingObserver`が受け取った`csp-violation https://example.com/a.png`が出ます（SafariのURLは`https://example.com:443/a.png`）。FirefoxとSafariでは、数秒のうちにターミナルにも同じ違反のレポートが出ます。

## Reporting-Endpointsヘッダー

`Reporting-Endpoints`はレスポンスヘッダーで、レポートの送り先のエンドポイントに名前を付けて定義します。カンマで区切れば、複数の名前を定義できます。

```http
Reporting-Endpoints: default="https://example.com/reports"
```

エンドポイントのURLはHTTPSにします。HTTPのエンドポイントは無視されますが、手元で試すときの`http://localhost`には届きます。

### エンドポイントの指定方法

CSPの`report-to`ディレクティブに、`Reporting-Endpoints`で付けた名前を書きます。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy: default-src 'self'; report-to csp-endpoint
```

この設定では、CSPの違反のレポートが`csp-endpoint`のURLに届きます。

### レポートの送信形式

ブラウザはレポートをJSONでエンドポイントにPOSTします。`Content-Type`は`application/reports+json`で、bodyはレポートの配列です。

```json
[
  {
    "type": "csp-violation",
    "age": 53531,
    "url": "https://example.com/page",
    "user_agent": "Mozilla/5.0 ...",
    "body": {
      "blockedURL": "https://evil.com/script.js",
      "columnNumber": 39,
      "disposition": "enforce",
      "documentURL": "https://example.com/page",
      "effectiveDirective": "script-src-elem",
      "lineNumber": 121,
      "originalPolicy": "default-src 'self'; report-to csp-endpoint",
      "referrer": "https://www.google.com/",
      "sample": "",
      "sourceFile": "https://example.com/app.js",
      "statusCode": 200
    }
  }
]
```

`age`は、レポートを作ってからの経過ミリ秒です。絶対時刻を入れると、ブラウザの時計のずれからユーザーを見分けるフィンガープリントに使われる恐れがあるので、相対的な時間になっています。

上の`server.mjs`で試すと、Firefoxはこの形の配列を送ります。Safariは`Content-Type`が`application/csp-report`で、`type`と`url`、`body`だけを持つオブジェクトを1件ずつ送り、`age`と`user_agent`はありません。受け取るサーバーは、両方の形を扱えるようにしておきます。

いつ送るかはブラウザに任されていて、届くことも保証されません。Firefoxは数秒のうちに複数のレポートを1つの配列にまとめて送り、Safariは違反のたびにすぐ送ります。

### Report-Onlyモード

`Content-Security-Policy-Report-Only`ヘッダーを使うと、ポリシーを強制せずにレポートだけを集められます。

```http
Reporting-Endpoints: csp-endpoint="https://example.com/csp-reports"
Content-Security-Policy-Report-Only: default-src 'self'; report-to csp-endpoint
```

Report-Onlyで送られるレポートの`disposition`は`"report"`になり、強制しているときの`"enforce"`と見分けられます。新しいポリシーを入れるときは、まずReport-Onlyで違反を洗い出してから強制に切り替えます。

## ReportingObserver

`ReportingObserver`は、ページのJavaScriptでレポートを受け取るAPIです。サーバーに送らなくてよいときや、レポートに応じてページで何かしたいときに使います。

```js
// [!og]
const observer = new ReportingObserver((reports) => {
  for (const report of reports) {
    console.log(report.type); // "csp-violation"
    console.log(report.url); // "https://example.com/page"
    console.log(report.body); // レポートの詳細
  }
});

observer.observe();
```

`ReportingObserver`がCSPの違反を受け取るかは、ブラウザで違います。`report-to`を書いたCSPの違反は、どのブラウザでも届きます。`report-to`の無いCSP（`<meta>`で書いたものを含む）の違反は、Chromeにだけ届きます。ページの中で受け取るだけのときも、ヘッダーのCSPに`report-to`を書いておきます。

### コンストラクタ

`ReportingObserver`のコンストラクタは、第1引数にコールバック関数、第2引数にオプションを受け取ります。コールバック関数には、レポートの配列と`ReportingObserver`自身が渡されます。

```js
const observer = new ReportingObserver(
  (reports, observer) => {
    // レポートの処理
  },
  {
    // 受け取るレポートの種類を絞り込む
    types: ['csp-violation'],
    // observe()を呼ぶ前にできたレポートも受け取る
    buffered: true,
  },
);
```

`types`を指定しないと、すべての種類のレポートを受け取ります。`buffered`を`true`にすると、`observe()`を呼ぶ前にたまっていたレポートも受け取れるので、ページを読み込んだときに起きた違反も後から確かめられます。

### メソッド

`ReportingObserver`には3つのメソッドがあります。

```js
observer.observe(); // 受け取りを始める
const records = observer.takeRecords(); // たまっているレポートを配列で取り出し、キューを空にする
observer.disconnect(); // 受け取りをやめる
```

### Reportオブジェクト

コールバックに渡されるレポートは、次のプロパティを持ちます。

- `type`：レポートの種類（`"csp-violation"`など）
- `url`：レポートが作られたドキュメントのURL
- `body`：レポートの種類ごとの詳細（`ReportBody | null`）

CSPの違反のレポート（`type: "csp-violation"`）の`body`は、次のプロパティを持ちます。

```js
report.body.blockedURL; // ブロックされたリソースのURL
report.body.disposition; // "enforce" または "report"
report.body.documentURL; // ドキュメントのURL
report.body.effectiveDirective; // 違反を検出したディレクティブ
report.body.originalPolicy; // 元のCSPポリシー文字列
report.body.referrer; // リファラー（不明な場合はnull）
report.body.sample; // 違反コードの先頭40文字
report.body.sourceFile; // スクリプトファイルのURL（不明な場合はnull）
report.body.lineNumber; // 行番号
report.body.columnNumber; // 列番号
report.body.statusCode; // HTTPステータスコード
```

## おわりに

`Reporting-Endpoints`ヘッダーとCSPの`report-to`を書けば、ユーザーのブラウザで起きたCSPの違反をサーバーに集められます。ページの中で受け取るときは`ReportingObserver`を使い、ヘッダーのCSPにも`report-to`を書いておきます。
