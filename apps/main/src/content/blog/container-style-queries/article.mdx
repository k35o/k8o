# Container style queriesでCSS変数で条件分岐

<BrowserSupportStatus featureId="container-style-queries" />

## はじめに

Container style queriesは、`@container style(--theme: dark)`のように、祖先要素のカスタムプロパティ（CSS変数）の値を条件にして、子孫のスタイルを切り替えるCSSの仕組みです。サイズクエリの`@container (width > 600px)`と同じ`@container`ルールで、幅の代わりにカスタムプロパティの値を見ます。

親のクラスで子のスタイルを変えるときは、`.theme-dark .card`のような子孫セレクタを使います。ただ、セレクタはカスタムプロパティの値を見られないので、`style`属性で書いた値や親から継承した値を条件にできません。Container style queriesを使うと、親はカスタムプロパティを置くだけで、子のCSSがその値を読んでスタイルを決められます。Firefox 151が対応して、Baseline 2026に入りました。

## 基本構文

`@container`の`style(...)`に、カスタムプロパティと値を書きます。どの祖先の値を見るかは、`container-name`で祖先に名前を付けて決めます。

```css
.theme {
  /* [!hl] */
  /* [!callout: スタイルクエリで見る祖先に名前を付ける] */
  container-name: theme;
  --theme: dark;
}

/* [!hl] */
/* [!callout: theme と名前を付けた祖先の --theme が dark のときだけ当たる] */
@container theme style(--theme: dark) {
  .card {
    background: black;
    color: white;
  }
}
```

```html
<div class="theme">
  <p class="card">カード</p>
</div>
```

`.theme`の中の`.card`は、背景が黒、文字が白になります。`.theme`の`--theme`を`light`に書き換えると、元の色に戻ります。

サイズクエリと違って、`container-type`の指定は要りません。スタイルクエリでは、どの要素もクエリで見る対象になれるからです。

ただし、クエリが見るのは祖先だけです。`.card`自身に`--theme: dark`を書いて`@container style(--theme: dark)`で`.card`を指定しても、スタイルは当たりません。値は、スタイルを当てたい要素の祖先に置きます。`style(color: black)`のように、カスタムプロパティではないふつうのプロパティを書いた条件も、どのブラウザでもマッチしません。

`@container theme { ... }`のように`style()`を書かない形は、名前だけで祖先を探す別の機能で、カスタムプロパティの値は見ません。この形は[@containerの名前だけで親要素に応じてスタイルを変える](/blog/container-name-queries)で書いています。

## 親の値でボタンの大きさを変える

`.surface`に置いた`--size`の値に応じて、子孫の`.button`のパディングを切り替える例です。

```css
/* [!og] */
.surface {
  container-name: surface;
  --size: md;
}

@container surface style(--size: md) {
  .button {
    padding: 8px 16px;
  }
}

@container surface style(--size: sm) {
  .button {
    padding: 4px 8px;
  }
}
```

ボタンに大きさ用のクラスを足さなくても、親の`--size`を切り替えるだけで、中のボタンがまとめて変わります。

値は、前後の空白を除いた文字列として比べられます。`--size:md`と空白なしで書いても`style(--size: md)`にマッチしますが、`--gap: 16px`は`style(--gap: 1rem)`にマッチしません。`@property`で`syntax: '<length>'`を登録したカスタムプロパティなら、長さとして比べられ、`16px`が`1rem`にマッチします。

## 名前で見る祖先を決める

カスタムプロパティは継承されるので、深い子孫にも上の祖先の値が届きます。途中の要素が同じカスタムプロパティを上書きしていても、`container-name`で見る祖先を決めておけば、その上書きに左右されません。

```css
.theme {
  container-name: theme;
}

@container theme style(--theme: dark) {
  .card {
    background: black;
    color: white;
  }
}
```

```html
<section class="theme" style="--theme: dark">
  <article style="--theme: light">
    <p class="card">深い場所のカード</p>
  </article>
</section>
```

`@container theme`は`container-name: theme`の付いた祖先を見るので、`article`が`--theme: light`に上書きしていても、`section`の`dark`で判定されます。`.card`にはdark側のスタイルが当たります。

`container-name`を付けずに`@container style(--theme: dark)`と書くと、スタイルを当てる要素の親を見ます。どの要素もクエリで見る対象になれるので、いちばん近い祖先である親が選ばれるからです。上の例では`article`の`--theme: light`が見えて、`.card`にはdark側が当たりません。テーマのように上から渡す値は、名前を付けて見る祖先を決めておくと、途中の上書きに左右されません。

## おわりに

Container style queriesを使うと、祖先に置いたカスタムプロパティの値を条件にして、子孫のスタイルを切り替えられます。どの祖先の値を見るかは`container-name`で決め、値はスタイルを当てる要素の祖先に置きます。
