# Container style queriesでCSS変数で条件分岐

<BrowserSupportStatus featureId="container-style-queries" />

## はじめに

Container style queriesは、`@container style(--theme: dark)`のように、祖先要素のカスタムプロパティ（CSS変数）の値を条件にして、子孫のスタイルを切り替えるCSSの仕組みです。サイズクエリの`@container (width > 600px)`と同じ`@container`ルールで、幅の代わりにカスタムプロパティの値を見ます。

親のクラスで子のスタイルを変えるだけなら、`.theme-dark .card`のような子孫セレクタで足ります。一方で、セレクタではカスタムプロパティの値を見られないので、`style`属性で書いた値や親から継承した値を条件にはできませんでした。Baseline 2026で揃ったContainer style queriesを使うと、親はカスタムプロパティを立てるだけで、子のCSSがそれを読んでスタイルを決める形に書けます。

## 基本構文

スタイルクエリは、まず`container-name`で祖先にスタイルクエリの対象として名前を付け、その親の上で評価したいカスタムプロパティを`@container style(...)`の中に書きます。

```html
<div class="theme">
  <p class="card">カード</p>
</div>
```

```css
.theme {
  /* [!hl] */
  /* [!callout: スタイルクエリの対象にする親に名前を付ける] */
  container-name: theme;
  --theme: dark;
}

/* [!hl] */
/* [!callout: theme と名前を付けた祖先の --theme が dark のときだけ当たる] */
@container theme style(--theme: dark) {
  .card {
    background: black;
    color: white;
  }
}
```

`.theme`の中の`.card`は、背景が黒、文字が白になります。`.theme`の`--theme`を`light`に書き換えると、元の色に戻ります。

`container-type`を指定する必要はありません。`container-type: size`や`inline-size`はサイズクエリ専用で、スタイルクエリは指定なしでもデフォルトで全要素が暗黙のスタイルクエリコンテナとして扱われます。サイズクエリのようなcontainmentの指定は不要です。

ただし、クエリが見るのは祖先だけです。Chrome 156、Safari 27.2、Firefox 159のどれでも、`.card`自身に`--theme: dark`を書いて`@container style(--theme: dark)`で`.card`を指定しても、スタイルは当たりませんでした。値は、スタイルを当てたい要素の祖先に置きます。`style(color: black)`のようにカスタムプロパティではないプロパティを書いた条件も、3つのブラウザのどれでもマッチしませんでした。

なお、`@container theme { ... }`のように条件を省略する書き方は、Chrome 148で追加されたname-only container queriesという別機能で、カスタムプロパティの値は見ません。スタイルクエリとして条件分岐したい場合は`style()`の中に条件を書きます。

## サイズクエリとの違い

`@container (width > 600px)`のようなサイズクエリは、コンテナの寸法を条件にしてレイアウトを変えるのが目的です。スタイルクエリの目的はそれとは別で、親に立っている値（テーマやサイズスケールなど）に追従して子のスタイルを変えることにあります。

条件として見るものも違います。サイズクエリはコンテナの幅や高さを見るので、親側に`container-type: inline-size`などのcontainment指定が必要です。スタイルクエリはコンテナのカスタムプロパティを見るだけなので、追加の`container-type`は必要ありません。

## カスタムプロパティを使う

`.surface`に立てた`--size`の値に応じて、子孫の`.button`のパディングを切り替える例です。

```css
/* [!og] */
.surface {
  container-name: surface;
  --size: md;
}

@container surface style(--size: md) {
  .button {
    padding: 8px 16px;
  }
}

@container surface style(--size: sm) {
  .button {
    padding: 4px 8px;
  }
}
```

子コンポーネントに`size`用のクラスを増やさずに、親側で`--size`を切り替えるだけでまとめて反映されます。

値は、前後の空白を除いた文字列として比べられます。3つのブラウザのどれでも、`--size:md`と空白なしで書いても`style(--size: md)`にマッチしましたが、`--gap: 16px`は`style(--gap: 1rem)`にマッチしませんでした。`@property`で`syntax: '<length>'`を登録したカスタムプロパティなら、長さとして比べられ、`16px`が`1rem`にマッチしました。

## 階層を超えて効かせる

カスタムプロパティはCSSの継承に乗るので、`container-name`で祖先を固定しておけば、深い子孫からでも一番上の祖先を見に行けます。途中の要素が同じカスタムプロパティを上書きしていても、`container-name`で対象を固定しておけば影響を受けません。

```html
<section class="theme" style="--theme: dark">
  <article style="--theme: light">
    <p class="card">深い場所のカード</p>
  </article>
</section>
```

```css
.theme {
  container-name: theme;
}

@container theme style(--theme: dark) {
  .card {
    background: black;
    color: white;
  }
}
```

`@container theme`はクエリの対象を`container-name: theme`が付いている祖先に固定しているので、`article`が`--theme: light`に上書きしていても、`section`の`dark`で判定されて`.card`にはdark側のスタイルが当たります。

`container-name`を付けずに`@container style(--theme: dark)`と書くと、対象はもっとも近い祖先のスタイルクエリコンテナになります。CSS Conditional Rules Module Level 5は、スタイルクエリではどの要素もクエリコンテナになると定めているので、もっとも近い祖先のスタイルクエリコンテナは実質的にスタイルを当てる要素の親要素です。上の例だと`article`の`--theme: light`が見えて`.card`にはdark側が当たりません。Chrome 156、Safari 27.2、Firefox 159のどれでも、名前付きのクエリではdark側が当たり、名前を付けないクエリでは当たりませんでした。テーマやモードのような上から降ってくる文脈は、名前付きで明示しておくのが安全です。

## おわりに

Container style queriesは、テーマやサイズスケールといった親の文脈に追従する子のスタイルを素直にCSSだけで書く道具です。Baseline 2026で主要ブラウザに揃ったので、子コンポーネントに対してテーマ用のクラスや属性を配って回る処理を減らし、子側のCSSが親の値を読みに行く形に書き直していけます。
