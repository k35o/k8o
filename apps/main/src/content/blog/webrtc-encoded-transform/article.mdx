# WebRTC Encoded TransformでE2EEを実装する

<BrowserSupportStatus featureId="webrtc-encoded-transform" />

## はじめに

WebRTC Encoded Transformは、WebRTCで送受信する映像や音声を、エンコードした後・デコードする前のフレームの段階でWorkerに渡し、データを書き換えられるようにする機能です。送信側で暗号化して受信側で復号すれば、通信を中継するサーバーにも中身が読めないE2EE（End-to-End Encryption）を実装できます。Chrome 141が対応して、Baseline 2025に入りました。

1対1でつなぐだけなら、WebRTCが通信をDTLS-SRTPで暗号化するので、これまでの書き方で足ります。SFUのようなメディアサーバーを経由する通信では、サーバーで一度復号されます。サーバーにも読めないように暗号化したいときに、Encoded Transformが要ります。

同じページで2つの`RTCPeerConnection`をつなぐと、外のサーバーなしで試せます。

```html title="index.html"
<!doctype html>
<canvas width="320" height="240"></canvas>
<video autoplay muted playsinline></video>
<script type="module">
  // 色が変わり続けるcanvasを送る映像にする
  const canvas = document.querySelector('canvas');
  const ctx = canvas.getContext('2d');
  let n = 0;
  setInterval(() => {
    ctx.fillStyle = `hsl(${n++ * 5} 80% 50%)`;
    ctx.fillRect(0, 0, 320, 240);
  }, 33);
  const stream = canvas.captureStream(30);

  const pc1 = new RTCPeerConnection();
  const pc2 = new RTCPeerConnection();
  const sender = pc1.addTrack(stream.getVideoTracks()[0], stream);
  sender.transform = new RTCRtpScriptTransform(new Worker('worker.js'), {});
  pc2.ontrack = (event) => {
    document.querySelector('video').srcObject = event.streams[0];
  };

  // ICEの候補が出そろってからSDPを渡す
  const gathered = (pc) =>
    new Promise((resolve) => {
      if (pc.iceGatheringState === 'complete') return resolve();
      pc.addEventListener('icegatheringstatechange', () => {
        if (pc.iceGatheringState === 'complete') resolve();
      });
    });
  await pc1.setLocalDescription();
  await gathered(pc1);
  await pc2.setRemoteDescription(pc1.localDescription);
  await pc2.setLocalDescription();
  await gathered(pc2);
  await pc1.setRemoteDescription(pc2.localDescription);
</script>
```

```js title="worker.js"
self.addEventListener('rtctransform', (event) => {
  const { readable, writable } = event.transformer;
  readable
    .pipeThrough(
      new TransformStream({
        transform(frame, controller) {
          console.log(frame.type, frame.data.byteLength);
          controller.enqueue(frame);
        },
      }),
    )
    .pipeTo(writable);
});
```

開くと左のcanvasの色が変わり続け、右のvideoに同じ映像が映ります。コンソールには、Workerが受け取ったフレームの種類と大きさが`key 177`、`delta 111`のように流れます。

## WebRTCとは

[WebRTC（Web Real-Time Communication）](https://webrtc.org)は、ブラウザ間でリアルタイムに音声や映像など任意のデータを直接やり取りできる技術です。

実際に試してみたい方は、公式から提供されている[簡単なサンプル群](https://webrtc.github.io/samples/)や、Googleが用意する[コードラボ](https://codelabs.developers.google.com/codelabs/webrtc-web)を見るのがおすすめです。

## WebRTC Encoded Transformとは

WebRTC Encoded Transformは、WebRTC APIの一部で、エンコードされたメディアフレームを変換するために使用される機能です。
Workerスレッドで実行される変換処理をWebRTCの送信・受信パイプラインに挿入できます。

この機能は`RTCRtpScriptTransform`インターフェイスや、`RTCRtpSender`・`RTCRtpReceiver`の`transform`プロパティを利用して実装されます。

```ts
new RTCRtpScriptTransform(worker, options, transfer);
```

第1引数には変換処理を実行するWorkerオブジェクトを指定します。
第2引数には変換処理に関するオプションを、第3引数には、Workerに転送するオブジェクトの配列を指定します。
第2、第3引数は省略可能です。

`RTCRtpSender`・`RTCRtpReceiver`の`transform`プロパティは`RTCRtpScriptTransform`を設定するものです。

```ts
videoSender.transform = new RTCRtpScriptTransform(worker);
```

Workerでは、`rtctransform`イベントの`event.transformer`の`readable`からフレームを読み、`writable`に書き戻します。映像のフレームは`RTCEncodedVideoFrame`で、`data`（`ArrayBuffer`）と`type`（`key`か`delta`）を持ちます。`getMetadata()`を呼ぶと、コーデック（既定ではChromeが`video/VP8`、Safariが`video/H264`）や幅と高さが分かります。

## 使用例

例としてE2EEを実装します。上の`index.html`の`sender.transform`と`pc2.ontrack`を次のように替え、送信側で暗号化し、受信側で復号します。

```js
// [!og]
const key = await crypto.subtle.generateKey(
  { name: 'AES-GCM', length: 128 },
  false,
  ['encrypt', 'decrypt'],
);
sender.transform = new RTCRtpScriptTransform(new Worker('e2ee-worker.js'), {
  operation: 'encrypt',
  key,
});
pc2.ontrack = (event) => {
  event.receiver.transform = new RTCRtpScriptTransform(
    new Worker('e2ee-worker.js'),
    { operation: 'decrypt', key },
  );
  document.querySelector('video').srcObject = event.streams[0];
};
```

`CryptoKey`は`options`に入れてWorkerに渡せます。ここでは同じページで作った鍵を両方に渡していますが、実際には鍵交換の仕組みで相手と共有します。

Worker側（`e2ee-worker.js`）では、AES-GCMでフレームを暗号化し、初期化ベクトル（IV）を末尾に付けて送ります。受信側は末尾のIVを取り出して復号します。

```js title="e2ee-worker.js"
// 先頭のバイトは暗号化しない（VP8のキーフレームは10バイト、それ以外は3バイト）
const offsets = { key: 10, delta: 3 };

self.addEventListener('rtctransform', (event) => {
  const { readable, writable, options } = event.transformer;
  const { operation, key } = options;
  readable
    .pipeThrough(
      new TransformStream({
        async transform(frame, controller) {
          const data = new Uint8Array(frame.data);
          const n = offsets[frame.type] ?? 1;
          const head = data.subarray(0, n);
          if (operation === 'encrypt') {
            const iv = crypto.getRandomValues(new Uint8Array(12));
            const body = await crypto.subtle.encrypt(
              { name: 'AES-GCM', iv, additionalData: head },
              key,
              data.subarray(n),
            );
            frame.data = concat(head, new Uint8Array(body), iv).buffer;
          } else {
            const iv = data.subarray(data.length - 12);
            try {
              const body = await crypto.subtle.decrypt(
                { name: 'AES-GCM', iv, additionalData: head },
                key,
                data.subarray(n, data.length - 12),
              );
              frame.data = concat(head, new Uint8Array(body)).buffer;
            } catch {
              return; // 復号できないフレームは捨てる
            }
          }
          controller.enqueue(frame);
        },
      }),
    )
    .pipeTo(writable);
});

function concat(...parts) {
  const out = new Uint8Array(parts.reduce((sum, p) => sum + p.length, 0));
  let offset = 0;
  for (const p of parts) {
    out.set(p, offset);
    offset += p.length;
  }
  return out;
}
```

VP8では、フレームの先頭（キーフレームは10バイト、それ以外は3バイト）を暗号化せずに残し、受信側のブラウザがフレームの種類を見分けられるようにします。フレーム全体を暗号化すると、Chromeでは映像は映りますが、受信側ではキーフレームでない多くのフレームが`type`を`key`として届きます。

受信側に復号のTransformを置かないと、映像は映りません。違う鍵で復号すると`decrypt()`が失敗してフレームを捨てるので、やはり映りません。

Safariは既定のコーデックがH.264で、このE2EEのコードのままでは映像が映りません（フレームをそのまま通す最初の例は映ります）。Workerで暗号化せずに残す先頭のバイト数はVP8に合わせたものなので、Safariでは`addTrack()`の後でVP8を先頭に並べます。

```js
const [transceiver] = pc1.getTransceivers();
const { codecs } = RTCRtpSender.getCapabilities('video');
transceiver.setCodecPreferences([
  ...codecs.filter((c) => c.mimeType === 'video/VP8'),
  ...codecs.filter((c) => c.mimeType !== 'video/VP8'),
]);
```

こう並べると、Safariでもフレームが復号されて映ります。

```txt
// これまで
[getUserMedia] → [Encoder] → [Network] → [Decoder] → [Display]
                     ↑                        ↑
                 触れられない               触れられない
// これから
[getUserMedia] → [Encoder] → [Transform] → [Network] → [Transform] → [Decoder] → [Display]
                                  ↑                          ↑
                             E2EEを追加可能               E2EEを追加可能
```

このように、WebRTC Encoded Transformを使うと、送受信するフレームのデータを書き換えられます。扱うのはエンコード済みのデータなので、色を変えるといった映像の効果をかける用途には向きません。

## おわりに

WebRTCとWebRTC Encoded Transformについて簡単に紹介しました。

これにより、通信を中継するサーバーにも読めない形で映像や音声を送るE2EEのような処理を、WebRTCの送受信の途中に挟めます。
