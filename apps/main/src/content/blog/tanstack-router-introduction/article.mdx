# Reactの新しいルーティングライブラリ、TanStackRouterを学ぶ

## はじめに

React で開発する時、どのようにルーティングを実装していますか？[Next.js](https://nextjs.org/)や[Remix](https://remix.run/)などのフレームワークを用いて開発するときはフレームワークに実装されたルーティング利用し、フレームワークを利用しないときは[ReactRouter](https://reactrouter.com/)を利用する方法がスタンダードだと思います。
この記事では React におけるルーティング方法の新たな選択肢として[TanStack Router](https://tanstack.com/router/latest)を紹介します。名前から察する通り、これは[TanStack Query](https://tanstack.com/query/latest)(React Query)と同じ開発元の[TanStack](https://tanstack.com/)が開発したライブラリとなります。
この記事では紹介しませんが、React のほかに Solid と Vue 向けのパッケージ（`@tanstack/solid-router`・`@tanstack/vue-router`）もあります。

## 特徴

TanStack Router は後発のライブラリということもあり、React Router のようなルーティング専用のライブラリや、Next.js のようなフレームワークに実装されたルーティングからインスピレーションを受けて構成されています。React Router や Next.js のルーティング機能と比較したい場合は[こちら](https://tanstack.com/router/latest/docs/comparison)を確認してください。
そして、TanStack Router は大きく 3 つの特徴を持ちます。

### 型安全でシンプル

先述の通り ReactRouter や Next.js などの既存のルーティングを基に構築されたライブラリなので初めて使う人でも使いやすい設計になっています。また、ルートの定義からパスやパスパラメータの型が推論され、存在しないパスへのリンクは型エラーになります。

### 優秀な検索パラメータ

検索パラメータを型安全にオブジェクトを扱うように変更や取得が可能でさらにバリデーションを行えます。検索パラメータを一種の状態管理を行うストアのように扱えるのでより直感的で安全に利用することが可能です。

### クライアント側のデータ取得

TanStack Query や SWR などの stale-while-revalidate キャッシュを活かしたデータ取得ライブラリと相性が良い設計がなされています。

## 導入

パッケージをインストールするだけで TanStack Router を利用するための準備が完了します。

```sh
npm install @tanstack/react-router
```

TanStack Routerには、ファイルの配置からルートの木を生成するファイルベースのルーティング（`@tanstack/router-plugin`）もあります。この記事では、ルートをコードで組み立てる書き方で紹介します。ルートに渡す`component`・`validateSearch`・`loader`といったオプションは、どちらの書き方でも同じです。

### 開発ツール

TanStack Router には専用の開発ツールが準備されており、TanStack Router の内部で行われている振る舞いを可視化してくれます。

開発ツールは専用のパッケージをインストールして、コード内で埋め込むことで利用できます。

```sh
npm install -D @tanstack/react-router-devtools
```

`TanStackRouterDevtools`は開発中（`process.env.NODE_ENV`が`development`）にだけ描かれ、本番のビルドでは何も描かないので、そのまま埋め込めます。一般的には、ルートの木の根になる`createRootRoute`の`component`に埋め込みます。

```tsx
import { createRootRoute, Outlet } from '@tanstack/react-router';
import { TanStackRouterDevtools } from '@tanstack/react-router-devtools';

const rootRoute = createRootRoute({
  component: () => (
    <>
      <Outlet />
      <TanStackRouterDevtools />
    </>
  ),
});
```

## 使い方

### ルーティングの作成

`createRootRoute`でルーティングの入り口を作ります。

```tsx
const rootRoute = createRootRoute();
```

そして`createRoute`で各ルートの設定を行います。

```tsx
const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => <IndexContent />,
});
```

`getParentRoute`は作成するルートの親となるルートを指定します。そして、`path`には指定した親からの相対パスを渡します。`/blog/create`にルートを作るとします。
`path`に`/blog/create`を渡した時は親に`rootRoute`を、`path`が`create`であれば親に`/blog`にルートを作る`blogRoute`を指定します。`path`の先頭のスラッシュはあってもなくても同じに扱われますが、末尾のスラッシュは付けません。1.170.46で`/docs/`という`path`を持つルートの子に`/create`のルートを作ると、子の`fullPath`は`/docs/create`になるのに、`/docs/create`を開くとNot Foundになりました。
この 2 つ、`getParentRoute`と`path`が`createRoute`でルートを作るために必須のオプションです(厳密には`path`の代わりに`id`を渡してもよく、そのときはパスを持たないルートになります)。

必須のオプション以外の任意のオプションでは`component`にそのルートにアクセスしたときに表示するコンポーネントを渡せます。その他にも表示するルートでエラーが発生した時に表示する`errorComponent`や、`loader`の完了を待つ間に表示する`pendingComponent`や、検索パラメータをバリデーションする`validateSearch`など様々なものを渡せます。

使用するルートを準備できたら、改めてルーティング全体を組み上げていきます。親要素のルートに対して`addChildren`で子要素を配置するようにします。子のルートは、親のコンポーネントの`Outlet`の位置に描かれます。

```tsx
const rootRoute = createRootRoute();
// /
const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => <div>Index</div>,
});
// /blog
const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  component: () => (
    <div>
      Blog
      <Outlet />
    </div>
  ),
});
// /blog/:slug
const postRoute = createRoute({
  getParentRoute: () => blogRoute,
  path: '$slug',
  component: () => <div>Post</div>,
});
// /accounts/:id
const userRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'accounts/$id',
  // 遅延読み込みする。lazyRouteComponentはTanStack Routerが提供する関数
  component: lazyRouteComponent(() => import('./account')),
});

const routeTree = rootRoute.addChildren([
  indexRoute,
  blogRoute.addChildren([postRoute]),
  userRoute,
]);
```

`addChildren`と`getParentRoute`の両方でルーティングツリーを構成しているように見えます。重複した定義のように感じますが、これによって型安全なルーティングが構成されます。
組み上げたルーティング`routeTree`は`createRouter`に渡してルーターを作成し、[declaration merging](https://www.typescriptlang.org/docs/handbook/declaration-merging.html)でプロジェクト全体にルーティングに関する型の情報を共有します。

```ts
const router = createRouter({ routeTree });

declare module '@tanstack/react-router' {
  interface Register {
    router: typeof router;
  }
}
```

ルーターは`RouterProvider`コンポーネントに渡して React のツリーに反映します。

```tsx
const App: FC = () => {
  return <RouterProvider router={router} />;
};
```

### ページの遷移

ページの遷移はコンポーネントとして`Link`と`Navigate`、hooks としては`useNavigate`、そして`router.navigate`が提供されています。

#### Link

`Link`コンポーネントは他のライブラリと同じで、SPA で遷移する`a`タグとしてレンダリングされます。
`/blog`へ遷移するリンクを作りたい時は以下のように書きます。

```tsx
import { Link } from '@tanstack/react-router';

const BlogLink: FC = () => {
  return <Link to="/blog">Blog</Link>;
};
```

このリンクは以下のような html を出力し、クリックなどのアクションで`/blog`に SPA で遷移します。

```html
<a href="/blog">Blog</a>
```

`to`には作成したルーティングに存在するパスしか指定できません。これが TanStack Router の持つ特徴の型安全性の一つです。

`/blog/tanstack-router`のようなパスパラメータを含むルートへ遷移させたい場合は、`to`にルートのパスをそのまま書き、値を`params`で渡します。これによって`to`の型は動的リンクであっても厳密な指定を可能にしています。`params`を書き忘れると型エラーになります。

```tsx
import { Link } from '@tanstack/react-router';

const PostLink: FC = () => {
  return (
    <Link
      to="/blog/$slug"
      params={{
        slug: 'tanstack-router',
      }}
    >
      Blog
    </Link>
  );
};
```

他にも検索パラメータが必要な場合は`search`で、ハッシュリンクを渡したいときは`hash`で指定することができます。
例えば`/blog?filter=tanstack&sort=name#Search`にリンクしたい場合は以下のように書きます。

```tsx
import { Link } from '@tanstack/react-router';

const SearchLink: FC = () => {
  return (
    <Link
      to="/blog"
      search={{
        filter: 'tanstack',
        sort: 'name',
      }}
      hash="Search"
    >
      Blog
    </Link>
  );
};
```

このように書くことで遷移先のルートで登録されたバリデーションを行える点などにメリットがあります。バリデーションについては後ほど記述します。
さらに、`preload`でリンクにホバーやタッチしたタイミングから遷移先の読み込みを行うように指定できます。

```tsx
import { Link } from '@tanstack/react-router';

const PreloadLink: FC = () => {
  return (
    <Link to="/blog" preload="intent">
      Blog
    </Link>
  );
};
```

他にも`from`を起源としてリンク先を記述する相対リンクや、`Link`の状態に応じた`style`を指定できる`activeProps`などを指定することができます。

#### Navigate

`Navigate`はコンポーネントがレンダリングされたら遷移を行うようコンポーネントです。使われる場面として考えられるのは、アカウントの設定画面に遷移したときにログインしていなければログイン画面へ遷移させるようなケースです。

```tsx
const Setting: FC = () => {
  const user = useUser();

  if (!user) {
    return <Navigate to="/login" search={{ redirect: '/accounts/setting' }} />;
  }
  return <AccountSetting user={user} />;
};
```

このコンポーネントの Props として渡せる値は`Link`とほとんど同じです。

#### useNavigate

`navigate`という遷移に関する機能を持つインターフェイスを返す hooks です。ブログを作成するページで作成後にブログの詳細ページへ飛ばす挙動を作成するときなどで使われる考えています。

```tsx
const navigate = useNavigate();

const onSubmit = async (data: CreateDTO) => {
  const response = await trigger(data);

  if (response.ok) {
    navigate({ to: '/blog/$slug', params: { slug: data.slug } });
  }
};
```

`navigate`に渡す値はオブジェクト形式で、`Link`と同じような値を渡せます(`from`は`useNavigate`で渡せるなどの差異はあります)。

#### router.navigate

`router.navigate`は`createRouter`で作ったルーターが持つメソッドで、`useNavigate`が返す`navigate`と同じ能力を持ちます。hooks を用いたくないタイミングで有効的に活用できます。

```ts
const router = createRouter({ routeTree });
router.navigate({ to: '/blog/$slug', params: { slug: 'tanstack-router' } });
```

## バリデーション

TanStack Router では`createRoute`の`validateSearch`で検索パラメータのバリデーションや型情報の付与が可能です。

```ts
type BlogSearch = {
  page: number;
  filter: string;
  sort: 'name' | 'date';
};

const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: (search: Record<string, unknown>): BlogSearch => {
    return {
      page: Number(search.page ?? 1),
      filter: typeof search.filter === 'string' ? search.filter : '',
      sort: search.sort === 'date' ? 'date' : 'name',
    };
  },
});
```

Zod 4のようにStandard Schemaに対応したライブラリのスキーマは、そのまま`validateSearch`に渡せます。

```ts
// zodなどのライブラリを用いて検査する
const blogSearchSchema = z.object({
  page: z.number().default(1).catch(1),
  filter: z.string().default(''),
  sort: z.enum(['name', 'date']).default('name').catch('name'),
});

const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: blogSearchSchema,
});
```

このようにして検索パラメータに型を付与しつつ、入力値の検査を行うことができます。
`useSearch`によってコンポーネント内で検索パラメータの値を取得できますが、その値の型は`BlogSearch`（Zodの場合はスキーマの出力の型）になります。他にも、このルート内で扱う検索パラメータの値の型は全て同じ型になります。

このルートに対する遷移を考えてみます。

```tsx
<Link to="/blog" search={{ page: 1, filter: 'blog' }}>Blog</Link>

<Link to="/blog" search={{ page: false, filter: 'blog' }}>Blog</Link>
```

Zodのスキーマで検証したルートでは、上記のように定義した 2 つの`Link`のうち後者は検索パラメータの型が不一致のためエラーが発生します。`.default()`を付けたキーは`Link`で省けるので、前者は`sort`が無くてもエラーになりません。
関数で検証したルートでは、`Link`の`search`に`BlogSearch`のすべてのキーが要ります。前者も`sort`が無いのでエラーになります。

## データの取得

TanStack Router ではルーティングに沿ったデータの取り扱いが可能です。`loader`で取得したデータはルーターがキャッシュし、`useLoaderData`で読めます。TanStack Query や SWR のようなデータ取得ライブラリと組み合わせて、キャッシュをそちらに任せることもできます。この記事では TanStack Query を用いて紹介します。
ルーティングに合わせたデータ取得なのでルートごとに定義します。`createRoute`の引数`loader`でデータの取得についてのロジックを記述します。`loader`に記述した関数はルートの移動や更新、`preload`のたびに実行されます。

```tsx
const blogQueryOptions = (slug: string) =>
  queryOptions({
    queryKey: ['blog', slug],
    queryFn: () => fetchBlog(slug),
  });

const postRoute = createRoute({
  getParentRoute: () => blogRoute,
  path: '$slug',
  loader: ({ params }) =>
    queryClient.query({
      ...blogQueryOptions(params.slug),
      staleTime: 'static',
    }),
  component: function Post() {
    const { slug } = postRoute.useParams();
    const { data: blog } = useSuspenseQuery(blogQueryOptions(slug));
    return <Blog blog={blog} />;
  },
});
```

この例では`component`がレンダリングされる前にルートの移動、更新、`preload`の時点で api を呼び出してキャッシュを更新しています。これによってページの読み込み後の非同期なデータをより早く解決することが可能になります。TanStack Query 5.105では`ensureQueryData`が非推奨になり、`queryClient.query`に`staleTime: 'static'`を付けて同じことをします。

`loader`には検索パラメータが渡りません。検索パラメータによって取得するデータを変えるときは、`loaderDeps`で使う値を選び、`loader`では`deps`として受け取ります。

```tsx
const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: blogSearchSchema,
  loaderDeps: ({ search }) => ({ page: search.page }),
  loader: ({ deps }) =>
    queryClient.query({
      ...blogListQueryOptions(deps.page),
      staleTime: 'static',
    }),
});
```

`preload`を有効にするには遷移のタイミングで`preload`に`intent`を付与するか、`createRouter`の`defaultPreload`でルーター全体のデフォルト設定にする必要があります。

```tsx
<Link to="/blog" preload="intent">Blog</Link>;

const router = createRouter({
  routeTree,
  defaultPreload: 'intent',
});
```

これによって`Link`にホバーやタッチしたタイミングから先行してデータの読み込みを実行できます。

## おわりに

TanStack Router の基本的な機能を紹介しました。これまで利用してきたライブラリの使用感を保ったまま新たな機能が追加された使いやすいルーティングライブラリに感じました。特に、検索パラメータを簡単に型安全で状態のように扱える点が新鮮でそこに惹かれています。
フレームワークを利用しないアプリケーションを作るときは、TanStack Router を使ってみてはいかがでしょうか。
