# TanStack RouterでReactのルーティングを型安全に書く

## はじめに

[TanStack Router](https://tanstack.com/router/latest)は、[TanStack Query](https://tanstack.com/query/latest)（React Query）と同じ[TanStack](https://tanstack.com/)が開発するReactのルーティングライブラリです。ルートの定義からパスや検索パラメータの型が推論され、存在しないパスへのリンクや渡し忘れたパラメータを型エラーとして見つけられます。

[Next.js](https://nextjs.org/)のようなフレームワークを使うなら、そのフレームワークのルーティングで足ります。フレームワークを使わないSPAでも、パスを文字列のまま扱ってよければ[React Router](https://reactrouter.com/)で足ります。TanStack Routerが向くのは、パスと検索パラメータを型で縛り、検索パラメータをアプリの状態のように読み書きしたい場面です。

この記事のコードは、`@tanstack/react-router` 1.170.46とTypeScript 7.0.2で型を確かめ、Chrome 156で動かしています。ReactのほかにSolidとVue向けのパッケージ（`@tanstack/solid-router`・`@tanstack/vue-router`）もありますが、この記事では扱いません。

## 特徴

TanStack Routerは後発のライブラリで、React Routerのようなルーティング専用のライブラリや、Next.jsのようなフレームワークのルーティングを参考に作られています。React RouterやNext.jsのルーティングとの比較は[公式の比較表](https://tanstack.com/router/latest/docs/comparison)にまとまっています。大きな特徴は次の3つです。

### 型安全でシンプル

既存のルーティングを参考にした設計なので、初めてでも使い始めやすくなっています。ルートは親のルートと`path`を渡して1つずつ作り、木に組み上げます。組み上げたルートの木から、パスやパスパラメータの型が推論されます。

次のコードは、ページが2つあるだけの最小の例です。Viteで作ったReactとTypeScriptのプロジェクトに`@tanstack/react-router`を入れ、`src/main.tsx`をこのコードに置き換えると動きます。

```tsx title="src/main.tsx"
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import {
  createRootRoute,
  createRoute,
  createRouter,
  Link,
  Outlet,
  RouterProvider,
} from '@tanstack/react-router';

const rootRoute = createRootRoute({
  component: () => (
    <>
      <nav>
        <Link to="/">Home</Link> <Link to="/about">About</Link>
      </nav>
      <Outlet />
    </>
  ),
});

const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => <h1>Home</h1>,
});

const aboutRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'about',
  component: () => <h1>About</h1>,
});

const routeTree = rootRoute.addChildren([indexRoute, aboutRoute]);
const router = createRouter({ routeTree });

declare module '@tanstack/react-router' {
  interface Register {
    router: typeof router;
  }
}

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);
```

Aboutのリンクを押すと、ページを読み直さずにURLが`/about`に変わり、見出しがAboutに替わります。`to="/about"`を`to="/abuot"`と打ち間違えると、TypeScript 7.0.2では次の型エラーになり、正しいパスを提案されます。

```txt
Type '"/abuot"' is not assignable to type '"." | ".." | "/" | "/about"'. Did you mean '"/about"'?
```

### 優秀な検索パラメータ

検索パラメータを型の付いたオブジェクトとして読み書きでき、ルートごとに値を検証できます。URLの`?page=2`は、読むときに数値の`2`に戻ります。検索パラメータを状態を持つストアのように扱えるので、ページ番号や絞り込みの条件をURLに置きやすくなります。

### クライアント側のデータ取得

ルートごとに`loader`でデータを取得でき、リンクにホバーした時点で遷移先のデータを先に読み込めます。TanStack QueryやSWRのような、stale-while-revalidateのキャッシュを持つデータ取得ライブラリと組み合わせやすい設計です。

## 導入

パッケージをインストールすれば、TanStack Routerを使う準備は終わりです。

```sh
npm install @tanstack/react-router
```

TanStack Routerには、ファイルの配置からルートの木を生成するファイルベースのルーティング（`@tanstack/router-plugin`）もあります。この記事では、ルートをコードで組み立てる書き方で紹介します。ルートに渡す`component`・`validateSearch`・`loader`といったオプションは、どちらの書き方でも同じです。

### 開発ツール

TanStack Routerには専用の開発ツールがあり、ルーターの内部の状態を見られます。専用のパッケージを入れて、コードに埋め込んで使います。

```sh
npm install -D @tanstack/react-router-devtools
```

ふつうは、ルートの木の根になる`createRootRoute`の`component`に埋め込みます。

```tsx
import { createRootRoute, Outlet } from '@tanstack/react-router';
import { TanStackRouterDevtools } from '@tanstack/react-router-devtools';

const rootRoute = createRootRoute({
  component: () => (
    <>
      <Outlet />
      <TanStackRouterDevtools />

});
```

## 使い方

### ルーティングの作成

`createRootRoute`でルーティングの入り口を作ります。

```tsx
const rootRoute = createRootRoute();
```

そして`createRoute`で各ルートを作ります。

```tsx
const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => <IndexContent />,
});
```

`getParentRoute`には親のルートを返す関数を、`path`には親からの相対パスを渡します。`/blog/create`にルートを作るなら、`path`を`/blog/create`にして親を`rootRoute`にするか、`path`を`create`にして親を`/blog`のルートにします。

`path`の先頭のスラッシュはあってもなくても同じに扱われますが、末尾のスラッシュは付けません。1.170.46で`/docs/`という`path`を持つルートの子に`/create`のルートを作ると、子の`fullPath`は`/docs/create`になるのに、`/docs/create`を開くとNot Foundになりました。

`getParentRoute`と`path`の2つが、`createRoute`でルートを作るのに必須のオプションです。厳密には`path`の代わりに`id`を渡してもよく、そのときはパスを持たないルートになります。

ほかに、そのルートで表示するコンポーネントを`component`に渡せます。エラーが起きたときに表示する`errorComponent`、`loader`の完了を待つあいだに表示する`pendingComponent`、検索パラメータを検証する`validateSearch`なども渡せます。

ルートを用意できたら、ルーティング全体を組み上げます。親のルートの`addChildren`に子のルートを渡します。子のルートは、親のコンポーネントの`Outlet`の位置に描かれます。

```tsx
const rootRoute = createRootRoute();
// /
const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => <div>Index</div>,
});
// /blog
const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  component: () => (
    <div>
      Blog
      <Outlet />
    </div>
  ),
});
// /blog/:slug
const postRoute = createRoute({
  getParentRoute: () => blogRoute,
  path: '$slug',
  component: () => <div>Post</div>,
});
// /accounts/:id
const userRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'accounts/$id',
  // 遅延読み込みする。lazyRouteComponentはTanStack Routerが提供する関数
  component: lazyRouteComponent(() => import('./account')),
});

const routeTree = rootRoute.addChildren([
  indexRoute,
  blogRoute.addChildren([postRoute]),
  userRoute,
]);
```

`addChildren`と`getParentRoute`の両方でルーティングの木を作っているように見えます。重複した定義に感じますが、これによって型安全なルーティングになります。
組み上げた`routeTree`は`createRouter`に渡してルーターを作り、[declaration merging](https://www.typescriptlang.org/docs/handbook/declaration-merging.html)でプロジェクト全体にルーティングの型を共有します。

```ts
const router = createRouter({ routeTree });

declare module '@tanstack/react-router' {
  interface Register {
    router: typeof router;
  }
}
```

ルーターは`RouterProvider`コンポーネントに渡して、Reactのツリーに反映します。

```tsx
const App: FC = () => {
  return <RouterProvider router={router} />;
};
```

### ページの遷移

ページの遷移には、コンポーネントの`Link`と`Navigate`、フックの`useNavigate`、ルーターのメソッドの`router.navigate`があります。

#### Link

`Link`コンポーネントは他のライブラリと同じく、SPAで遷移する`a`タグとして描かれます。`/blog`へ遷移するリンクは次のように書きます。

```tsx
import { Link } from '@tanstack/react-router';

const BlogLink: FC = () => {
  return <Link to="/blog">Blog</Link>;
};
```

このリンクは次のHTMLを出力し、クリックすると`/blog`にSPAで遷移します。

```html
<a href="/blog">Blog</a>
```

`to`には、作成したルーティングに存在するパスしか指定できません。これがTanStack Routerの型安全性の1つです。

`/blog/tanstack-router`のようなパスパラメータを含むルートへ遷移するときは、`to`にルートのパスをそのまま書き、値を`params`で渡します。`to`がルートのパスのままなので、パラメータを含むリンクも型で確かめられ、`params`を書き忘れると型エラーになります。

```tsx
import { Link } from '@tanstack/react-router';

const PostLink: FC = () => {
  return (
    <Link
      to="/blog/$slug"
      params={{
        slug: 'tanstack-router',
      }}
    >
      Blog
    </Link>
  );
};
```

検索パラメータは`search`で、ハッシュは`hash`で渡せます。`/blog?filter=tanstack&sort=name#Search`へのリンクは次のように書きます。

```tsx
import { Link } from '@tanstack/react-router';

const SearchLink: FC = () => {
  return (
    <Link
      to="/blog"
      search={{
        filter: 'tanstack',
        sort: 'name',
      }}
      hash="Search"
    >
      Blog
    </Link>
  );
};
```

`search`をオブジェクトで渡すので、遷移先のルートで登録した検証の型で確かめられます。検証については後で紹介します。
さらに、`preload`を指定すると、リンクにホバーやタッチした時点から遷移先を読み込めます。

```tsx
import { Link } from '@tanstack/react-router';

const PreloadLink: FC = () => {
  return (
    <Link to="/blog" preload="intent">
      Blog
    </Link>
  );
};
```

ほかにも、`from`を起点にリンク先を書く相対リンクや、`Link`が今のページを指すときのpropsを決める`activeProps`を指定できます。Chrome 156で`/blog`を開くと、`/blog`を指す`Link`には、`activeProps`を書かなくても`class="active"`と`aria-current="page"`が付きました。

#### Navigate

`Navigate`は、描かれた時点で遷移するコンポーネントです。アカウントの設定画面を開いたときに、ログインしていなければログイン画面へ移すような場面で使います。

```tsx
const Setting: FC = () => {
  const user = useUser();

  if (!user) {
    return <Navigate to="/login" search={{ redirect: '/accounts/setting' }} />;
  }
  return <AccountSetting user={user} />;
};
```

ログインしていない状態で`/accounts/setting`を開くと、URLが`/login?redirect=%2Faccounts%2Fsetting`に変わりました。`Navigate`のpropsに渡せる値は、`Link`とほとんど同じです。

#### useNavigate

遷移する関数`navigate`を返すフックです。記事を作るページで、作成後に記事のページへ移すような場面で使います。

```tsx
const navigate = useNavigate();

const onSubmit = async (data: CreateDTO) => {
  const response = await trigger(data);

  if (response.ok) {
    navigate({ to: '/blog/$slug', params: { slug: data.slug } });
  }
};
```

`navigate`には、`Link`のpropsとほぼ同じ値をオブジェクトで渡します。`from`は`useNavigate`の引数でも渡せます。

#### router.navigate

`router.navigate`は`createRouter`で作ったルーターのメソッドで、`useNavigate`が返す`navigate`と同じことができます。フックを使えないコンポーネントの外で遷移するときに使います。

```ts
const router = createRouter({ routeTree });
router.navigate({ to: '/blog/$slug', params: { slug: 'tanstack-router' } });
```

## バリデーション

TanStack Routerでは、`createRoute`の`validateSearch`で検索パラメータを検証し、型を付けられます。

```ts
type BlogSearch = {
  page: number;
  filter: string;
  sort: 'name' | 'date';
};

const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: (search: Record<string, unknown>): BlogSearch => {
    return {
      page: Number(search.page ?? 1),
      filter: typeof search.filter === 'string' ? search.filter : '',
      sort: search.sort === 'date' ? 'date' : 'name',
    };
  },
});
```

Zod 4のように、Standard Schemaに対応したライブラリのスキーマは、そのまま`validateSearch`に渡せます。

```ts
// zodなどのライブラリを用いて検査する
const blogSearchSchema = z.object({
  page: z.number().default(1).catch(1),
  filter: z.string().default(''),
  sort: z.enum(['name', 'date']).default('name').catch('name'),
});

const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: blogSearchSchema,
});
```

`.catch()`を付けたキーは、URLの値が型に合わないときに既定の値になります。`/blog?page=abc&sort=price`を開くと、`page`は`1`、`sort`は`name`として読めました。`.catch()`を付けないと、検証のエラーになって`errorComponent`が描かれます。

コンポーネントでは`useSearch`で検索パラメータを読め、その型は`BlogSearch`（Zodならスキーマの出力の型）になります。このルートで扱う検索パラメータは、どこでも同じ型になります。

このルートへの遷移を考えます。

```tsx
<Link to="/blog" search={{ page: 1, filter: 'blog' }}>Blog</Link>

<Link to="/blog" search={{ page: false, filter: 'blog' }}>Blog</Link>
```

Zodのスキーマで検証したルートでは、後者の`Link`は`page`の型が合わずに型エラーになります。`.default()`を付けたキーは`Link`で省けるので、前者は`sort`が無くてもエラーになりません。
関数で検証したルートでは、`Link`の`search`に`BlogSearch`のすべてのキーが要ります。前者も`sort`が無いので型エラーになります。

## データの取得

TanStack Routerでは、ルーティングに沿ってデータを取得できます。`loader`で取得したデータはルーターがキャッシュし、`useLoaderData`で読めます。TanStack QueryやSWRのようなデータ取得ライブラリと組み合わせて、キャッシュをそちらに任せることもできます。ここではTanStack Query 5.105と組み合わせます。

データの取得はルートごとに、`createRoute`の`loader`に書きます。`loader`は、ルートへの移動や更新、preloadのたびに実行されます。

```tsx
const blogQueryOptions = (slug: string) =>
  queryOptions({
    queryKey: ['blog', slug],
    queryFn: () => fetchBlog(slug),
  });

const postRoute = createRoute({
  getParentRoute: () => blogRoute,
  path: '$slug',
  loader: ({ params }) =>
    queryClient.query({
      ...blogQueryOptions(params.slug),
      staleTime: 'static',
    }),
  component: function Post() {
    const { slug } = postRoute.useParams();
    const { data: blog } = useSuspenseQuery(blogQueryOptions(slug));
    return <Blog blog={blog} />;
  },
});
```

この例では、`component`を描く前の移動や更新、preloadの時点でAPIを呼び、TanStack Queryのキャッシュに入れます。`component`の`useSuspenseQuery`はキャッシュから読むので、ページを描いてからデータを待たずに済みます。TanStack Query 5.105では`ensureQueryData`が非推奨になり、`queryClient.query`に`staleTime: 'static'`を付けて同じことをします。

`loader`には検索パラメータが渡りません。検索パラメータによって取得するデータを変えるときは、`loaderDeps`で使う値を選び、`loader`では`deps`として受け取ります。

```tsx
const blogRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: 'blog',
  validateSearch: blogSearchSchema,
  loaderDeps: ({ search }) => ({ page: search.page }),
  loader: ({ deps }) =>
    queryClient.query({
      ...blogListQueryOptions(deps.page),
      staleTime: 'static',
    }),
});
```

preloadを有効にするには、`Link`の`preload`に`intent`を渡すか、`createRouter`の`defaultPreload`でルーター全体の既定にします。

```tsx
<Link to="/blog" preload="intent">Blog</Link>;

const router = createRouter({
  routeTree,
  defaultPreload: 'intent',
});
```

これで、`Link`にホバーやタッチした時点から、遷移先のデータを先に読み込めます。Chrome 156で試すと、`preload="intent"`の`Link`にホバーしてから50msほど（`defaultPreloadDelay`の既定値）で`loader`が呼ばれ、そのあとクリックしても`loader`は呼ばれ直しませんでした。preloadで読んだ結果は、既定で30秒（`defaultPreloadStaleTime`）のあいだ使い回されます。`preload`を付けない`Link`では、ホバーしても`loader`は呼ばれません。

## おわりに

TanStack Routerの基本的な機能を紹介しました。これまで使ってきたライブラリの使い心地を保ったまま、パスや検索パラメータに型が付く使いやすいルーティングライブラリだと感じました。特に、検索パラメータを型安全な状態のように扱える点が新鮮で、そこに惹かれています。
フレームワークを使わないReactのアプリケーションを作るときは、TanStack Routerを使ってみてはいかがでしょうか。
