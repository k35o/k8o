# ToggleEvent.sourceでpopoverを開いた要素を特定

<BrowserSupportStatus featureId="toggleevent-source" />

## はじめに

`ToggleEvent.source`は、ポップオーバーや`<dialog>`を開閉したボタンを、`toggle`と`beforetoggle`のイベントから読めるプロパティです。開いたか閉じたかに加えて、どのボタンで開閉したかが同じイベントで分かります。Safari 26.5が対応して、Baseline 2026に入りました。

ボタンが1つなら、そのボタンの`click`イベントで足ります。複数のボタンから1つのポップオーバーを開くUIでは、これまで各ボタンの`click`で押されたボタンを変数に覚え、ポップオーバーの側でそれを読んでいました。`source`なら、ポップオーバーの`toggle`イベントのリスナー1つで、押されたボタンが分かります。

```js demo="toggle-source"
const log = document.getElementById('log');

document.getElementById('menu').addEventListener('toggle', (event) => {
  // [!hl]
  log.textContent = `${event.newState} ${event.source?.id ?? null}`;
});
```

```html demo="toggle-source"
<button popovertarget="menu" id="a">A</button>
<button popovertarget="menu" id="b">B</button>
<div id="menu" popover>メニュー</div>
<p id="log"></p>
```

Aを押すと結果の欄に`open a`、もう一度Aを押すと`closed a`が出ます。Bで開けば`open b`で、外側をクリックして閉じると`closed null`です。

## sourceに入る値

`toggle`と`beforetoggle`のイベントは`ToggleEvent`です。`newState`と`oldState`で開いたか閉じたかが分かり、`source`で開閉した要素が分かります。

### 呼び出し元の要素

呼び出し元として`source`に入るのは、次の3つです。

- `popovertarget`属性を持つボタン
- `commandfor`と、`command="show-popover"`か`"hide-popover"`、`"toggle-popover"`を書いたボタン
- スクリプトで`showPopover({ source })`や`togglePopover({ source })`に渡した要素

ボタンの2つは、開く方向でも閉じる方向でも押したボタンが入ります。`<dialog>`も、`commandfor`と`command="show-modal"`や`"close"`のボタンで開閉すると、そのボタンが入ります。`<details>`の`toggle`イベントでは`null`です。`togglePopover({ source })`で閉じたときは、ChromeとFirefoxでは`null`、Safariでは渡した要素が入ります。

### nullになる場合

呼び出し元を通さずに開閉すると、`null`になります。

- `hidePopover()`をスクリプトから呼ぶ（`hidePopover`は`source`オプションを取らない）
- `showPopover()`や`togglePopover()`を、`source`オプションを渡さずに呼ぶ
- ESCキーや外側のクリックで閉じる（light dismiss）

ボタンで開閉したかどうかを、リスナーで見分けるのにも使えます。

## 使い方

メンバー一覧の詳細ボタンを押すと、共通のポップオーバーが押されたメンバーの情報に切り替わって表示されます。

ボタンには`popovertarget`で共通のポップオーバーを指定し、`data-member-id`でどのメンバーかを持たせます。開く操作はブラウザに任せられるので、HTMLは次のように書けます。

```html
<button popovertarget="member-card" data-member-id="alice">詳細</button>
<button popovertarget="member-card" data-member-id="bob">詳細</button>
<button popovertarget="member-card" data-member-id="carol">詳細</button>

<div id="member-card" popover></div>
```

JavaScriptは、ポップオーバーに`toggle`のリスナーを1つ付けるだけです。`event.source`が押されたボタンなので、その`data-member-id`から中身を組み立てます。

```js
const popover = document.getElementById('member-card');

popover.addEventListener('toggle', (event) => {
  // 閉じる方向(light-dismissやhidePopover)はsourceがnullのことが多いので、
  // 開く方向だけを処理する
  if (event.newState !== 'open') return;

  // [!hl]
  // [!callout: 発火元のボタン要素が取れる]
  const trigger = event.source;
  if (!(trigger instanceof HTMLElement)) return;

  popover.textContent = `${trigger.dataset.memberId}の詳細`;
});
```

aliceのボタンを押すと、ポップオーバーにaliceの詳細と出ます。ボタンごとにリスナーを付けたり、最後に押されたボタンを覚えておいたりせずに、ポップオーバーの1か所で押されたボタンが分かります。

ただし、`popovertarget`の既定の動き（`toggle`）では、ポップオーバーを開いたまま別のメンバーの詳細を押すと、切り替わらずに閉じます。どのブラウザでも、そのときの`toggle`イベントは`newState`が`closed`で、`source`は後から押したボタンです。`popovertargetaction="show"`にすると、開いているあいだは押しても何も起きず、イベントも届きません。

デモでは、ボタンの`click`で`hidePopover()`と`showPopover({ source })`を続けて呼び、開いたまま中身を切り替えています。このとき`beforetoggle`は閉じる向きと開く向きの2回届き、`toggle`は`oldState`も`newState`も`open`の1回にまとまります。

Reactの`onToggle`で受け取る合成イベントにも、実行時には`source`が入ります。ただし@types/reactの型には`source`が無いので、TypeScriptでは`event.nativeEvent.source`から読みます。デモもこの書き方です。

## おわりに

`ToggleEvent.source`を使うと、1つのポップオーバーを複数のボタンで開くUIで、押されたボタンをポップオーバーの`toggle`イベントから読めます。開いたまま別のボタンで中身を切り替えるときは、`hidePopover()`と`showPopover({ source })`を続けて呼びます。
