# ToggleEvent.sourceでpopoverを開いた要素を特定

<BrowserSupportStatus featureId="toggleevent-source" />

## はじめに

`ToggleEvent.source`は、ポップオーバーや`<dialog>`を開閉したボタンを、`toggle`・`beforetoggle`イベントから読めるプロパティです。開いたか閉じたかに加えて、どのボタンで開閉したかが同じイベントで分かります。Safari 26.5が対応して、Baseline 2026に入りました。

ボタンが1つなら、そのボタンの`click`イベントで足ります。複数のボタンから1つのポップオーバーを開くUIでは、これまで各ボタンの`click`で押されたボタンを変数に覚え、ポップオーバーの側でそれを読むといった工夫が必要でした。`source`なら、ポップオーバーの`toggle`イベントのリスナー1つで、押されたボタンが分かります。

```html
<button popovertarget="menu" id="a">A</button>
<button popovertarget="menu" id="b">B</button>
<div id="menu" popover>メニュー</div>
<script>
  document.getElementById('menu').addEventListener('toggle', (event) => {
    console.log(event.newState, event.source?.id);
  });
</script>
```

Aを押すとコンソールに`open a`、もう一度Aを押すと`closed a`が出ます。Bで開けば`open b`です。

## どんなプロパティか

`toggle` / `beforetoggle`イベントは`ToggleEvent`インターフェースを持ちます。これまでは`newState` / `oldState`で閉→開・開→閉の遷移だけが分かりましたが、`source`が追加されたことで遷移を引き起こした要素も同じイベントから取れるようになりました。

### `source`に何が入るか

`source`にはイベントを引き起こした呼び出し元が入ります。呼び出し元として拾われるのは次の3パターンです。

- `popovertarget`属性を持つボタン
- `commandfor` + `command="show-popover"` / `"hide-popover"` / `"toggle-popover"`が指定されたボタン
- スクリプトから`showPopover({ source })` / `togglePopover({ source })`の`source`オプションで渡した要素

ボタンの2つは、開く方向でも閉じる方向でも押したボタンが入ります。`<dialog>`も、`commandfor`と`command="show-modal"`・`"close"`のボタンで開閉すると、そのボタンが入ります。`<details>`の`toggle`イベントでは`null`です。`togglePopover({ source })`で閉じたときは、ChromeとFirefoxでは`null`、Safariでは渡した要素が入ります。

### `source`が`null`になるケース

呼び出し元を介さない経路で開閉した場合は`null`になります。

- `hidePopover()`をスクリプトから呼ぶ（`hidePopover`は`source`オプションを取らない）
- `showPopover()` / `togglePopover()`を`source`オプションを取らずに呼ぶ
- ESCキーや外側クリックによるlight-dismissで閉じる（どのブラウザでも、外側のクリックとESCキーで閉じたときは`null`です）

ユーザー操作起点の発火と区別できるので、リスナー側で分岐させる材料にも使えます。

## 使い方

メンバー一覧の詳細ボタンを押すと、共通のポップオーバーが押されたメンバーの情報に切り替わって表示されます。

/>

このUIは、ボタン側に`popovertarget`属性で共通ポップオーバーを指定し、`data-member-id`でどのメンバーかを持たせる構成です。開く操作はブラウザに任せられるので、HTMLは次のように書けます。

```html
<button popovertarget="member-card" data-member-id="alice">詳細</button>
<button popovertarget="member-card" data-member-id="bob">詳細</button>
<button popovertarget="member-card" data-member-id="carol">詳細</button>

<div id="member-card" popover></div>
```

JS側はポップオーバーに`toggle`リスナーを1つ張るだけです。`event.source`が押されたボタンを返してくれるので、その`data-member-id`から表示すべき中身を組み立てます。

```js
const popover = document.getElementById('member-card');

popover.addEventListener('toggle', (event) => {
  // 閉じる方向(light-dismissやhidePopover)はsourceがnullのことが多いので、
  // 開く方向だけを処理する
  if (event.newState !== 'open') return;

  // [!hl]
  // [!callout: 発火元のボタン要素が取れる]
  const trigger = event.source;
  if (!(trigger instanceof HTMLElement)) return;

  popover.textContent = `${trigger.dataset.memberId}の詳細`;
});
```

aliceのボタンを押すと、ポップオーバーにaliceの詳細と出ます。ボタンごとに個別のリスナーを張ったり、最後に押されたボタンを別途状態として持ち回したりする必要がなくなり、ポップオーバー側の1か所で発火元を判定できるのが`event.source`の効きどころです。

ただし、`popovertarget`の既定の動き（`toggle`）では、ポップオーバーを開いたまま別のメンバーの詳細を押すと、切り替わらずに閉じます。どのブラウザでも、そのときの`toggle`イベントは`newState`が`closed`で、`source`は後から押したボタンです。`popovertargetaction="show"`にすると、開いているあいだは押しても何も起きず、イベントも届きません。デモでは、ボタンの`click`で`hidePopover()`と`showPopover({ source })`を続けて呼び、開いたまま中身を切り替えています。このとき`beforetoggle`は閉じる向きと開く向きの2回届き、`toggle`は`oldState`も`newState`も`open`の1回にまとまります。

Reactの`onToggle`で受け取る合成イベントにも、実行時には`source`が入ります。ただし@types/reactの型には`source`が無いので、TypeScriptでは`event.nativeEvent.source`から読みます。デモもこの書き方です。

## おわりに

`ToggleEvent.source`はやっていることは小さいですが、複数トリガーが1つのポップオーバーを共有するUIでは効きの大きい機能です。ボタンごとにリスナーを分けたり、開いたボタンをグローバルに記録したりといった回避策が一段整理できます。Popover APIや`commandfor`を組み合わせた宣言的なUIと相性がよく、合わせて使うときに覚えておきたい一手です。開いたまま別のボタンで中身を切り替えるときは、`hidePopover()`と`showPopover({ source })`を続けて呼びます。
