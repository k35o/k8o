# MapのgetOrInsertComputedでキーが無ければ追加する

<BrowserSupportStatus featureId="getorinsert" />

## はじめに

`getOrInsert`と`getOrInsertComputed`は、`Map`と`WeakMap`のメソッドです。キーが無ければ値を追加してから返し、キーがあればその値を返します。Baseline 2026で使えるようになりました。

配列の要素をまとめてグループに分けるだけなら、`Map.groupBy`で足ります。要素があとから1つずつ届き、そのたびにキーの値を取り出して手を加える場面では、これまで次のように書いていました。

```js
const map = new Map();
if (!map.has(key)) {
  map.set(key, INIT_VALUE);
}
return map.get(key) ?? INIT_VALUE;
```
`Map`にキーが存在しない場合は新たに初期値をセットして、存在する場合はその値を返す、というパターンです。

グループ化やカウントなど頻出のパターンですが`has`→`set`→`get`の3ステップが毎回必要で冗長です。
TypeScriptでは`has`で存在を確認した後でも`get`の返り値が`V | undefined`のままで型が絞り込まれないため、非nullアサーション（`!`）や`??`での対処も必要になります。

`getOrInsert`と`getOrInsertComputed`を使うと、このパターンを1行で書けます。`WeakMap`にも同じメソッドがありますが、ここでは`Map`を例に紹介します。

## getOrInsert

```ts
const map = new Map<K, V>();
map.getOrInsert(key: K, defaultValue: V): V
```

`getOrInsert`は2つの引数を取ります。

- `key`：取得または挿入するキー
- `defaultValue`：キーが存在しない場合に挿入・返却する値

キーが存在すれば既存の値をそのまま返し、存在しなければ`defaultValue`を`set`してから返します。

```js
// [!og]
const map1 = new Map();
console.log(map1.getOrInsert('a', 0)); //  0（挿入して返す）
console.log(map1.getOrInsert('a', 1)); //  0（既存値を返す）

const map2 = new Map();
console.log(map2.getOrInsert('a', 1)); //  1（挿入して返す）
console.log(map2.getOrInsert('a', 0)); //  1（既存値を返す）
```

コンソールに貼ると、0・0・1・1の順に出ます。2回目の呼び出しは、渡した値に関わらず1回目に入れた値を返します。

冒頭に紹介したコードは以下のように簡潔に記述できます。

```ts
const map = new Map<string, typeof INIT_VALUE>();
return map.getOrInsert(key, INIT_VALUE);
```

単語の数を数えるなら、0を初期値にして取り出し、1を足して書き戻します。数値は取り出したあとに書き換えられないので、`set`は残ります。

```js
const counts = new Map();
for (const word of ['a', 'b', 'a', 'c', 'a']) {
  counts.set(word, counts.getOrInsert(word, 0) + 1);
}
console.log(counts.get('a')); // 3
```

ORMでは`findOrCreate`といった名前で同等の操作がよく提供されています。`getOrInsert`はそれと同じ考え方を`Map`にもたらすものです。

## getOrInsertComputed

実は`getOrInsert`には注意点があります。第2引数はメソッドを呼び出した時点で評価されるため、キーが既に存在する場合でもデフォルト値の式が実行されてしまいます。

```js
//'a'が存在していてもexpensiveCompute()は必ず実行される
map.getOrInsert('a', expensiveCompute());
```

デフォルト値の生成コストが高い場合にはこれが問題になります。`getOrInsertComputed`はこの問題を解決するために用意されたメソッドです。

```ts
const map = new Map<K, V>();
map.getOrInsertComputed(key: K, callbackFn: (key: K) => V): V
```

`getOrInsertComputed`の第2引数には値ではなく関数を渡します。

- `key`: 取得または挿入するキー
- `callbackFn`: キーが存在しない場合のみ呼ばれる関数。`key`を引数として受け取り、挿入する値を返す

キーが存在すれば`callbackFn`は呼ばれません。存在しない場合のみ`callbackFn(key)`を実行し、その返り値を`set`して返します。

```ts
const map = new Map<string, number>();

const callback = (key: string) => {
  // コールバックが実際に呼ばれたかどうかをログで確認する（本来は副作用を避けるべき）
  console.log(`"${key}" のコールバックを実行`);
  return key.length;
};

map.getOrInsertComputed('a', callback);
// ログ: "a" のコールバックを実行（キーが存在しないため呼ばれる）

map.getOrInsertComputed('a', callback);
// ログなし（キーが既に存在するため呼ばれない）
```

グループ化では、キーごとに空の配列を作って、取り出した配列に要素を足します。`getOrInsert(post.tag, [])`でも結果は同じですが、キーがあっても呼ぶたびに配列を作って捨てることになります。

```js
const posts = [
  { tag: 'css', title: 'field-sizing' },
  { tag: 'js', title: 'Promise.try' },
  { tag: 'css', title: '@scope' },
];
const byTag = new Map();
for (const post of posts) {
  byTag.getOrInsertComputed(post.tag, () => []).push(post.title);
}
console.log(byTag.get('css')); // ['field-sizing', '@scope']
```

コールバックの中で同じキーに`set`しても、追加されるのはコールバックが返した値です。Chrome 156、Safari 27.2、Firefox 159、Node.js 26.13.0のどれでも、次のコードは`'outer'`を2回出し、`size`は1でした。コールバックで`Map`を書き換えないようにします。

```js
const map = new Map();
const value = map.getOrInsertComputed('key', (key) => {
  map.set(key, 'inner');
  return 'outer';
});
console.log(value, map.get('key'), map.size); // outer outer 1
```

コールバックの引数にはキーが渡されるため、キーから値を導出するパターンにも適しています。

```js
// Intl.NumberFormat のインスタンスはコストが高いのでキャッシュしておく
const formatters = new Map();

const createFormatter = (locale) => new Intl.NumberFormat(locale);

formatters.getOrInsertComputed('ja-JP', createFormatter);
formatters.getOrInsertComputed('en-US', createFormatter);
```

## TypeScript 6.0での対応

`getOrInsert`と`getOrInsertComputed`の型は、[TypeScript 6.0](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0-beta/#new-types-for-%22upsert%22-methods-(a.k.a.-getorinsert))で`esnext`ライブラリに追加されました。TypeScript 5.9以前には型がありません。

手元のTypeScript 7.0.2でも、型があるのは`esnext`ライブラリだけでした。`lib`が`es2025`以前だと`Property 'getOrInsert' does not exist on type 'Map<string, number>'`（TS2550）になるので、`lib`に`esnext`を含めます。追加された型は次のとおりです。

```ts
interface Map<K, V> {
    getOrInsert(key: K, defaultValue: V): V;
    getOrInsertComputed(key: K, callback: (key: K) => V): V;
}

interface WeakMap<K extends WeakKey, V> {
    getOrInsert(key: K, defaultValue: V): V;
    getOrInsertComputed(key: K, callback: (key: K) => V): V;
}
```

`get`の返り値`V | undefined`に対して、`getOrInsert`と`getOrInsertComputed`は常に`V`を返すことが型レベルで保証されるようになり非常に嬉しいです。

## おわりに

`getOrInsert`と`getOrInsertComputed`は、`Map`で頻出する、キーが無ければ初期値を入れてから取り出す処理を1行で書けるようにするメソッドです。数え上げでは`getOrInsert`に0を、グループ化では`getOrInsertComputed`に空の配列を返す関数を渡します。

`getOrInsert`は値を直接渡す即時評価、`getOrInsertComputed`はコールバックによる遅延評価という使い分けを押さえておけば、場面に合わせて適切に選択できます。
