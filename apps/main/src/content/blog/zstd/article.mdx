# zstd（Zstandard）でHTTPのレスポンスを圧縮する

<BrowserSupportStatus featureId="zstd" />

## はじめに

`zstd`（Zstandard）は、Metaが開発した可逆圧縮のアルゴリズムです。HTTPではレスポンスの圧縮形式の1つとして使え、ブラウザは`Content-Encoding: zstd`で返されたレスポンスを展開します。Safari 26.3が対応して、Baseline 2026に入りました。

`gzip`と`Brotli`で返せていれば、多くの場面はそれで足ります。`zstd`を足して変わるのは、圧縮と展開にかかる時間です。リクエストのたびに圧縮するレスポンスを、`gzip`より短い時間で小さくしたいときに向いています。

レスポンスボディは、`Accept-Encoding`リクエストヘッダーと`Content-Encoding`レスポンスヘッダーを使って圧縮できます。

### Accept-Encoding

`Accept-Encoding`はリクエストヘッダーで、クライアントが対応している圧縮形式をサーバーに伝えます。

```http
Accept-Encoding: gzip, deflate, br
```

カンマ区切りで複数の圧縮形式を指定できます。また、`q`パラメータで各形式の優先度（0〜1）を指定することもできます。

```http
Accept-Encoding: gzip;q=0.8, br;q=1.0
```

優先度を指定しない場合は`1.0`として扱われます。`q=0`は、その形式を受け入れないという意味です。

### Content-Encoding

`Content-Encoding`はレスポンスヘッダーで、サーバーが実際に適用した圧縮形式をクライアントに伝えます。

```http
Content-Encoding: br
```

クライアントはこのヘッダーを見て、適切な方法でレスポンスボディを展開します。

なお、サーバーが圧縮に対応していない場合や、クライアントが送った`Accept-Encoding`の中に対応形式がなかった場合は、`Content-Encoding`ヘッダーなしで非圧縮のまま返されます。

`zstd`も、この仕組みで使える圧縮形式の1つです。

## zstd

`zstd`は[RFC 8878](https://www.rfc-editor.org/rfc/rfc8878)で標準化されていて、`zlib`レベルの圧縮率を保ちつつリアルタイム圧縮が可能なことを目標に設計されています。

[ベンチマーク](https://github.com/facebook/zstd?tab=readme-ov-file#benchmarks)によれば、`gzip(zlib)`を上回る圧縮率を誇り、`Brotli`と同等のサイズを維持しながら、数倍速い展開速度を実現しています。
これにより、クライアント側のCPU負荷を抑えつつ高速なページロードが可能です。

また、圧縮速度と圧縮率はトレードオフの関係にありますが、圧縮レベルを細かく調整することでそのバランスを柔軟に変えられます。

Node.jsの`node:zlib`で、この記事のHTMLを圧縮して比べると、`zstd`（既定のレベル3）は`gzip`（レベル6）より速く、小さくなります。最も小さくなるのは`Brotli`（品質11）ですが、圧縮には`gzip`の数十倍の時間がかかります。react-domの本番用のJSでは、レベル3の`zstd`は`gzip`より大きくなり、レベル9で`gzip`より速く小さくなります。展開は、どちらのファイルでも`zstd`が`Brotli`より速く終わります。

### ブラウザでの利用

対応したブラウザでは、`Accept-Encoding`ヘッダーに`zstd`が自動的に追加されます。

```http
Accept-Encoding: gzip, deflate, br, zstd
```

サーバーが`zstd`圧縮に対応している場合、`Content-Encoding: zstd`ヘッダーとともにzstd圧縮されたレスポンスを返します。

```http
Content-Encoding: zstd
```

Node.jsでは、`node:zlib`の`zstdCompressSync`で圧縮して返せます。

```js title="server.mjs"
import { createServer } from 'node:http';
import { zstdCompressSync } from 'node:zlib';

createServer((req, res) => {
  const acceptEncoding = req.headers['accept-encoding'] ?? '';
  console.log(acceptEncoding);
  const body = Buffer.from('<h1>Hello, zstd!</h1>');
  if (acceptEncoding.includes('zstd')) {
    res.writeHead(200, {
      'Content-Type': 'text/html; charset=utf-8',
      'Content-Encoding': 'zstd',
      Vary: 'Accept-Encoding',
    });
    res.end(zstdCompressSync(body));
    return;
  }
  res.writeHead(200, {
    'Content-Type': 'text/html; charset=utf-8',
    Vary: 'Accept-Encoding',
  });
  res.end(body);
}).listen(3000);
```

ChromeかFirefoxで`http://localhost:3000`を開くと、ターミナルに`gzip, deflate, br, zstd`と出て、`zstd`で圧縮した見出しが表示されます。Safariでは`gzip, deflate`とだけ出て、圧縮していない見出しが表示されます。Safariは`zstd`で返したレスポンスも展開できますが、`http`の`localhost`へのリクエストには`zstd`を付けません。`https`で開いたページでは、ページの読み込みにも`fetch()`にも`gzip, deflate, br, zstd`を付けます。

ただし、ブラウザが`zstd`を送っても、サーバーが`zstd`を選ぶとは限りません。どの形式で返すかはサーバーやCDNが決めるので、`zstd`で配信したいときは、DevToolsのネットワークパネルで`Content-Encoding`を見て、配信側が対応しているかを確かめます。

## おわりに

`zstd`がBaseline 2026で追加され、`gzip`・`Brotli`に並ぶ圧縮形式の選択肢として使えるようになりました。

対応したブラウザは`Accept-Encoding`に`zstd`を自動で付けるので、サーバーかCDNが`zstd`で返せば使われます。事前に圧縮して置ける静的なファイルは時間をかけた`Brotli`が最も小さくなり、リクエストのたびに圧縮するレスポンスは`zstd`で`gzip`より速く小さくできます。配信している`Content-Encoding`を確かめて、`zstd`への対応を検討してみてください。
