# webkitdirectoryでinputからフォルダを選択する

<BrowserSupportStatus featureId="input-file-webkitdirectory" />

## はじめに
`webkitdirectory`は、`<input type="file">`でファイルの代わりにフォルダ（ディレクトリ）を選ばせる属性です。選んだフォルダの中のファイルがサブフォルダの中まで`files`に入り、各ファイルの`webkitRelativePath`には、選んだフォルダから見たパスが入ります。

ファイルを1つ、または`multiple`で複数選ばせるなら、これまでの`type="file"`で足ります。`<input>`でフォルダを丸ごと選ばせて、どのファイルがどのサブフォルダにあったかまで受け取るのは、`webkitdirectory`でしかできません。

`<input>`要素に`type="file"`を付与すると、ファイルを入力するための要素になります。

```html
<!-- 単一ファイル選択 -->
<input type="file" />

<!-- 複数ファイル選択 -->
<input type="file" multiple />
```

<BasicFileInputExamples />

この機能に加えて、ディレクトリごと選択させる`webkitdirectory`属性が、Firefox Androidの対応によってBaseline 2025に追加されました。

```html
<!-- [!og] -->
<!-- ディレクトリ選択 -->
<input type="file" webkitdirectory />
```

<WebkitDirectoryInputExample />

ボタンを押すと、ファイルではなくフォルダを選ぶダイアログが開きます。フォルダを選ぶと、中のファイルがまとめて`files`に入ります。

## webkitdirectory属性
`webkitdirectory`は真偽値の属性で、付けるとディレクトリの選択になり、付けなければファイルの選択になります。
値は見ないので、`webkitdirectory="false"`と書いてもディレクトリの選択になります。Chrome 156、Safari 27.2、Firefox 159のいずれでも、`webkitdirectory="false"`の`input`の`webkitdirectory`プロパティは`true`でした。JavaScriptから切り替えるときは、プロパティに`true`か`false`を入れると属性が付け外しされます。

### ファイルの取得
`webkitdirectory`属性を付与した`<input>`要素で選択したファイルの取得は、`multiple`属性を指定した時の取得方法と同じように`files`プロパティから取得します。

`files`プロパティは`FileList`オブジェクトまたは`null`を返します。

`FileList`オブジェクトは`File`オブジェクトの集合体で、`File`は添え字からのアクセスと`item()`メソッドでアクセスできます。また、`FileList`はイテレーターとしての機能も持っています。

```ts
const files = inputElement.files;

// 選択されたファイル数
console.log(files?.length);
// 添え字でのアクセス
console.log(files?.[0]);
// item()メソッドでのアクセス なければnullを返す
console.log(files?.item(0));
// イテレーターでのアクセス
for (const file of files ?? []) {
  console.log(file);
}
```

`webkitdirectory`属性を付与した`<input>`要素から入力された`File`は書き換え不可な`webkitRelativePath`プロパティを持ちます。
このプロパティには、選択されたファイルの相対パスが格納されます。

```ts
const files = inputElement.files;

for (const file of files ?? []) {
  console.log(file.webkitRelativePath);
}
```

Chrome 156で、`a.txt`と`.hidden`のほかにサブフォルダと空のフォルダを置いた`photos`フォルダを渡すと、上のコードは次の4行を出しました。

```txt
photos/.hidden
photos/a.txt
photos/sub/b.txt
photos/sub/deeper/c.txt
```

パスは選んだフォルダの名前から始まり、`.`で始まるファイルも入ります。空のフォルダ（`photos/empty`）は何も残しません。`multiple`属性は付けていません。そのままフォームで送ると、multipartの`filename`にも`photos/sub/b.txt`のパスが入りました。フォルダは、Playwrightの`setInputFiles()`にフォルダのパスを渡して選ばせています。

テストで`DataTransfer`を使って`files`に`File`を入れても、`webkitRelativePath`は空文字のままです。Chrome 156、Safari 27.2、Firefox 159のいずれでもそうでした。`webkitRelativePath`を使う処理を確かめるときは、上のようにブラウザにフォルダを渡します。

ボタンを押してフォルダを選ぶと、中の各ファイルが`webkitRelativePath`のパスと一緒に一覧になります。

`input`要素が持つ複数のファイルを扱う別の方法として`webkitEntries`プロパティがありますが、このプロパティはいくつかのブラウザで`webkitdirectory`属性と併用できないようなので注意してください。Chrome 156では、上と同じようにフォルダを渡したあとの`webkitEntries`は空の配列でした。

## おわりに
`input`要素でファイルを扱う際に、`webkitdirectory`属性を利用することでディレクトリごと選択可能になり、中のファイルを`webkitRelativePath`のパスと一緒に受け取れるようになりました。

`webkitdirectory`属性のような`webkit`prefixがついている機能は利用を躊躇いますが、Baseline 2025に追加されたことで安心して利用できるようになったのではないでしょうか。
