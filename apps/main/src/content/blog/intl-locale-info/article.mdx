# Intl.Localeで週の始まりの曜日や書字方向を調べる

<BrowserSupportStatus featureId="intl-locale-info" />

## はじめに

Intl.Locale infoは、`Intl.Locale`に`getWeekInfo()`や`getTextInfo()`などのメソッドを足す機能です。週の始まりの曜日や書字方向といった、ロケールごとの慣習を返します。Firefox 153が対応して、Baseline 2026に入りました。

日付や数値をロケールに合わせて表示するときは、`Intl.DateTimeFormat`や`Intl.NumberFormat`がロケールの慣習に従って整形します。カレンダーの列を何曜日から並べるかや、ページの`dir`属性のように、慣習の値そのものを受け取ってUIを組むときに、Intl.Locale infoが要ります。

```js
// [!og]
const locale = new Intl.Locale('ja-JP');

console.log(locale.getWeekInfo());
// { firstDay: 7, weekend: [6, 7] }

console.log(locale.getTextInfo());
// { direction: 'ltr' }
```

コンソールに貼ると、日本語の日本では週が日曜（7）から始まり、土曜（6）と日曜が週末で、文字を左から右へ書くことが分かります。

こうした情報の大元は、Unicodeコンソーシアムが管理するロケールデータのCLDR（Common Locale Data Repository）です。これまでは、CLDRのデータを含むライブラリを組み込むか、使うロケールの対応表を自分で持っていました。Intl.Locale infoなら、ブラウザが持つCLDR由来のデータをそのまま読めます。

## Intl.Localeに追加された7つのメソッド

`Intl.Locale`は、BCP 47のロケール識別子を解析し、言語や地域といった部分を読めるようにするオブジェクトです。

```js
const locale = new Intl.Locale('ja-JP');
locale.language; // 'ja'
locale.region; // 'JP'
```

Intl.Locale infoは、この`Intl.Locale`に7つのメソッドを足します。どれも引数を取らず、CLDRに基づく値を返します。

- `getWeekInfo()`：週の始まりと週末の曜日
- `getTextInfo()`：書字方向
- `getCalendars()`：好まれる暦
- `getHourCycles()`：時刻の表記法
- `getNumberingSystems()`：数字の表記
- `getCollations()`：文字列の並べ替え規則
- `getTimeZones()`：地域で使われるタイムゾーン

TypeScriptでは、`lib`に`esnext`を含めると7つのメソッドの型が付きます。`es2025`までだと`Property 'getWeekInfo' does not exist on type 'Locale'`（TS2339）になります。

## 週の始まりと週末を返すgetWeekInfo

`getWeekInfo()`は、`firstDay`と`weekend`を持つオブジェクトを返します。曜日は、1が月曜、7が日曜の整数です。`firstDay`は週の最初の曜日で、`weekend`は週末の曜日の配列です。

```js
new Intl.Locale('ja-JP').getWeekInfo();
// { firstDay: 7, weekend: [6, 7] }

new Intl.Locale('en-GB').getWeekInfo();
// { firstDay: 1, weekend: [6, 7] }

new Intl.Locale('ar-EG').getWeekInfo();
// { firstDay: 6, weekend: [5, 6] }
```

日本は日曜始まりで土日が週末、イギリスは月曜始まり、エジプトは土曜始まりで金曜と土曜が週末です。カレンダーの列の順や週末の色分けを、ロケールごとに組み立てられます。

```js
const tag = 'en-GB';
const { firstDay, weekend } = new Intl.Locale(tag).getWeekInfo();
const format = new Intl.DateTimeFormat(tag, { weekday: 'short', timeZone: 'UTC' });
const days = Array.from({ length: 7 }, (_, i) => ((firstDay - 1 + i) % 7) + 1);
// 2024年1月1日は月曜なので、1月1〜7日が曜日の1〜7に当たる
const header = days.map((day) => ({
  label: format.format(new Date(Date.UTC(2024, 0, day))),
  isWeekend: weekend.includes(day),
}));
console.log(header.map(({ label }) => label).join(' '));
// Mon Tue Wed Thu Fri Sat Sun
```

`tag`を`ja-JP`にすると`日 月 火 水 木 金 土`の順になり、`ar-EG`にすると土曜から始まって金曜と土曜の`isWeekend`が`true`になります。どのブラウザでも同じ並びです。

## 書字方向を返すgetTextInfo

`getTextInfo()`は、文字を左右どちらの向きへ書くかを`direction`プロパティで返します。値は`ltr`か`rtl`です。

```js
new Intl.Locale('ja-JP').getTextInfo(); // { direction: 'ltr' }
new Intl.Locale('ar-EG').getTextInfo(); // { direction: 'rtl' }
```

HTMLの`dir`属性と同じ値なので、そのまま渡せます。

```js
const locale = new Intl.Locale(navigator.language);
// [!hl]
document.documentElement.dir = locale.getTextInfo().direction;
```

アラビア語やヘブライ語のように右から左へ書く言語では、文字の向きだけでなく、UIのレイアウトも左右を入れ替えます。CSSの論理プロパティでレイアウトを組んでいれば、この1行でレイアウトも入れ替わります。

## 好まれる暦を返すgetCalendars

`getCalendars()`は、そのロケールで好まれる暦の識別子を、優先順に並べた配列で返します。先頭が既定の暦です。

```js
new Intl.Locale('ja-JP').getCalendars();
// ['gregory', 'japanese']

new Intl.Locale('ar-EG').getCalendars();
// ['gregory', 'coptic', 'islamic', 'islamic-civil', 'islamic-tbla']
```

日本語ではグレゴリオ暦に加えて和暦（`japanese`）が、エジプトのアラビア語ではコプト暦やヒジュラ暦が候補に入ります。`ar-EG`の結果はChromeとSafariのもので、Firefoxは`islamic`を含めず、4つを返します。

## 時刻の表記法を返すgetHourCycles

`getHourCycles()`は、好まれる時刻の表記法の識別子を、同じく優先順の配列で返します。表記法は4種類あります。

- `h11`：0時から11時までの12時間制
- `h12`：1時から12時までの12時間制
- `h23`：0時から23時までの24時間制
- `h24`：1時から24時までの24時間制

```js
new Intl.Locale('ja-JP').getHourCycles(); // ['h23']
new Intl.Locale('en-US').getHourCycles(); // ['h12']
```

日本語を含む多くのロケールは`h23`が、アメリカ英語は`h12`が既定です。

この結果もChromeとSafariのものです。Firefoxは既定以外の表記も並べ、`ja-JP`に`['h23', 'h11', 'h12']`を、`en-US`に`['h12', 'h23']`を返します。先頭が既定なのはどのブラウザでも同じなので、既定の表記を知りたいときは先頭の値を使います。

## 数字の表記を返すgetNumberingSystems

`getNumberingSystems()`は、好まれる数字の表記の識別子を優先順の配列で返します。

```js
new Intl.Locale('ja-JP').getNumberingSystems(); // ['latn']
new Intl.Locale('ar-EG').getNumberingSystems(); // ['arab']
```

日本語では算用数字（`latn`）が、エジプトのアラビア語ではアラビア・インド数字（`arab`）が既定です。

`getCalendars()`と`getHourCycles()`、`getNumberingSystems()`が返す識別子は、`Intl.DateTimeFormat`の`calendar`や`hourCycle`、`numberingSystem`のオプションにそのまま渡せます。ロケールの既定に合わせつつ、ほかの表記に切り替える選択肢を出すときに使えます。

## 文字列の並べ替え規則を返すgetCollations

`getCollations()`は、そのロケールで使われる文字列の並べ替え規則の識別子を、アルファベット順の配列で返します。

```js
new Intl.Locale('ja-JP').getCollations();
// ['emoji', 'eor', 'unihan']
```

日本語では、絵文字の並べ替え（`emoji`）や、漢字を部首と画数で並べる方式（`unihan`）などが返ります。既定の並べ替えを表す`standard`と、検索用の`search`は一覧に入りません。Safariは`ja-JP`に`['unihan', 'emoji', 'eor']`を返し、アルファベット順になっていません。並びに頼らず、`includes()`で含まれるかを調べます。

返った識別子は、`Intl.Collator`の`collation`オプションに渡して実際の並べ替えへ反映できます。

## 地域のタイムゾーンを返すgetTimeZones

`getTimeZones()`は、ロケールの地域サブタグに対応するIANAタイムゾーンIDを、辞書順に並んだ配列で返します。

```js
new Intl.Locale('ja-JP').getTimeZones(); // ['Asia/Tokyo']

new Intl.Locale('en-US').getTimeZones();
// ['America/Adak', 'America/Anchorage', ...] 全29件
```

地域サブタグを持たないロケールでは`undefined`を返します。

```js
new Intl.Locale('ja').getTimeZones(); // undefined
```

タイムゾーンを選ぶUIで、ユーザーの地域のタイムゾーンを先頭に出すときに使えます。返るのは地域に結びつくタイムゾーンの一覧なので、ユーザーが今いるタイムゾーンを知るには、これまでどおり`Intl.DateTimeFormat().resolvedOptions().timeZone`を使います。

## Unicode拡張キーワードを指定した場合

ロケール識別子の`-u-`拡張で暦や時刻の表記を指定すると、対応するメソッドは地域の既定ではなく、その値だけを返します。

```js
new Intl.Locale('ja-JP-u-ca-japanese').getCalendars(); // ['japanese']
new Intl.Locale('ja-JP-u-hc-h12').getHourCycles(); // ['h12']
new Intl.Locale('ja-JP-u-fw-mon').getWeekInfo(); // { firstDay: 1, weekend: [6, 7] }
```

週の始まりも`fw`で指定でき、どのブラウザでも`ja-JP-u-fw-mon`は月曜始まりになります。既定以外の表記も並べるFirefoxも、`hc`を指定すると`['h12']`だけを返します。

ユーザーが選んだ暦や時刻の表記をロケール識別子に載せておけば、地域の既定とユーザーの選択を同じコードで扱えます。

## ロケールを変えて試す

ロケールを選ぶか識別子を入力すると、7つのメソッドが返す値を見られます。

```html demo="locale"
<label>
  ロケール識別子
  <input id="tag" type="text" value="ja-JP" />
</label>
<p id="presets">
  <button type="button">ja-JP</button>
  <button type="button">en-US</button>
  <button type="button">en-GB</button>
  <button type="button">ar-EG</button>
  <button type="button">zh-Hant-TW</button>
  <button type="button">ja-JP-u-ca-japanese</button>
</p>
<p id="error" hidden>ロケール識別子として解釈できません</p>
<dl id="results"></dl>
```

```css demo="locale"
dl {
  font-family: monospace;
}

dd {
  margin-block-end: 0.5rem;
  word-break: break-all;
}
```

```js demo="locale"
const input = document.querySelector('#tag');
const error = document.querySelector('#error');
const results = document.querySelector('#results');

const methods = [
  'getWeekInfo',
  'getTextInfo',
  'getCalendars',
  'getHourCycles',
  'getNumberingSystems',
  'getCollations',
  'getTimeZones',
];

const update = () => {
  results.replaceChildren();
  let locale;
  try {
    locale = new Intl.Locale(input.value.trim());
  } catch {
    error.hidden = false;
    return;
  }
  error.hidden = true;

  for (const method of methods) {
    const name = document.createElement('dt');
    name.textContent = `${method}()`;
    const value = document.createElement('dd');
    // JSON.stringify(undefined) は文字列ではなく undefined を返す
    value.textContent = JSON.stringify(locale[method]()) ?? 'undefined';
    results.append(name, value);
  }
};

input.addEventListener('input', update);
document.querySelector('#presets').addEventListener('click', (event) => {
  if (!(event.target instanceof HTMLButtonElement)) return;
  input.value = event.target.textContent;
  update();
});
update();
```

## おわりに

Intl.Locale infoを使うと、週の始まりや書字方向から地域のタイムゾーンまで、ロケールの慣習を対応表やライブラリなしに受け取れます。`getCalendars()`と`getHourCycles()`、`getCollations()`の返す並びはブラウザで分かれるので、先頭の値か、含まれるかどうかで判断します。
