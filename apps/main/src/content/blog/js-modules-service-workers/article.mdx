# Service WorkerでES Modulesのimportを使う

<BrowserSupportStatus featureId="js-modules-service-workers" />

## はじめに

Service WorkerのES Modules対応は、`navigator.serviceWorker.register()`に`type: 'module'`を渡すと、Service Workerのスクリプトで`import`文を使えるようにするものです。ページと同じESモジュールのファイルを、Service Workerからもそのまま読み込めます。Firefox 147が対応して、Baseline 2026に入りました。

ビルドツールでService Workerを1つのファイルにまとめているなら、これまでどおりの書き方で足ります。ビルドせずに、ページと同じモジュールをService Workerから読みたいときに`type: 'module'`が要ります。

Service Workerで外部のスクリプトを読み込むには、これまで`importScripts()`を使う必要がありました。

```js
// sw.js（従来の方法）
importScripts('./utils.js');
importScripts('./cache-config.js');
```

`importScripts()`は読み込んだスクリプトの変数や関数がすべてグローバルスコープに追加されるため、依存関係が不明確になりやすいという課題がありました。

## 使い方

Service Workerの登録時に`type`オプションで`'module'`を指定します。

```html title="index.html"
<!doctype html>
<script type="module">
  import { cacheName } from './cache-config.js';
  console.log(cacheName);
  navigator.serviceWorker.register('./sw.js', { type: 'module' });
</script>
```

`type`オプションには`'classic'`と`'module'`の2つの値があり、デフォルトは`'classic'`です。
`'module'`を指定することで、Service Worker内でES Modulesの静的インポートが使えるようになります。

```js title="sw.js"
// [!og]
import { cacheName, precacheFiles } from './cache-config.js';

self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(cacheName).then((cache) => cache.addAll(precacheFiles)),
  );
});

self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((res) => res ?? fetch(event.request)),
  );
});
```

ページとService Workerの両方が読む`cache-config.js`は、ふつうのESモジュールです。

```js title="cache-config.js"
export const cacheName = 'app-v1';
export const precacheFiles = ['/', '/cache-config.js'];
```

Service Workerは`https`か`localhost`でしか登録できませんが、`localhost`なら`http`でも登録できます。`http://localhost`で開くとコンソールに`app-v1`が出て、DevToolsでService Workerが動いていることと、キャッシュ`app-v1`に2つのファイルが入ったことが見えます。2回目に開いたページは、Service Workerの制御下に入ります。

ES Modulesを使う最大のメリットは、ウェブアプリとService Workerで同じコードを共有できることです。
`importScripts()`では難しかったコードの再利用が、`import`文によって自然に行えるようになります。

`import()`による動的なインポートはサポートされていないことに注意してください。
また、`type`を`'module'`に設定すると、`importScripts()`の使用も不可になるので気をつけてください。どちらも呼ぶと`TypeError`になり、メッセージはブラウザで違います。

- Chrome: `import() is disallowed on ServiceWorkerGlobalScope by the HTML specification.`、`Module scripts don't support importScripts().`
- Safari: `Dynamic-import is not available in Worklets or ServiceWorkers`、`importScripts cannot be used if worker type is "module"`
- Firefox: `Dynamic import not supported in this context`、`` Using `ImportScripts` inside a Module Worker is disallowed. ``

反対に、`type: 'module'`を付けずに`import`文を書いたService Workerは、登録の時点で`TypeError`になります。メッセージは、Chromeでは`ServiceWorker script evaluation failed`、Safariでは`SyntaxError: Unexpected token '{'. import call expects one or two arguments.`です。また、`import`で読むファイルは、JavaScriptのMIMEタイプで配る必要があります。`text/plain`で返すと、登録に失敗します。

## おわりに

Service WorkerでES Modulesを使う方法を紹介しました。

`type: 'module'`オプションを指定するだけで、`importScripts()`から静的`import`文への移行が可能です。
動的インポートが使えないという制限はありますが、コードの整理やモジュールの再利用がしやすくなります。
