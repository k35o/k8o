# URLPatternでURLのパスからパラメータを取り出す

<BrowserSupportStatus featureId="urlpattern" />

## はじめに
URLPattern APIは、`/blog/:id`のようなパターンでURLを照合し、`:id`に当たる部分を取り出せるAPIです。Safari 26のサポートによって、Baseline 2025入りした新しい機能です。

パスが決まった文字列と同じかを見るだけなら、`url.pathname === "/blog"`や`startsWith()`で足ります。`/blog/`の後ろの記事名を取り出したり、数字だけのIDに絞ったりするには、これまで正規表現を書いていました。URLPatternなら名前を付けたパラメータで書け、ホスト名やクエリも部品ごとに照合できます。

```js
const pattern = new URLPattern({ pathname: "/blog/:slug" });

console.log(pattern.exec("https://k8o.me/blog/urlpattern").pathname.groups);
console.log(pattern.test("https://k8o.me/talks"));
```

コンソールに貼ると、`slug`が`"urlpattern"`のオブジェクトと、`false`が出ます。`exec`は一致した部分を部品ごとに返し、`test`は一致したかどうかだけを返します。

この記事では、URLPattern APIの基本的な使い方について紹介します。

## URLPattern
URLPattern APIは、生成した`URLPattern`オブジェクトを使って、URLのパターンマッチを行います。

```ts
const pattern = new URLPattern(
  input,
  baseURL,
  options,
)
```

`input`は必須で、`baseURL`と`options`は省略可能です。`baseURL`を省略して`input`と`options`を指定することもできます。

```ts
// これはもちろんOK
new URLPattern(
  input,
)

// baseURLだけを省略可能
new URLPattern(
  input,
  options,
)
```

第1引数の`input`にはURLのパターンを文字列かオブジェクトで渡します。
```ts
const pattern1 = new URLPattern("https://k8o.me/blog/:id");
```
オブジェクトの場合は、`protocol`・`username`・`password`・`hostname`・`port`・`pathname`・`search`・`hash`・`baseURL`の各プロパティにパターンを指定します。
```ts
// [!og]
const pattern2 = new URLPattern({
  protocol: "https",
  hostname: "k8o.me",
  pathname: "/blog/:id",
});

const pattern3 = new URLPattern({
  pathname: "/blog/:id",
  baseURL: "https://k8o.me",
});
```

`pattern1`と`pattern3`は同じ意味になります。`pattern2`だけは`port`が`*`になるので、`https://k8o.me:8080/blog/a`のようにポート番号の付いたURLにも一致します。

指定していないプロパティは`*`が渡された、つまりワイルドカードとして扱われます。ただし、`baseURL`を指定した場合は、指定したプロパティより前の部品を`baseURL`の値で埋めます。部品の順は`protocol`・`hostname`・`port`・`pathname`・`search`・`hash`です。`baseURL`だけを渡せばどの部品も`baseURL`の値になり、`https://k8o.me`なら`port`・`search`・`hash`が`''`、`pathname`が`/`になります。`username`と`password`は`baseURL`から埋めず、`*`のままです。

```ts
// 同じ
const pattern1 = new URLPattern({
  protocol: "https",
  hostname: "k8o.me",
  pathname: "/blog/:id",
});
const pattern2 = new URLPattern({
  protocol: "https",
  username: "*",
  password: "*",
  hostname: "k8o.me",
  port: "*",
  pathname: "/blog/:id",
  search: "*",
  hash: "*",
});

// 同じ
const pattern3 = new URLPattern({
  baseURL: "https://k8o.me",
});
const pattern4 = new URLPattern({
  protocol: "https",
  username: "*",
  password: "*",
  hostname: "k8o.me",
  port: "",
  pathname: "/",
  search: "",
  hash: "",
});
```

第2引数の`baseURL`には、相対URLを解決するための基準となるURLを文字列で渡します。
```ts
// pattern1とpattern2は同じ意味になる
const pattern1 = new URLPattern("https://k8o.me/blog/:id");
const pattern2 = new URLPattern("/blog/:id", "https://k8o.me");
```

第3引数の`options`にはパターンマッチのオプションを渡せます。現在付与できるのは`ignoreCase`のみで、デフォルトは`false`です。
デフォルトでは大文字小文字を区別しますが、`ignoreCase`を`true`にすると大文字小文字を区別しなくなります。

```ts
const pattern = new URLPattern("/blog/:id", "https://k8o.me", { ignoreCase: true });
console.log(pattern.test("https://k8o.me/BLOG/urlpattern")); // Chrome 156とSafari 27.2はtrue、Firefox 159はfalse
```

Firefox 159では、`:id`や`*`を含むパターンに`ignoreCase: true`を渡しても、大文字小文字を区別しました。区別しなくなったのは、`/blog`のように固定の文字列だけのパターンのときです。

## 定義したパターンと照合するexecメソッド
作成した`URLPattern`オブジェクトは、URLのパターンマッチを`exec`メソッドで行います。
`exec`メソッドは、指定したURLが定義したパターンに一致するかどうかを確認し、一致した場合はマッチした部品ごとの情報を返します。

```ts
const pattern = new URLPattern("https://k8o.me/blog/:id");
const result = pattern.exec("https://k8o.me/blog/urlpattern?query=abc#section1");

// 一致しない場合はnullが返る
if (result) {
  console.log(result.inputs);  // ["https://k8o.me/blog/urlpattern?query=abc#section1"]
  console.log(result.pathname); // { input: "/blog/urlpattern", groups: { id: "urlpattern" } }
  console.log(result.search);   // { input: "query=abc", groups: { 0: "query=abc" } }
  console.log(result.hash);     // { input: "section1", groups: { 0: "section1" } }
  console.log(result.username); // { input: "", groups: { 0: "" } }
} else {
  console.log("パターンに一致しませんでした");
}
```
戻り値は各部品ごとに一致した情報をオブジェクトで返します。`input`には一致した文字列が、`groups`にはパターンマッチでキャプチャされた値が格納されます。パターンが`*`の部品では、`*`に当たった文字列が`0`という名前で`groups`に入ります。

返り値のオブジェクトは部品の他に`inputs`プロパティも持ち、入力された情報が配列で返ってきます。

`exec`メソッドの引数にはコンストラクタと同様に`input`と`baseURL`を渡せます。
渡すのは照合するURLですので、オブジェクトを`input`に渡した場合、指定していない部分は`''`が渡されたものとされます。

`groups`の値は、パスに日本語を含むURLでもパーセントエンコードされたまま入ります。`/blog/あ`なら`id`は`%E3%81%82`になるので、元の文字に戻すには`decodeURIComponent()`を通します。また、`:id`は`/`をまたがないので、`/blog/urlpattern/`のように末尾にスラッシュが付いたURLには一致しません。末尾のスラッシュを許すなら`/blog/:id{/}?`と書きます。Chrome 156、Safari 27.2、Firefox 159とNode.js 26.13.0のどれでも同じでした。

パターンを並べて順に`exec`を呼べば、URLを振り分けるルーティングを正規表現なしで書けます。`:id(\d+)`のように、パラメータの後ろの括弧に正規表現を書けば、当てはまる文字を絞れます。

```ts
const routes = [
  { name: "blog", pattern: new URLPattern({ pathname: "/blog/:slug" }) },
  { name: "tag", pattern: new URLPattern({ pathname: "/tags/:id(\\d+)" }) },
  { name: "talks", pattern: new URLPattern({ pathname: "/talks{/}?" }) },
];

const matchRoute = (url: string) => {
  for (const { name, pattern } of routes) {
    const result = pattern.exec(url);
    if (result) return { name, params: result.pathname.groups };
  }
  return null;
};

console.log(matchRoute("https://k8o.me/blog/urlpattern")); // { name: "blog", params: { slug: "urlpattern" } }
console.log(matchRoute("https://k8o.me/tags/12"));         // { name: "tag", params: { id: "12" } }
console.log(matchRoute("https://k8o.me/tags/css"));        // null
console.log(matchRoute("https://k8o.me/talks/"));          // { name: "talks", params: {} }
```

## 定義したパターンに一致すること確認するtestメソッド
作成した`URLPattern`オブジェクトは、URLのパターンマッチの一致を`test`メソッドで確認できます。
`test`メソッドは、指定したURLが定義したパターンに一致するかどうかを真偽値で返します。
```ts
const pattern = new URLPattern("/blog/:id", "https://k8o.me");
console.log(pattern.test("https://k8o.me/blog/urlpattern?query=abc#section1")); // true
console.log(pattern.test("https://k8o.me/blog")); // false
```

`test`メソッドの引数は`exec`メソッドと同様です。

## 適用されたパターンマッチを部品ごとに確認する
作成した`URLPattern`オブジェクトは、適用されたパターンを部品ごとに確認するためのプロパティを持ちます。
`protocol`・`username`・`password`・`hostname`・`port`・`pathname`・`search`・`hash`の各部品にどのようなパターンが適用されたかを確認できます。

```ts
const pattern1 = new URLPattern("https://k8o.me");
console.log(pattern1.protocol); // "https"
console.log(pattern1.username); // "*"
console.log(pattern1.password); // "*"
console.log(pattern1.hostname); // "k8o.me"
console.log(pattern1.port);     // ""
console.log(pattern1.pathname); // "*"
console.log(pattern1.search);   // "*"
console.log(pattern1.hash);     // "*"

const pattern2 = new URLPattern({
  baseURL: "https://k8o.me",
});
console.log(pattern2.protocol); // "https"
console.log(pattern2.username); // "*"
console.log(pattern2.password); // "*"
console.log(pattern2.hostname); // "k8o.me"
console.log(pattern2.port);     // ""
console.log(pattern2.pathname); // "/"
console.log(pattern2.search);   // ""
console.log(pattern2.hash);     // ""

const pattern3 = new URLPattern({
  baseURL: "https://k8o.me",
  protocol: "https",
  hostname: "k8o.me",
});
console.log(pattern3.protocol); // "https"
console.log(pattern3.username); // "*"
console.log(pattern3.password); // "*"
console.log(pattern3.hostname); // "k8o.me"
console.log(pattern3.port);     // "*"
console.log(pattern3.pathname); // "*"
console.log(pattern3.search);   // "*"
console.log(pattern3.hash);     // "*"
```

初めの方に紹介した、第1引数の渡し方による違いも、この機能を用いて確認しました。文字列で`https://k8o.me`のようにホスト名まで書くと`port`が`''`になり、オブジェクトで`port`を省くと`*`になります。

## おわりに
URLのパスからパラメータを取り出すURLPattern APIについて紹介しました。

これまでRegExp等で書いてきたURLの照合とルーティングを、`/blog/:id`のようなパターンで書けるのは非常に便利だと感じました。取り出した値がパーセントエンコードされたままであることと、Firefox 159では`ignoreCase`がパラメータを含むパターンに効かないことには気をつけてください。
