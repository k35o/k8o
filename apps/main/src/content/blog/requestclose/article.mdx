# requestCloseでdialogを閉じる前に確認を挟む

<BrowserSupportStatus featureId="requestclose"></BrowserSupportStatus>

## はじめに

`requestClose`メソッドは、`<dialog>`要素を閉じる前に`cancel`イベントを発火させるメソッドです。`cancel`イベントで`preventDefault`メソッドを呼ぶと、閉じるのを止められます。Firefox 139が対応して、Baseline 2025に入りました。

ダイアログは、`close`メソッドや`<form method="dialog">`の送信で閉じられます。ただ、`close`メソッドは`cancel`イベントを出さずにすぐ閉じるので、入力中なら閉じないといった確認を挟めません。

```html
<dialog id="dialog">
  <input id="name" />
  <button type="button" id="close-button">閉じる</button>
</dialog>
<script>
  const dialog = document.getElementById('dialog');
  const input = document.getElementById('name');

  dialog.addEventListener('cancel', (event) => {
    // 入力中なら閉じない
    if (input.value !== '') event.preventDefault();
  });
  document.getElementById('close-button').addEventListener('click', () => {
    dialog.requestClose();
  });
  dialog.showModal();
</script>
```

入力欄に文字があるうちは、閉じるを押してもダイアログは開いたままです。入力欄を空にしてから押すと閉じます。

## HTMLDialogElement.requestClose

`cancel`イベントは`requestClose`メソッドの中で発火します。止めなければ、呼び出しから戻った時点でダイアログは閉じていて、`close`イベントはその後に届きます。

`<dialog>`要素を開いた状態で`Escape`キーを押したときも、`requestClose`メソッドを呼んだときと同じく`cancel`イベントを経て閉じます。Invoker Commands APIの`command="request-close"`を付けたボタンからも呼べます。このボタンを押すと`cancel`イベントを経て閉じ、ボタンの`value`属性が`returnValue`になります。

### 使用例

次のデモでは、名前の入力欄に文字があるあいだ、閉じるボタンでも`Escape`キーでもダイアログを閉じられません。

```html demo="confirm"
<button type="button" id="open">ダイアログを開く</button>
<ul id="log"></ul>

<dialog id="dialog">
  <form method="dialog">
    <label>名前 <input id="name" /></label>
    <button type="button" id="close">閉じる</button>
    <button>送信</button>
  </form>
</dialog>
```

```css demo="confirm"
/* 開いたダイアログが収まる高さを取る */
body {
  min-height: 10rem;
}
```

```js demo="confirm"
const dialog = document.getElementById('dialog');
const input = document.getElementById('name');
const log = document.getElementById('log');

const addLog = (message) => {
  const item = document.createElement('li');
  item.textContent = message;
  log.prepend(item);
};

dialog.addEventListener('cancel', (event) => {
  addLog('cancel');
  // 入力中なら閉じない
  if (input.value !== '') event.preventDefault();
});
dialog.addEventListener('close', () => {
  addLog('close');
  input.value = '';
});

document.getElementById('open').addEventListener('click', () => {
  dialog.showModal();
});
document.getElementById('close').addEventListener('click', () => {
  dialog.requestClose();
});
```

名前を入れたまま閉じるを押すと、ログには`cancel`イベントの1行だけが増え、ダイアログは開いたままです。名前を消してから押すと、`cancel`イベントと`close`イベントの2行が増えて閉じます。

`Escape`キーで閉じるときは、いつでも止められるわけではありません。Chromeでは、名前を入れたまま`Escape`キーを押すと、1回目は止まりますが、続けて押した2回目には`cancelable`が`false`の`cancel`イベントが届いて閉じます。途中で文字を打ち足しても、2回目で閉じます。ページが`Escape`キーで閉じるのを止め続けると、ユーザーがダイアログから抜け出せなくなるためです。閉じるボタンから呼んだ`requestClose`メソッドの`cancel`イベントは、何度押しても止められます。

### returnValue

`close`メソッドと同じく、`requestClose`メソッドにも文字列を渡せます。渡した文字列は、閉じたあとの`returnValue`になります。

```js
// [!og]
const requestClose = () => {
  dialogElement.requestClose('some value');
};

dialogElement.addEventListener('cancel', () => {
  // cancelの時点では、returnValueは前の値のまま
  console.log('cancel:', dialogElement.returnValue);
});

dialogElement.addEventListener('close', () => {
  // 閉じたあとは、requestCloseに渡した'some value'になる
  console.log('close:', dialogElement.returnValue);
});
```

`cancel`イベントの中の`returnValue`は前の値（初めは空文字列）のままで、`close`イベントで`some value`になります。`cancel`イベントで`preventDefault`メソッドを呼んで止めたときと、引数を渡さずに呼んだときは、`returnValue`は前の値のままです。

## おわりに

`requestClose`メソッドを使うと、閉じるボタンからも`Escape`キーと同じく`cancel`イベントを経てダイアログを閉じられます。入力中なら閉じないといった確認を、`cancel`イベントの1か所にまとめられます。ただし、`Escape`キーから来た`cancel`イベントは止められないことがある点に気をつけてください。
