# requestCloseでdialogを閉じる前に確認を挟む

<BrowserSupportStatus featureId="requestclose"></BrowserSupportStatus>

## はじめに

`requestClose`メソッドは、`<dialog>`要素を閉じる前に`cancel`イベントを発火させるメソッドです。`cancel`イベントで`preventDefault`メソッドを呼ぶと、閉じるのを止められます。Firefox 139が対応して、Baseline 2025に入りました。

閉じるだけなら、`close`メソッドや`<form method="dialog">`の送信で足ります。ただ、`close`メソッドは`cancel`イベントを出さずにすぐ閉じるので、入力中なら閉じないといった確認を挟めません。`Escape`キーで閉じるときと同じく`cancel`イベントを経て閉じるには、`requestClose`メソッドを使います。

```html
<dialog id="dialog">
  <input id="name" />
  <button type="button" id="close-button">閉じる</button>
</dialog>
<script>
  const dialog = document.getElementById('dialog');
  const input = document.getElementById('name');

  dialog.addEventListener('cancel', (event) => {
    // 入力中なら閉じない
    if (input.value !== '') event.preventDefault();
  });
  document.getElementById('close-button').addEventListener('click', () => {
    dialog.requestClose();
  });
  dialog.showModal();
</script>
```

入力欄に文字があるうちは、閉じるを押してもダイアログは開いたままです。入力欄を空にしてから押すと閉じます。

## HTMLDialogElement.requestClose

`HTMLDialogElement.close`メソッドは`<dialog>`要素を閉じます。
それに対し、`HTMLDialogElement.requestClose`メソッドは`<dialog>`要素を閉じるように要求します。

要求と書いたのは、即座にダイアログを閉じるのではなく、`cancel`イベントを介して`close`イベントを発火させるからです（既存の`close`メソッドは`close`イベントを呼ぶだけです）。`cancel`イベントは`requestClose`メソッドの中で発火し、止めなければ呼び出しから戻った時点でダイアログは閉じています。`close`イベントはその後に届きます。

`<dialog>`要素を開いた状態で`Escape`キーを押した時も、`requestClose`メソッドを実行した時と同じように`cancel`イベントを経て閉じます。Invoker Commands APIの`command="request-close"`を付けたボタンからも呼べます。このボタンを押すと`cancel`イベントを経て閉じ、ボタンの`value`属性が`returnValue`になります。

`cancel`イベントを`close`イベントに挟むことで、ダイアログを閉じる前に何らかの処理を行うことができます。

たとえば、`cancel`イベント中で`preventDefault`メソッドを呼ぶことで、ダイアログを閉じるのをキャンセルすることも可能です。

`Escape`キーで閉じるときは、いつでも止められるわけではありません。Chrome 156で、名前を入れたまま`Escape`キーを続けて押すと、2回目までは閉じず、3回目は`cancelable`が`false`の`cancel`イベントが届いて閉じました。途中で文字を打ち足しても、3回目で閉じました。ページが`Escape`キーで閉じるのを止め続けると、ユーザーがダイアログから抜け出せなくなるためです。閉じるボタンから呼んだ`requestClose`メソッドの`cancel`イベントは、何度押しても止められました。

### returnValue

`close`メソッド同様に、`requestClose`メソッドの引数に文字列を渡せます。
`<dialog>`要素のプロパティ`returnValue`を更新します。

```js
// [!og]
const requestClose = () => {
  dialogElement.requestClose('some value');
};

dialogElement.addEventListener('cancel', () => {
  // cancelの時点では、returnValueは前の値のまま
  console.log('cancel:', dialogElement.returnValue);
});

dialogElement.addEventListener('close', () => {
  // 閉じたあとは、requestCloseに渡した'some value'になる
  console.log('close:', dialogElement.returnValue);
});
```

`cancel`イベントの中の`returnValue`は前の値（初めは空文字列）のままで、`close`イベントで`some value`になります。`cancel`イベントで`preventDefault`メソッドを呼んで止めたときと、引数を渡さずに呼んだときは、`returnValue`は前の値のままです。

## おわりに

`requestClose`メソッドを使うと、閉じるボタンからも`Escape`キーと同じく`cancel`イベントを経てダイアログを閉じられます。入力中なら閉じないといった確認を、`cancel`イベントの1か所にまとめられます。ただし、`Escape`キーから来た`cancel`イベントは止められないことがある点に気をつけてください。
