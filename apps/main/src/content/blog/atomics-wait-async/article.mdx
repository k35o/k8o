# Atomics.waitAsyncでメインスレッドを止めずに待つ

<BrowserSupportStatus featureId="atomics-wait-async"></BrowserSupportStatus>

## はじめに

`Atomics.waitAsync`は、`SharedArrayBuffer`の値が`notify`で通知されるのを、スレッドを止めずに`Promise`で待つ静的メソッドです。`Atomics.wait`の非同期版です。Firefox 145が対応して、Baseline 2025に入りました。

Workerの計算結果を受け取るだけなら、Workerが`postMessage`で送り、メインスレッドが`message`イベントで受け取れば足ります。Workerと共有したメモリの値が書き換わるのを待つときに、`Atomics.waitAsync`が要ります。`Atomics.wait`はスレッドを止めて待つので、ブラウザのメインスレッドで呼ぶと`TypeError`になります。

```js title="main.js"
const int32 = new Int32Array(new SharedArrayBuffer(4));
const result = Atomics.waitAsync(int32, 0, 0);

const worker = new Worker('worker.js');
worker.postMessage(int32);

if (result.async) {
  result.value.then((value) => {
    console.log(value, Atomics.load(int32, 0)); // ok 42
  });
}
```

```js title="worker.js"
onmessage = ({ data: int32 }) => {
  Atomics.store(int32, 0, 42);
  Atomics.notify(int32, 0);
};
```

ページを`Cross-Origin-Opener-Policy: same-origin`と`Cross-Origin-Embedder-Policy: require-corp`のヘッダーで返し、`main.js`を読み込むと、コンソールに`ok 42`が出ます。どのブラウザでも、待っているあいだもメインスレッドのタイマーは動き続けます。

`Atomics`の基本と`Atomics.pause`は、[AtomicsでWorker間の共有メモリを安全に読み書きする](/blog/atomics-pause)で書いています。

## 引数と戻り値

`waitAsync`は4つの引数を取ります。

- 第1引数：`SharedArrayBuffer`を元にした`Int32Array`か`BigInt64Array`
- 第2引数：その配列のインデックス
- 第3引数：その位置にあると期待する値
- 第4引数：タイムアウトのミリ秒。省略できる

```ts
const sab = new SharedArrayBuffer(4);
const int32 = new Int32Array(sab);
// int32の0番目の値が0であることを期待して待機、タイムアウトは1秒
const result = Atomics.waitAsync(int32, 0, 0, 1000);
```

戻り値は`Promise`ではなく、すぐに返るオブジェクトです。`async`は`value`が`Promise`かどうかを、`value`は待った結果を表します。

戻り値の型は次のとおりです。TypeScriptでは、`lib`に`es2024`以降を含めると同じ形の型が付きます。

```ts
type ReturnValue =
	| { async: false; value: "not-equal" | "timed-out" }
	| { async: true; value: Promise<"ok" | "timed-out"> };
```

`{ async: false; value: "not-equal" }`は、その位置の値が第3引数と違っていたときに返ります。Workerが値を書き換えてから呼ぶと、どのブラウザでも`{ async: false, value: 'not-equal' }`が返ります。冒頭の`main.js`で`waitAsync`を`postMessage`より先に呼んでいるのは、このためです。

`{ async: false; value: "timed-out" }`は、タイムアウトに0ミリ秒を渡したときに返ります。

ふだん返るのは`{ async: true; value: Promise<"ok" | "timed-out"> }`です。`value`の`Promise`は、`notify`で起こされると`"ok"`に、その前にタイムアウトすると`"timed-out"`になります。

```ts
// [!og]
const sab = new SharedArrayBuffer(4);
const int32 = new Int32Array(sab);
const result = Atomics.waitAsync(int32, 0, 0, 1000);

if (result.value === 'not-equal') {
  // 指定した位置に存在する値が期待した値と異なる場合の処理
}
if (result.value === 'timed-out') {
  // タイムアウト時間が0ミリ秒に指定された場合の処理
}
if (result.async) {
  result.value.then(
    (value) => {
      if (value === 'ok') {
        // notifyによって呼び出された場合の処理
      } else {
        // タイムアウトした場合の処理
      }
    });
}
```

共有していない配列を渡すなど引数が不正なときは、呼び出した時点で`TypeError`が投げられます。`value`の`Promise`が`reject`されることはありません。

Node.jsでは、`waitAsync`の`Promise`だけが残るとプロセスが終わり、タイムアウトを100msにしても`then`は呼ばれません。Node.jsで使うときは、Workerのようにプロセスを動かし続けるものと組み合わせます。

## おわりに

`Atomics.waitAsync`はスレッドを止めずに`notify`を待つので、メインスレッドでもWorkerが共有メモリを書き換えるのを待てます。Workerが先に書き換えたときは`not-equal`がすぐに返るので、`async`を確かめてから`value`を使います。
