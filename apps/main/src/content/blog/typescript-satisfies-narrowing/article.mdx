# TypeScriptのsatisfiesで型が絞り込まれる理由

## はじめに

`satisfies`は、式の型が指定した型に合うかを検査する演算子です。式の型は変えずに残し、TypeScript 4.9で追加されました。

変数の型を宣言した型そのものにしたいなら、型注釈で足ります。型を検査しながら、推論されたリテラル型を残したいときに`satisfies`を使います。ただし、制約にリテラル型のユニオンがあると、`satisfies`を付けた式の型が付けないときより絞り込まれます。

次の3つの`palette`は、どれも`blue`を`bleu`と書き間違えています（[TypeScript Playground](https://www.typescriptlang.org/play/?#code/FAFwngDgpgBAwgewDYIE4GcYF4YCJVQAmuMAPngOYFQB2J5uARkgK5S4DcwwAxgjehAwIAQyRQQIKAEZsMAN7AYymAUIAuPAGIAZjoAMh-bgA0SlVSi1NuLYb2HT55czY27RvU4C+MEZj4BEC5efkFhMQkpACZNACUoPlRCAB5EFAwTGEFUAEsaCgA+OUUVVSJ3ByMnMstrbXsDYzMy1yh3I30vM19-GEDBEIGhUXFJKABmEudyjW0qxxaLahoOrqaalTa1xp8-ALChdBEQXPQdXKhMBKTU9LR0LJz8oo4gA)）。

```ts
// [!og]
type Colors = "red" | "green" | "blue";

const palette1 = {
  red: "#ff0000",
  green: "#00ff00",
  bleu: "#0000ff"
} as const;

const palette2: Record<Colors, string> = {
  red: "#ff0000",
  green: "#00ff00",
  bleu: "#0000ff"
};

const palette3 = {
  red: "#ff0000",
  green: "#00ff00",
  bleu: "#0000ff"
} as const satisfies Record<Colors, string>;
```

`palette1`には型の制約が無いので、この誤りに気づけません。`palette2`は型注釈で、`palette3`は`satisfies`で制約を付けているので、`bleu`の行が`Object literal may only specify known properties, and 'bleu' does not exist in type 'Record<Colors, string>'.`（TS2353）になります。

`bleu`を`blue`に直すと、それぞれの型は次のように推論されます。

```ts
// palette1
type Palette1 = {
  readonly red: "#ff0000";
  readonly green: "#00ff00";
  readonly blue: "#0000ff";
};

// palette2
type Palette2 = Record<Colors, string>;

// palette3
type Palette3 = {
  readonly red: "#ff0000";
  readonly green: "#00ff00";
  readonly blue: "#0000ff";
};
```

`palette1`と`palette3`はリテラル型が残り、`palette2`は型注釈どおりの`Record<Colors, string>`になります。`satisfies`は、式の型を変えずに制約だけを付けます。

## 式の型が絞り込まれる例

次の`user1`と`user2`を比べます（[TypeScript Playground](https://www.typescriptlang.org/play?#code/C4TwDgpgBAqgzhATlAvFA3gKClAlgEwC4o5hFcA7AcwG5spRJiByYCAQwGMALJZqAD5RmYAK5hcAG2YAaehXYBbCMVLlqdHLjgB9AG5JcAM1wQiUAEYB7K5I4U6AXzqZOViqSiiEiAIyoMei1zZnZZIIZwFWE2Ll5EcJwcBWUWdigwuSS8XQNyEzNiMlEIOWdMV3dPbyQAJgCsbII0xKTGaNYOHj4spJSO9MyI7X1DAvNi0sxHEnZgbQK4WB8XIA)）。

```ts
type User = {
  id: string;
  type: 'teacher' | 'pupil',
  name: string;
  is_verified: boolean;
};

const user1 = {
  id: 'a',
  type: 'teacher',
  name: 'a a',
  is_verified: true,
};

const user2 = {
  id: 'a',
  type: 'teacher',
  name: 'a a',
  is_verified: true,
} satisfies User;
```

`satisfies`は式の型を変えないはずなので、`user2`は`user1`と同じ型になりそうです。ところが、推論される型は違います。

```ts
// user1
type User1 = {
  id: string;
  type: string;
  name: string;
  is_verified: boolean;
};

// user2
type User2 = {
  id: string;
  type: "teacher";
  name: string;
  is_verified: true;
};
```

`id`と`name`は同じですが、`user2`の`type`と`is_verified`は、`'teacher'`と`true`のリテラル型になっています。

配列でも、同じように絞り込まれます（[TypeScript Playground](https://www.typescriptlang.org/play?#code/C4TwDgpgBAcgrgWwEYQE4GcoF4oAoCMUAPlAEzFQDMFALAJQDaAugNwBQbAxgPYB26wKL0QoMhHA3wAaMjMqsOPfoOHI06chOmyqTKOgCGwAJboAZsYiZ4ajOyA)）。

```ts
type Numbers = (1 | 2 | 3 | 4)[];

const numbers1 = [1, 2, 3];

const numbers2 = [1, 2, 3] satisfies Numbers;
```

`numbers1`は`number[]`になりますが、`numbers2`は制約にリテラル型のユニオンがあるので、`(1 | 2 | 3)[]`まで絞り込まれます。

```ts
// numbers1
type Numbers1 = number[];

// numbers2
type Numbers2 = (1 | 2 | 3)[];
```

`as const`を付けたときのような、タプル型にはなりません。

## 絞り込まれる理由

`satisfies`は、右に書いた型を、左の式の文脈上の型（contextual type）として渡します。文脈上の型にリテラル型のユニオンがあると、TypeScriptは`'teacher'`のようなリテラルを`string`に広げず、リテラル型のまま残します。TypeScriptのIssueでも、意図どおりの挙動だと説明されています（[TypeScript#55189](https://github.com/microsoft/TypeScript/issues/55189)）。

`user1`のように制約が無ければ、`'teacher'`は`string`に広げて推論されます。もし`satisfies`の検査でも広げると、`'guardian'`も`'teacher'`も`string`になります。検査は`string extends 'teacher' | 'pupil'`となり、どちらも制約を満たさないと判断されます。リテラル型のまま残すので、`'guardian' extends 'teacher' | 'pupil'`は満たさず、`'teacher' extends 'teacher' | 'pupil'`は満たす、と見分けられます。

`is_verified`の制約は`boolean`ですが、`true`は`boolean`に広げられません。`boolean`は`true | false`のユニオンで、リテラル型のユニオンとして扱われるためです。

## 絞り込まれた型への代入

絞り込まれた型は、あとで値を書き換えるときに問題になります。`user2`を`let`で宣言して書き換えると、ユニオンのほかの値を代入した行がエラーになります。

```ts
let user2 = {
  id: 'a',
  type: 'teacher',
  name: 'a a',
  is_verified: true,
} satisfies User;

user2.type = 'pupil'; // Type '"pupil"' is not assignable to type '"teacher"'.
user2.is_verified = false; // Type 'false' is not assignable to type 'true'.
```

あとで書き換える値は、`const user3: User = { ... }`のように型注釈で宣言すれば、`'pupil'`も`false`も代入できます。

## ジェネリクスの制約

ジェネリクスでも、型引数の制約にリテラル型のユニオンがあると、同じようにリテラル型が残ります（[TypeScript Playground](https://www.typescriptlang.org/play?#code/C4TwDgpgBAMglsCAnAhgGwCrmgXigbwCgopEBnYALigHIUaoAfWgIxoG5CBfT0SKAApI4AWwRwAbhCz88+KMVIQK1CsIB2Ac26dCAYwD26ilCTKArmmBQ5i8lVr0dhQgBMIetCjNRDx6-YAjNQAPBhQEAAeiOquZILCYsCS0tgAfAAU3prUGACUNmlQGJzunt7Qfib2AEyh4VExcbAIyOgyEJnZuQU4RSUuVdZmZJbAgTZKFIEZ8vbUdAxceZxDphZWNZO1s1MOi1DLnEA)）。

```ts
type PrimitiveType = {
  test: string
};
type LiteralType = {
  test: 'a' | 'b';
};

const result = {
  test: 'a'
};

declare const test1: <T extends PrimitiveType>(arg: T) => T;
declare const test2: <T extends LiteralType>(arg: T) => T;

const result1 = test1({ test: 'a' });
const result2 = test2({ test: 'a' });
```

`result`と`result1`と`result2`の型は、次のように推論されます。

```ts
// result
type Result = {
    test: string;
};

// result1
type Result1 = {
    test: string;
};

// result2
type Result2 = {
    test: "a";
};
```

`result2`だけが、`string`ではなく`'a'`になります。`test2`の`T extends LiteralType`で、`'a' | 'b'`の制約が付いているためです。

## おわりに

`satisfies`やジェネリクスの制約にリテラル型のユニオンがあると、式のリテラル型はそのまま残ります。絞り込まれた型にはユニオンのほかの値を代入できないので、あとで書き換える値は型注釈で宣言します。
