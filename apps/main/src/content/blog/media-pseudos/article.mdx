# :playingと:pausedで動画の再生中だけスタイルを変える

<BrowserSupportStatus featureId="media-pseudos" />

## はじめに

`:playing`や`:paused`は、`<video>`や`<audio>`が再生中か一時停止中かに当たるCSSの疑似クラスです。`:has()`と組み合わせると、再生ボタンやスピナーを再生の状態に合わせて出し分けられます。

動画の上に再生ボタンを重ねて、再生が始まったら消す。読み込み待ちの間だけスピナーを出す。こうしたプレイヤーUIを作るとき、CSSからは`<video>`が再生中かどうかを知る手段がありませんでした。そのため`play`や`pause`、`waiting`といったイベントを購読して、JavaScriptを経由してスタイルを当てる必要がありました。

`:playing`をはじめとするメディア要素の疑似クラスは、この状態をセレクタとして直接書けるようにするものです。Safari 15.4とFirefox 150に続いてChromeとEdgeが158で対応し、2026年11月にBaseline 2026に入りました。

## 7つの疑似クラス

対象は`<audio>`と`<video>`です。HTML仕様では、それぞれが`HTMLMediaElement`のプロパティにもとづいて次のように定義されています。

- `:playing` - `paused`が`false`
- `:paused` - `paused`が`true`
- `:seeking` - `seeking`が`true`。シーク先の位置にまだ到達していない間
- `:buffering` - `paused`が`false`で、`networkState`が`NETWORK_LOADING`、かつ`readyState`が`HAVE_CURRENT_DATA`以下。再生しようとしているのにデータが足りない状態
- `:stalled` - `:buffering`のうち、データが一定時間届いていないもの。`stalled`イベントに相当する
- `:muted` - `muted`が`true`
- `:volume-locked` - ブラウザが音量をロックしている。iOSのSafariのように本体のボタンでしか音量を変えられない環境

Chrome、Safari、Firefoxのどれでも、7つとも`CSS.supports()`が`true`を返しました。

```css
/* [!og] */
.player:has(video:paused) .play-button {
  display: grid;
}

.player:has(video:buffering) .spinner {
  display: block;
}

.player:has(video:muted) .sound-icon {
  opacity: 0.4;
}
```

冒頭の例のように、これらの疑似クラスはメディア要素そのものよりも周りのUIに当てる場面がほとんどです。`<video>`は置換要素なので再生ボタンやスピナーは兄弟要素として重ねるしかなく、`<audio>`にいたっては`controls`属性がなければ描画すらされません。そこで`:has()`で状態を親のプレイヤーまで持ち上げます。こうすると`play`と`pause`のイベントリスナーは要らなくなります。ネイティブのコントロールから操作してもスクリプトから`play()`を呼んでも、`paused`プロパティが変わりさえすればCSSが追従します。

```html demo="playing"
<div class="player">
  <div class="bars">
    <span></span>
    <span style="animation-delay: 90ms"></span>
    <span style="animation-delay: 180ms"></span>
    <span style="animation-delay: 270ms"></span>
    <span style="animation-delay: 360ms"></span>
  </div>
  <audio controls loop src="/demos/media-pseudos/tone.wav"></audio>
  <ul class="chips">
    <li class="chip-playing">:playing</li>
    <li class="chip-paused">:paused</li>
    <li class="chip-muted">:muted</li>
  </ul>
</div>
<button id="play" type="button">play()</button>
<button id="pause" type="button">pause()</button>
<button id="toggle" type="button">mutedを反転</button>
```

```js demo="playing"
const audio = document.querySelector('audio');

document.querySelector('#play').addEventListener('click', () => {
  audio.play();
});
document.querySelector('#pause').addEventListener('click', () => {
  audio.pause();
});
document.querySelector('#toggle').addEventListener('click', () => {
  audio.muted = !audio.muted;
});
```

再生するか`play()`を押すと、5本のバーが上下に動き、`:playing`のチップが点灯します。`muted`を反転すると、バーが薄くなります。

`:playing`と`:paused`は互いに補集合で、メディア要素は必ずどちらか一方にマッチします。読み込みが終わる前の要素は`paused`が`true`なので`:paused`側です。

`:buffering`と`:stalled`は`:playing`の内側にあります。ユーザーが再生を求めていて、ブラウザ側の都合で止まっているのがこの2つなので、`:paused`と同時にマッチすることはありません。`:stalled`と判定されるまでの時間はブラウザに委ねられており、おおむね3秒程度です。

## 属性ではなく今の状態を見る

`muted`は属性セレクタでも取れそうに見えますが、`audio[muted]`と`audio:muted`は別のものです。`muted`属性が決めるのは要素が作られたときの初期値だけで、あとから付け外ししても音の状態は変わりません。逆にユーザーがコントロールのミュートボタンを押しても、属性は付きません。

同じ3つのブラウザで試すと、`muted`属性を書いた`<audio>`から属性を外しても`:muted`のままで、属性の無い`<audio>`に属性を足しても`:muted`にはなりませんでした。JavaScriptで要素を作るときも、`createElement()`の直後の`setAttribute('muted', '')`では、ChromeとFirefoxの`muted`は`false`のままでした（Safariでは`true`）。音を消すときは`muted`プロパティに`true`を入れます。

`:muted`が見ているのは`muted`プロパティ、つまり今まさに音が消されているかどうかです。同じことは`:playing`にも言えます。`autoplay`属性を付けていても、ブラウザの自動再生ポリシーで止められた要素は`:paused`のままです。3つのブラウザのどれでも、ページを開いただけで音の出る`<audio>`の`play()`を呼ぶと`NotAllowedError`で拒否され、要素は`:paused`のままでした。

```html
<div class="hero">
  <video autoplay muted playsinline src="hero.mp4"></video>
  <!-- [!callout: 自動再生が止められたときだけ見える] -->
  <button class="play-button">再生</button>
</div>
```

```css
.hero:has(video:playing) .play-button {
  display: none;
}
```

自動再生が成功したかどうかを`play()`の戻り値のPromiseで判定し、失敗時にボタンを出すコードを書く必要がなくなります。

```html demo="muted"
<div class="player">
  <audio controls loop src="/demos/media-pseudos/tone.wav"></audio>
  <ul class="chips">
    <li class="chip-attribute">audio[muted]</li>
    <li class="chip-pseudo">audio:muted</li>
  </ul>
</div>
<button id="property" type="button">mutedプロパティを反転</button>
<button id="attribute" type="button">muted属性を付け外し</button>
```


## 対応していないブラウザでの書き方

Chrome 157以前のように対応していないブラウザでは、`:has(video:playing)`のように未知の疑似クラスを含む規則は丸ごと無効になります。`:has()`の引数は寛容ではないので、外側の`.player`まで含めて規則が捨てられます。再生ボタンを表示する側を既定にしておき、`:playing`で消す向きに書くと、未対応のブラウザでは再生ボタンが出たままになり、ほかの見た目は変わりません。

```css
/* [!callout: 既定では出しておく] */
.player .play-button {
  display: grid;
}

/* [!callout: 対応ブラウザだけがここを解釈する] */
.player:has(video:playing) .play-button {
  display: none;
}
```

対応前のChromeで試すと、2つ目の規則は`document.styleSheets`の`cssRules`に残らず、`.play-button`は`display: grid`のままでした。

## おわりに

メディア要素の疑似クラスは、`HTMLMediaElement`が持っている状態をそのままセレクタに写したものです。プレイヤーUIの見た目に関わる部分については、イベントを購読してJavaScriptを経由していたスタイルを、`:has()`と組み合わせたCSSに置き換えられます。再生ボタンのオーバーレイやローディングのスピナーのように、これまで小さなスクリプトを毎回書いていた箇所を宣言的に書けるようになります。対応前のブラウザで開かれる場面では、再生ボタンを表示する側を既定にして書きます。
